# Tech Spec: Per-category folders for `.yoke/` working memory

> Generated by `/yoke:tech-spec` from an approved PRD on 2026-04-25.
> PRD: `.vibeflow/prds/yoke-working-memory-folders.md`
> Plugin version target: 0.6.0
> Status: approved
> Approved by: iury.krieger@stone.com.br
> Approved at: 2026-04-25

## Overall objective

Reshape `.yoke/` working memory from flat files (`.yoke/prd.md`, `.yoke/tech-spec.md`, …) into per-category folders keyed by a `<YYYY-MM-DD>-<slug>` task identifier. All path resolution is centralized in a new bash library (`lib/working-memory/paths.sh`) so every existing skill (`bootstrap`, `discover`, `tech-spec`, `acceptance-contract`, `implement`, `canonize`, `drift-sense`, `ask`, `status`) is refactored to source one helper instead of hard-coding paths. The Generator agent gains semantic slug regeneration on collision. A smoke test guards against any future skill regressing to flat paths. Ships as one atomic v0.6.0 release; no migration logic (zero adopters today).

## Sprints

### Sprint 1 — v0.6.0: per-category folders + paths helper

**Delivery objective:** A single installable Yoke plugin version (0.6.0) where every skill writes and reads working memory under `.yoke/<category>/<YYYY-MM-DD>-<slug>.md` for archive categories and `.yoke/runtime/` for ephemeral state, with `.yoke/.current` as the per-worktree active-task pointer. `/yoke:discover` → `/yoke:tech-spec` → `/yoke:acceptance-contract` → `/yoke:implement` → `/yoke:canonize` → `/yoke:drift-sense` runs end-to-end on a fresh host project producing the layout described in the PRD's "Layout" section. No flat `.yoke/<file>.md` exists at any point in the flow.

#### Task 1.1 — Working-memory paths library

Add `lib/working-memory/paths.sh` exposing the bash functions enumerated in the "Contracts and interfaces" section. Functions resolve paths against `.yoke/`, validate the slug regex, detect collisions across all five versioned categories, manage `.yoke/.current`, and expose helpers for runtime files. The library is the only place in the codebase that knows the on-disk layout of `.yoke/`.

**Acceptance criterion:** `bash -n lib/working-memory/paths.sh` exits 0; sourcing the file in a subshell and invoking each documented function with valid inputs returns the exact paths/strings listed in the contract section; invoking `wm_validate_slug` with `2026-05-01-foo-bar` exits 0 and with `Foo Bar` exits 1; `shellcheck lib/working-memory/paths.sh` reports no warnings of severity error.

#### Task 1.2 — Bootstrap writes new `.yoke/.gitignore` and stops creating flat files

Update `skills/bootstrap/SKILL.md` and any helper scripts referenced by it so that `/yoke:bootstrap` writes `.yoke/.gitignore` with exactly two lines (`.current` and `runtime/`), creates `.yoke/config.yaml`, and creates none of the legacy flat files (`prd.md`, `tech-spec.md`, etc.). The category folders (`prds/`, `tech-specs/`, …) are not pre-created — they are lazy. Update `templates/yoke-config.yaml` only if its content references the legacy layout.

**Acceptance criterion:** Running `/yoke:bootstrap` in a clean directory produces exactly the following entries inside `.yoke/`: `config.yaml`, `.gitignore`. The contents of `.yoke/.gitignore` are exactly `.current\nruntime/\n`. No file or directory named `prd.md`, `tech-spec.md`, `acceptance-contract.md`, `contracts.md`, `query-trace.md`, `progress.md`, `prds`, `tech-specs`, `acceptance-contracts`, `contracts`, `query-traces`, or `runtime` exists under `.yoke/` after bootstrap completes.

#### Task 1.3 — `/yoke:discover` writes PRD to versioned path and manages `.current`

Update `skills/discover/SKILL.md` and `agents/generator.md` so the discover flow:
1. Asks the Generator to propose a slug derived from the PRD title (lowercase kebab-case, ≤ 50 chars after the date prefix, matching the slug regex).
2. Computes the candidate filename `<YYYY-MM-DD>-<slug>` using local-time date.
3. If `wm_slug_in_use` reports collision in any of the five versioned categories, asks the Generator to regenerate a semantically similar but lexically distinct slug, repeating until unique. Surfaces the chosen slug to the user for confirmation.
4. Wipes `.yoke/runtime/` (idempotent — creates the dir if absent, removes contents if present).
5. Writes the PRD draft to `.yoke/prds/<slug>.md`.
6. Writes the slug to `.yoke/.current`.
7. Approval flow on `.yoke/prds/<slug>.md` is unchanged in semantics; the file path is the only difference.

The `back to PRD` / `revise` / `restart` flows operate on the active slug.

**Acceptance criterion:** Starting from a freshly bootstrapped `.yoke/`, running `/yoke:discover` and approving the PRD results in: (a) `.yoke/prds/<slug>.md` exists with `Status: approved` in its frontmatter, (b) `.yoke/.current` exists and contains exactly the slug (no trailing newline issues — `wc -c < .yoke/.current` equals `printf %s "$(cat .yoke/.current)" | wc -c`), (c) `.yoke/runtime/` exists and is empty, (d) no flat file like `.yoke/prd.md` exists. Running `/yoke:discover` a second time on the same day, with an idea that yields the same first-choice slug, results in a different slug being persisted (verified by `ls .yoke/prds/ | wc -l` returning 2 with two distinct semantic slugs, neither one a numeric `-2` suffix).

## Contracts and interfaces

### `lib/working-memory/paths.sh`

Bash library; sourced (`source lib/working-memory/paths.sh`) by every skill that touches `.yoke/`. All functions emit paths relative to the current working directory. Functions are idempotent (no side-effects on bare path queries) except where noted.

| Function | Args | Returns / writes | Behavior |
|---|---|---|---|
| `wm_active_slug` | — | echoes slug | Reads `.yoke/.current`, trims whitespace, validates against regex, exits 1 if file absent or content invalid. |
| `wm_set_active <slug>` | slug | writes `.yoke/.current` | Validates slug; overwrites file with exactly the slug (no trailing newline). |
| `wm_clear_active` | — | removes `.yoke/.current` | Idempotent; ok if file absent. |
| `wm_validate_slug <s>` | slug | exit 0/1 | Tests against regex `^[0-9]{4}-[0-9]{2}-[0-9]{2}-[a-z0-9][a-z0-9-]{0,49}$`. |
| `wm_slug_in_use <slug>` | slug | exit 0 if in use, 1 if free | Checks for any of `.yoke/{prds,tech-specs,acceptance-contracts,contracts,query-traces}/<slug>.md`. |
| `wm_prd_path [<slug>]` | optional slug | echoes path | Returns `.yoke/prds/<slug>.md` (uses `wm_active_slug` if no arg). |
| `wm_tech_spec_path [<slug>]` | … | … | `.yoke/tech-specs/<slug>.md`. |
| `wm_acceptance_contract_path [<slug>]` | … | … | `.yoke/acceptance-contracts/<slug>.md`. |
| `wm_contracts_path [<slug>]` | … | … | `.yoke/contracts/<slug>.md`. |
| `wm_query_trace_path [<slug>]` | … | … | `.yoke/query-traces/<slug>.md`. |
| `wm_runtime_dir` | — | echoes path | `.yoke/runtime`. |
| `wm_progress_path` | — | echoes path | `.yoke/runtime/progress.md`. |
| `wm_cycle_counter_path` | — | echoes path | `.yoke/runtime/.cycle-counter`. |
| `wm_snapshots_dir` | — | echoes path | `.yoke/runtime/.snapshots`. |
| `wm_trigger4_packet_path` | — | echoes path | `.yoke/runtime/.trigger4-packet.yaml`. |
| `wm_wipe_runtime` | — | side-effect | Removes `.yoke/runtime/*` and `.yoke/runtime/.[!.]*` (preserves the dir, clears contents). Idempotent. |
| `wm_list_archived_slugs` | — | echoes slugs (one per line) | Lists basenames of `.yoke/prds/*.md` minus the `.md` extension; sorted lexically (= chronologically because of date prefix). |

Error contract: every function emits failures to stderr with the prefix `wm:` and exits non-zero. Skills that source this library are expected to honor `set -euo pipefail`.

### `.yoke/.gitignore`

Two-line file written by `/yoke:bootstrap`:

```
.current
runtime/
```

Versioned in the host project's git repository (the file itself is checked in; its declared paths are ignored).

### `.yoke/.current`

Plain text, exactly the active slug. No trailing newline. UTF-8. Single line. Gitignored. Per-worktree (each git worktree carries its own physical file).

### Slug

Lowercase kebab-case identifier with date prefix: `<YYYY-MM-DD>-<slug>`. Total filename (without `.md` extension) matches `^[0-9]{4}-[0-9]{2}-[0-9]{2}-[a-z0-9][a-z0-9-]{0,49}$`. Date is local time at task creation. Slug body is generated by the Generator agent from the PRD's title; collisions trigger semantic regeneration.

### Generator agent — slug collision protocol

The Generator's `agents/generator.md` instruction set carries a "Slug collision protocol" block: when invoked with `colliding_slugs: [<list>]` in the orchestration context, the agent must return a slug that preserves the semantic intent of the original ask while being lexically distinct from every entry in `colliding_slugs`. No numeric suffixes (`<term>-2`, `<term>-3`); rephrase with synonyms or alternative framings (`auth-flow` → `auth-pipeline` → `signin-handler` → `credential-exchange`). If the agent cannot find a rephrasing after 5 attempts, it surfaces the failure to the user with the candidate list and asks for an explicit choice.

### Tests for the Acceptance Contract (Phase 3)

- **Path resolution sensor.** A bash function `assert_paths` that asserts every file written under `.yoke/` during a recorded skill execution is in the allow-list of category folders. Implemented via `find .yoke/ -type f -newer <ref>` plus a regex match.
- **Slug regex sensor.** A function that scans `.yoke/.current`, `.yoke/{prds,tech-specs,acceptance-contracts,contracts,query-traces}/*.md` filenames, and asserts every slug matches the regex.
- **Helper-only path access sensor.** `grep -RIn '"\.yoke/[a-z-]*\.md"' skills/ lib/ hooks/ | grep -v paths\.sh` returns no matches.
- **Worktree isolation sensor.** Two parallel worktrees, each running `/yoke:discover`, produce two independent `.current` files and two independent `runtime/` directories without contention.

## Out of scope

- **Migration from flat layout.** v1.0 has zero adopters; the change is a clean break. No `/yoke:migrate-folders` skill is added.
- **Archive cleanup, pruning, or rotation.** Past tasks persist on disk (and in git) indefinitely. A future `/yoke:prune` can be specified later if disk-bloat materializes.
- **Concurrency within a single worktree.** Per the PRD, one task in flight per worktree. Concurrency support is not added by this Tech Spec, and changes to enable it are explicitly out of scope. (Cross-worktree concurrency is supported by construction, not by added logic.)
- **Drift-sense algorithmic changes.** Drift-sense's discovery, scoring, and YAML output format are unchanged; only the input file globbing is updated.
- **`/yoke:status` enrichment beyond default + `--all`.** No `--task <slug>` flag, no JSON output, no machine-readable mode added in this sprint.
- **Query-trace commit cadence automation.** `git status` will surface uncommitted query-trace edits; this Tech Spec does not auto-commit, batch, or hint about it.
- **Resuming a past task.** "Continue task X" from a previous run is not added. Every `/yoke:discover` starts a new task. (User can manually `echo <slug> > .yoke/.current` if they need to revisit, but no skill helps with that.)
