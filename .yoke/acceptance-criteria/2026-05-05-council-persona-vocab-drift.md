## User Stories

### US-001 — Council persona prompts author against v4.0.0 Acceptance-Criteria vocabulary

As a Yoke framework maintainer, I want the three council persona
prompts at `agents/sr-eng.md`, `agents/sr-qa.md`, and
`agents/sr-staff.md` to use the v4.0.0 Acceptance-Criteria
vocabulary, so that every Phase-A `/yoke:implement` cycle spawns
subagents whose system prompt names the current binding artifact
("Acceptance Criteria document") rather than the v3.x predecessor
("Acceptance Contract").

#### Definition of Done

- [ ] `agents/sr-eng.md` body and frontmatter contain zero occurrences of the substrings `acceptance-contract`, `Acceptance-Contract`, or `Acceptance Contract` (when referring to the artifact's name).
- [ ] `agents/sr-qa.md` body and frontmatter contain zero occurrences of the same substrings.
- [ ] `agents/sr-staff.md` body and frontmatter contain zero occurrences of the same substrings.
- [ ] All three files' YAML frontmatter `description:` and `objective:` keys remain single-line parseable string scalars after the edit (no YAML reflow, no multi-line splice).
- [ ] `lib/runtime/persona-loader.sh validate-all` exits 0 against the three modified files.

#### Acceptance Criteria

- **AC-001-1:** Running `grep -nE 'acceptance-contract|Acceptance-Contract|Acceptance Contract' agents/sr-eng.md agents/sr-qa.md agents/sr-staff.md` returns 0 matches (Tech Spec FR-7).
- **AC-001-2:** The substring `acceptance-criteria-anchored tests` appears at least 3 times across the three files (one or more occurrences per file). The wording matches the in-tree reference at `docs/architecture.md` line 30.
- **AC-001-3:** The phrase `binding Acceptance Criteria document` appears at least once in `agents/sr-qa.md` and at least once in `agents/sr-staff.md` (anti-scope migration).
- **AC-001-4:** An inferential review of the modified files (LLM judge against the persona role definitions in `concepts/yoke-pattern-roles`) confirms each persona's lane semantics are preserved post-fix: Sr Eng never authors acceptance-criteria-anchored tests; Sr QA owns the `tests/acceptance/<contract-slug>/` lane; Sr Staff never invokes `/ultrareview` autonomously.
- **AC-001-5:** Reading the YAML frontmatter of each modified file via `awk '/^---/{c++; if(c==2)exit} c==1 && /^(description|objective): /' agents/sr-{eng,qa,staff}.md` produces no parse error and yields exactly one line per key per file.
