> **Definition of Done vs Acceptance Criteria — distinct, layered.**
> **DoD** is a single binary checklist per User Story that defines when
> the implementation is *finished*. **Acceptance Criteria** are
> multiple observable QA conditions per User Story that, given the
> implementation is done, define when the work is *acceptable* in
> quality terms. The runtime council enforces ordering: DoD checks
> must pass before any AC is evaluated for that story.

> **Sensor pool is unclassified at authoring time.** The
> `## Sensor pool` section below lists every sensor relevant to this
> task as a flat bullet list. Sr QA and Sr Staff pick which pool
> members gate which Acceptance Criterion at Phase 4 runtime, recording
> their selection in their per-cycle slice file. Authoring-time
> mandatory / complementary / optional tags are forbidden — they
> collapse a runtime-policy decision into an authoring-time decision.

## Functional Requirements

Cross-cutting requirements that span multiple stories. Each FR is sensor-decidable.

- **FR-1:** Every produced task MUST contain a single unified instruction block. Per-persona sub-sections (`**For Sr Eng:**`, `**For Sr QA:**`, `**For Sr Staff:**`) are forbidden — guidance density goes into the shared block. Verifiable by `grep -E '\*\*For Sr (Eng|QA|Staff):\*\*'` returning zero matches across produced sprint files.
- **FR-2:** Sprint runtime bundles produced by `/yoke:generate-sprints` MUST conform to `templates/sprint.md` exactly: YAML frontmatter + 5 H2 sections in fixed order. The bundle shape is the consumer-side contract for `/yoke:implement` and the council personas; no shape drift is allowed.
- **FR-3:** Re-running `/yoke:generate-sprints` against an unchanged `(spec, acceptance-criteria)` pair MUST converge to the same sprint partition (modulo deterministic ordering). Non-determinism in the partition stage is a defect.
- **FR-4:** The rename PR (`acceptance-contract` → `acceptance-criteria`) is a hard precondition; the implementation order is fixed: rename PR → this PR. The rename has merged on main as of 2026-05-03 (commit `a0b3dd2`); this work consumes the post-rename surface as-is and does not redo the rename inline.
- **FR-5:** Bash scripts authored under this PRD pass `shellcheck` with no new warnings (when the binary is available in CI).
