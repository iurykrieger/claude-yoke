## User Stories

### US-001 — Zero forbidden canonical-memory references in `lib/sensors/`

As a Yoke maintainer, I want every script under `lib/sensors/*.sh` to
be free of references to canonical-memory paths other than
`resolve-provider.sh`, so that the v2.0.0 facade boundary
(`yoke-decision-2026-04-30-namespace-separation-yoke-vs-provider`)
holds in the sensor surface and silent exit-2 failures stop masking
drift.

#### Definition of Done

- [ ] `lib/sensors/yoke-doctrine-round-trip.sh` removed from disk.
- [ ] `lib/sensors/contract-promotion-bidirectional.sh` removed from disk.
- [ ] `lib/sensors/no-canonical-memory-direct-refs.sh` exists and is executable (`-x` bit set).
- [ ] `shellcheck lib/sensors/no-canonical-memory-direct-refs.sh` exits 0.

#### Acceptance Criteria

- **AC-001-1:** Running the new regression sensor against the post-fix worktree (`bash lib/sensors/no-canonical-memory-direct-refs.sh`) exits 0 with empty stdout — silent-success per `concepts/yoke-pattern-sensors`.
- **AC-001-2:** Running the new regression sensor against a planted-fixture tree (a fixture sensor file containing the substring `lib/canonical-memory/registry.sh`) exits 1 with at least one structured-YAML violation block carrying `id`, `location`, `correction_instruction`, and `reference` keys.
- **AC-001-3:** A grep for the substring `lib/canonical-memory/registry.sh` OR `lib/canonical-memory/resolve-memory.sh` over `lib/sensors/*.sh` in the post-fix worktree returns no matches (the regression sensor's own forbidden-pattern definitions are exempt via the documented allow-list mechanism).

### US-002 — Surviving sensors do not source removed canonical-memory helpers

As a Yoke maintainer, I want the post-fix sensor surface to never
`source` substrate-direct canonical-memory helpers that were
extracted in v2.0.0, so that sensors are downstream of the facade
boundary and the facade rule (`yoke-pattern-facade-vs-provider-verbs`)
holds in code, not just in doctrine.

#### Definition of Done

- [ ] No surviving `lib/sensors/*.sh` file (excluding the regression sensor's allow-listed pattern definitions) contains a `source` directive whose argument matches the v2.0.0-extracted basename set (`registry.sh`, `resolve-memory.sh`, `write-promoted-concept.sh`).
- [ ] The regression sensor's detection pattern explicitly enumerates the v2.0.0-extracted basename set in its body or in a documented data file it reads.

#### Acceptance Criteria

- **AC-002-1:** Running `grep -nE 'source.*lib/canonical-memory/(registry|resolve-memory|write-promoted-concept)\.sh' lib/sensors/` over the post-fix worktree returns no matches outside the regression sensor's own allow-listed lines.
- **AC-002-2:** When the regression sensor flags a violation, its YAML output includes both the offending file path AND the offending substring (e.g., `registry.sh`) in the `correction_instruction` field — satisfying the structured-output rule from `concepts/yoke-pattern-sensors` ("Sensor output without precise violation identification + location + correction instruction is treated as a sensor bug").

### US-003 — Deletion atomicity (sensor + self-test in same change)

As a Yoke maintainer, I want each deleted sensor to ship together
with the deletion of its self-test under `tests/sensors/`, so that
the test runner's auto-discovery contract does not produce always-red
CI from orphan tests pointing at deleted scripts.

#### Definition of Done

- [ ] `tests/sensors/yoke-doctrine-round-trip.test.sh` removed from disk.
- [ ] No surviving file under `tests/sensors/*.test.sh` invokes a deleted sensor's command path (`lib/sensors/yoke-doctrine-round-trip.sh` or `lib/sensors/contract-promotion-bidirectional.sh`).
- [ ] `tests/run-all.sh` discovers and runs every remaining `tests/sensors/*.test.sh` without `bash: <path>: No such file or directory` errors attributable to either deleted sensor.

#### Acceptance Criteria

- **AC-003-1:** Running `bash tests/run-all.sh` on the post-fix worktree exits with the established baseline exit code (0 unless the project has independently failing tests outside this change's scope) and produces no `No such file or directory` errors mentioning `yoke-doctrine-round-trip` or `contract-promotion-bidirectional`.
- **AC-003-2:** Running `find tests/sensors -name '*.test.sh' -exec grep -lE 'yoke-doctrine-round-trip|contract-promotion-bidirectional' {} +` returns no files.

### US-004 — Post-fix sensor surface eliminates exit-2-from-removed-script class

As a Yoke maintainer, I want every invocation of every surviving
sensor under `lib/sensors/*.sh` to exit 0 or 1 (drift verdict) — never
2 from a missing-substrate-script path — so that the harness's
`exit 2 = environmental skip` semantics never silently mask drift
caused by stale references.

#### Definition of Done

- [ ] Every file under `lib/sensors/*.sh` either invokes only scripts that exist on disk in the post-fix worktree, OR documents an environmental-skip path whose exit-2 cause is unrelated to the v2.0.0-removed helper set (e.g., `shellcheck` binary absence).

#### Acceptance Criteria

- **AC-004-1:** Manual replay of every sensor in `lib/sensors/*.sh` (`bash lib/sensors/<id>.sh` with default flags) on the post-fix worktree returns exit code in `{0, 1}`, OR returns exit 2 with a stderr diagnostic that does not name any v2.0.0-removed helper (`registry.sh`, `resolve-memory.sh`, `write-promoted-concept.sh`).

### US-005 — Regression sensor exists, is discoverable, and self-tests pass

As a Yoke maintainer, I want a discoverable, self-tested regression
sensor that fails the build when any future PR re-introduces a
forbidden canonical-memory reference inside `lib/sensors/`, so that
the coverage gap which produced this fix is closed at PR time
rather than discovered at runtime.

#### Definition of Done

- [ ] `lib/sensors/no-canonical-memory-direct-refs.sh` exists, is executable, and shellcheck-clean.
- [ ] `tests/sensors/no-canonical-memory-direct-refs.test.sh` exists and exits 0 on the post-fix worktree.
- [ ] `.yoke/sensors/no-canonical-memory-direct-refs.md` exists with frontmatter (`id`, `command`, `type: computational`, `token_cost: 0`, `time_cost: 30`) and the four mandatory body sections (purpose, how to run, frequent errors, known issues).
- [ ] `bash lib/sensors/ack-sensors.sh --mode readiness` lists the new sensor without errors.

#### Acceptance Criteria

- **AC-005-1:** Running `bash tests/sensors/no-canonical-memory-direct-refs.test.sh` exits 0 with the positive subcase (clean tree → silent success), the negative subcase (planted forbidden ref → exit 1 with one violation per planted match), and the reverse subcase (legitimate `resolve-provider.sh` reference → silent success) all green.
- **AC-005-2:** Running `bash lib/sensors/no-canonical-memory-direct-refs.sh` against the post-fix worktree completes in < 500ms wall-clock and consumes 0 tokens of LLM budget (computational sensor, per `templates/sensor.md` semantics).
- **AC-005-3:** Running `bash lib/sensors/ack-sensors.sh --mode readiness` exits 0 and includes `no-canonical-memory-direct-refs` in its discovered-sensor listing.

### US-006 — Self-test of deleted sensor is also deleted

As a Yoke maintainer, I want the self-test of every deleted sensor
to be removed in the same change set, so that no orphan test file
remains in `tests/sensors/` whose subject script no longer exists.

#### Definition of Done

- [ ] `tests/sensors/yoke-doctrine-round-trip.test.sh` is not present on disk in the post-fix worktree.

#### Acceptance Criteria

- **AC-006-1:** Running `find tests/sensors -name 'yoke-doctrine-round-trip.test.sh'` on the post-fix worktree returns no files.
- **AC-006-2:** No surviving file under `tests/sensors/` references the basename `yoke-doctrine-round-trip` in its body — verified by `grep -rE 'yoke-doctrine-round-trip' tests/sensors/` returning no matches outside historical archives.

## Functional Requirements

- **FR-1:** Every bash script authored or modified under this change passes `shellcheck` with no new warnings — `shellcheck lib/sensors/no-canonical-memory-direct-refs.sh tests/sensors/no-canonical-memory-direct-refs.test.sh` exits 0.
- **FR-2:** `bash tests/run-all.sh` exits 0 on the post-fix worktree (or its established pre-change baseline if any unrelated failure is independently tracked) — this change introduces no new test-run failures.
- **FR-3:** No file authored or modified under this change re-introduces any path under `lib/canonical-memory/` other than `resolve-provider.sh`. The new regression sensor self-applies and its own forbidden-pattern definitions are exempt via a documented allow-list mechanism (header marker, fenced block, or external data file).
- **FR-4:** The new sensor catalog entry at `.yoke/sensors/no-canonical-memory-direct-refs.md` carries frontmatter that satisfies the existing per-sensor frontmatter schema (`id`, `command`, `type`, `token_cost`, `time_cost`) — verified by the existing harness sensor that walks `.yoke/sensors/<id>.md` frontmatter shape.
- **FR-5:** The plugin-distribution layout invariant — every script and entry under the canonical pattern at `concepts/yoke-pattern-plugin-structure` — remains satisfied after the change. Deletions and additions stay within the documented sub-tree.
