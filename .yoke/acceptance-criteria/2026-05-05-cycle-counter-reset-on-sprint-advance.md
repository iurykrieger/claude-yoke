## User Stories

### US-001 — Provide a deterministic `.cycle-counter` reset primitive

As a Yoke maintainer, I want a `wm_reset_cycle_counter` helper inside
`lib/working-memory/paths.sh`, so that the sprint-advance code path has
a single deterministic primitive for zeroing the runtime cycle counter
file.

#### Definition of Done

- [ ] A function named `wm_reset_cycle_counter` is defined inside
  `lib/working-memory/paths.sh` in the existing `# --- runtime paths ---`
  region, immediately below `wm_cycle_counter_path`.
- [ ] The function is callable after `source lib/working-memory/paths.sh`
  with no arguments.
- [ ] The function exits 0 on success and surfaces a `wm:`-prefixed
  stderr message plus a non-zero exit on filesystem error.
- [ ] `shellcheck lib/working-memory/paths.sh` reports no new warnings
  introduced by this change.

#### Acceptance Criteria

- **AC-001-1:** Given the runtime directory does not exist, when
  `wm_reset_cycle_counter` is called, then
  `.yoke/runtime/.cycle-counter` exists afterwards and reads exactly
  the byte `0` (no trailing newline, no whitespace).
- **AC-001-2:** Given `.yoke/runtime/.cycle-counter` already contains
  the integer `0`, when `wm_reset_cycle_counter` is called, then the
  file still reads exactly `0` — i.e. the helper is idempotent.
- **AC-001-3:** Given `.yoke/runtime/.cycle-counter` contains a
  non-zero integer (e.g. `7`), when `wm_reset_cycle_counter` is
  called, then the file is overwritten and reads exactly `0`.
- **AC-001-4:** The helper is contained — calling it does not write
  to `progress.md`, does not invoke any canonical-memory verb, and
  does not modify any file outside `wm_cycle_counter_path()`.

### US-003 — `.cycle-counter` reads `0` at the first cycle of any sprint after the first

As `hooks/check-hard-bounds.sh`, I want to read a per-sprint cycle
count (not a cumulative cross-sprint count), so that the documented
≤ 8-cycles-per-sprint guarantee is honored on every sprint, not just
the first.

#### Definition of Done

- [ ] At the start of any sprint with `current_sprint > 01`,
  `.yoke/runtime/.cycle-counter` reads exactly `0`.
- [ ] `hooks/check-hard-bounds.sh` is unchanged in this delivery
  (its line 93 read remains the consumer of record).
- [ ] `lib/ralph-loop/status-snapshot.sh` is unchanged in this
  delivery (its read of `.cycle-counter` is unaffected).

#### Acceptance Criteria

- **AC-003-1:** Given a fresh worktree's `.yoke/runtime/.cycle-counter`
  has been seeded with a value `N` where `1 ≤ N ≤ 8` (simulating the
  end of sprint 1), when the sprint-advance path executes, then
  reading `.yoke/runtime/.cycle-counter` afterwards yields exactly
  `0`.
- **AC-003-2:** Given a single-sprint task (only `*-s01.md` exists),
  when `/yoke:implement` runs to completion, then the helper is never
  invoked and behavior is observably identical to the pre-fix
  baseline (zero regression on `current_sprint == 01`).
- **AC-003-3:** Given the sprint-advance path is interrupted
  (process killed) **after** `wm_reset_cycle_counter` has executed
  but **before** the next cycle starts, when the run is later
  resumed, then `.cycle-counter` still reads `0` — the post-reset
  state is the correct semantic for the incoming sprint.

### US-004 — Behavior smoke test pins the helper contract

As Yoke QA, I want
`tests/smoke/cycle-counter-reset-on-sprint-advance.test.sh`
exercising the helper across absent / seeded / idempotency cases, so
that a regression in the file-side reset is caught by CI rather than
by a future user observing premature or bypassed Trigger-4
escalation.

#### Definition of Done

- [ ] A new file
  `tests/smoke/cycle-counter-reset-on-sprint-advance.test.sh` exists.
- [ ] The test installs the documented internal watchdog
  (`sleep 600 && kill -TERM $$ &`) per `CLAUDE.md :: ## Testing`.
- [ ] The test isolates `WM_RUNTIME_DIR` to a temporary directory
  (e.g. `mktemp -d`) so it cannot pollute the worktree's actual
  `.yoke/runtime/`.
- [ ] The test exits 0 on the happy path and non-zero on any
  assertion failure.
- [ ] The test completes in ≤ 10s wall-clock.

#### Acceptance Criteria

- **AC-004-1:** The test asserts AC-001-1 (helper creates the file
  with content `0` when absent).
- **AC-004-2:** The test asserts AC-001-2 (idempotent overwrite when
  the file already contains `0`).
- **AC-004-3:** The test asserts AC-001-3 (overwrite from a non-zero
  seed value, e.g. `7`, to `0`).
- **AC-004-4:** The test seeds a non-zero value before invoking the
  helper, so a coincidentally-zero counter cannot make the test pass
  without the helper actually executing the reset.
- **AC-004-5:** The test asserts AC-001-4 (the helper does not
  write to `progress.md` or any file outside
  `wm_cycle_counter_path()`).
- **AC-004-6:** The test exits 0 on the happy path within the
  ≤ 10s budget; the watchdog is the safety bound, not the target.
