## Functional requirements

Measurable, observable. Each FR maps to a concrete sensor or fixture.

- [ ] **FR-1** — A user installing Yoke alone (no peer plugin) can invoke `/yoke:search-canonical-memory "<query>"` and `/yoke:canonize` and have those calls dispatch through `providers.yaml` into existing skills with byte-equivalent responses to the legacy verbs. Sensors: `search-facade-equivalence`, `canonize-skill-shape`.
- [ ] **FR-2** — `providers.yaml` is the single source of truth for provider dispatch and has a frozen schema (`schema_version: 1`) consumed by `lib/canonical-memory/resolve-provider.sh`. Sensors: `providers-yaml-shape`, `resolve-provider-callable`.
- [ ] **FR-3** — `claude-bedrock` is a peer plugin installable independently of Yoke and exposes `/bedrock:ask`, `/bedrock:teach`, plus the five other migrated skills under the `/bedrock:` namespace. Sensors: `claude-bedrock-plugin-manifest`, `claude-bedrock-skills-migrated`.
- [ ] **FR-4** — `/bedrock:teach` consumes `.yoke/` per the working-memory provider contract (`contract_version: 1`) and writes ≥ 1 entity to the configured Bedrock vault under Model C governance, returning the soft exit-summary line. Sensors: `bedrock-canonize-skill-shape`, `bedrock-canonize-roundtrip`, `provider-contract-doc-shape`.
- [ ] **FR-5** — Every Yoke internal call-site (agents, spec-phase skills, `/yoke:implement`, sensors, tests, lib helpers) references only the facade verbs `/yoke:search-canonical-memory` and `/yoke:canonize` — never the legacy seven verbs. Sensors: `live-callsites-zero-legacy-refs`, `end-to-end-implement-cycle`.
- [ ] **FR-6** — Every Yoke skill except `bootstrap` and the seven legacy skills sources `lib/yoke-prelude.sh` and aborts non-zero with the documented message when `.yoke/config.yaml` lacks `canonical_memory.provider`. Sensors: `yoke-prelude-helper-callable`, `hard-break-pre-flight-enforced`, `prelude-source-line-audit`.
- [ ] **FR-7** — `/yoke:bootstrap` migrates a Yoke v1.x project (legacy `<plugin_dir>/memories.json` or v1.x-shaped `.yoke/config.yaml`) to v2.0.0 schema with `canonical_memory.provider: bedrock` and removes the legacy registry; fresh bootstrap writes the same key based on interactive selection or `--provider`. Sensors: `bootstrap-provider-flow`, `bootstrap-legacy-migration`.
- [ ] **FR-8** — The Yoke plugin source tree at the end of Sprint 3 contains zero residual artifacts of the legacy canonical-memory implementation: no legacy skill directories under `skills/`, no migrated scripts under `lib/canonical-memory/` (only `resolve-provider.sh`), no `entities/`, no `templates/canonical/`, no `templates/yoke-memory-config.json`, no `templates/canonical-entry-frontmatter.yaml`. Sensors: `legacy-skills-zero-residual`, `no-vibeflow-refs-sensor-pins-migration`.
- [ ] **FR-9** — All user-facing documentation (`docs/`, `CLAUDE.md`, `README.md`, `CHANGELOG.md`) and runtime templates (`templates/acceptance-contract.md`, `templates/task.md`, `templates/project-claude-md.md`, `templates/yoke-config.yaml`) reference only the facade verbs (CHANGELOG breaking-change block excluded). Sensors: `docs-zero-legacy-refs`, `docs-facade-presence`, `templates-zero-legacy-refs`, `templates-facade-presence`.
- [ ] **FR-10** — `.claude-plugin/plugin.json` reports `version: 2.0.0`, the description mentions `pluggable canonical-memory`, and `docs/migration-v1-to-v2.md` carries the upgrade runbook. Sensors: `plugin-version-2-0-0`, `migration-runbook-shape`.
- [ ] **FR-11** — The `legacy-parts-zero-residual` sensor (already present at main) continues to exit 0 across all three sprints — no `.yoke/specs/<slug>-part-N.md` and no `.yoke/tasks/<slug>-s*-t*.md` files appear in this PRD's working memory. Sensors: `legacy-parts-zero-residual`.

### Inferential sensors — calibration metadata

This Acceptance Contract declares **zero inferential sensors**. Every
criterion is decidable by a deterministic computational sensor (grep,
jq, yq, bash test, fixture-driven smoke). The entire abstraction is
structural — file presence, manifest fields, namespace rewrites,
exit codes, exit-summary regex — and admits no judgment-grade
ambiguity that would warrant LLM-evaluated criteria. If runtime
sprints surface a need for inferential calibration (e.g., a future
provider adds semantic-equivalence checks), the sprint contract
escalation pathway (Trigger 4) is the channel; this Contract does
not pre-allocate inferential capacity.
