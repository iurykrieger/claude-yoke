## Functional requirements

Measurable, observable. Each FR maps to a concrete sensor or
fixture.

### Criterion FR-1 — Stack auto-detection from manifest files

`/yoke:tech-spec` reads (when present) `package.json`, `go.mod`,
`Cargo.toml`, `requirements.txt`, `pyproject.toml`, `pom.xml`, and
`Gemfile` via the `Read` tool to populate the stack-default offer
in the dialogue.

### Validation

- **`tech-spec-stack-auto-detect`** — pass = a tempdir host project seeded with `package.json` causes the skill's stack-detection round to surface "Node.js / TypeScript family" as the default; pass when ≥ 2 manifests are present, the skill lists every detected stack as a candidate without auto-picking; fail = the skill silently picks one stack on a polyglot repo or never reads the manifest.

### Criterion FR-2 — Curated stack menu by feature category

`/yoke:tech-spec` presents a curated menu by feature category
(web-api / web-ui / cli / library / data-pipeline) with 3-5
lettered options + `Other: <free-text>` per category before
drafting begins.

### Validation

- **`tech-spec-stack-menu-curated`** — pass = the dialogue transcript contains a 3-5-option lettered menu for the chosen category plus an `Other:` line; fail = no menu printed or the menu skips the `Other:` escape.

### Criterion FR-3 — Canonical-memory query + threshold-gated WebSearch

`/yoke:tech-spec` invokes `/yoke:search-canonical-memory` with a
domain-scoped query; if the response surfaces fewer than
`overrides.tech_spec.canonical_pattern_threshold` (default 3)
applicable pattern entities, the skill loads `WebSearch` via
`ToolSearch` and runs a single targeted query; the chosen
alternatives are cited in `## Alternatives Considered` with the
`Source:` label populated.

### Validation

- **`tech-spec-canonical-memory-query`** — pass = the skill's transcript shows a `/yoke:search-canonical-memory` call with a non-empty domain-scoped query; fail = no canonical-memory query fired.
- **`tech-spec-web-search-threshold-fallback`** — pass = with `overrides.tech_spec.canonical_pattern_threshold: 99`, `WebSearch` fires once and the spec's `## Alternatives Considered` cites a URL returned by it; with the override unset (default 3) and ≥ 3 patterns from canonical memory, `WebSearch` does NOT fire; fail = WebSearch fires unconditionally or never fires regardless of threshold.

### Criterion FR-4 — Single-file 12-section spec output

`/yoke:tech-spec` outputs exactly one file at
`wm_spec_path "$slug"` carrying these H2 sections in this order:
Context and Scope; Goals and Non-Goals; System Context;
Architecture; Stack and Dependencies; APIs and Data Model;
Non-Functional Requirements; Alternatives Considered; Trade-offs;
Cross-cutting Concerns; Technical Use Cases; Open Questions.

### Validation

- **`tech-spec-design-doc-shape`** — pass = `grep -cE '^## (Context and Scope|Goals and Non-Goals|System Context|Architecture|Stack and Dependencies|APIs and Data Model|Non-Functional Requirements|Alternatives Considered|Trade-offs|Cross-cutting Concerns|Technical Use Cases|Open Questions)$' "$spec"` returns `12` AND the headings appear in the documented order; fail = any heading missing, out of order, or any extra H2 in between.

### Criterion FR-5 — No sprint-file or task-anchor side-effects in Phase 2

`/yoke:tech-spec` does not create any file under `.yoke/sprints/`
and does not emit any `### Task <ID>` anchor in the spec body.
The skill aborts non-zero if the post-draft self-check finds
either violation.

### Validation

- **`tech-spec-no-task-anchors`** — pass = `grep -cE '^### Task ' "$spec"` returns `0`; fail = ≥ 1 task anchor in the spec body.
- **`tech-spec-no-sprint-files-from-phase-2`** — pass = `find .yoke/sprints -name "${slug}-s*.md" | wc -l` returns `0` after a Phase-2-only run; fail = ≥ 1 sprint file present after Phase 2.

### Criterion FR-6 — US-### lift into Technical Use Cases

Each PRD `US-###` lifts to a `### US-### — <title>` subsection
under `## Technical Use Cases` with at least the four labels
`**Components involved:**`, `**Contracts used:**`,
`**NFRs applied:**`, `**Edge cases:**`. Silent drops abort.

### Validation

- **`tech-spec-us-id-lifted-into-technical-use-cases`** — pass = every `US-###` from the PRD appears as a `### US-### —` subsection in the spec or is marked `Deferred:` in `## Open Questions`; fail = any PRD `US-###` is silently absent.

### Criterion FR-7 — Quantitative NFR self-check

Each `## Non-Functional Requirements` bullet matches the
quantitative-target regex
`\d+(\.\d+)?\s*(ms|s|%|rps|qps|req/s|MB|GB|TB|users)`
(case-insensitive). Adjective-only entries make the post-draft
self-check abort non-zero.

### Validation

- **`tech-spec-quantitative-nfr-rejector`** — pass = injecting `- **Performance:** fast` into the dialogue triggers a non-zero abort with a `wm:`-prefixed message naming the offending bullet; pass = NFR bullets like `- **Latency:** p95 < 200ms` are accepted; fail = adjective-only entries pass the self-check.

### Criterion FR-8 — Alternatives triple-shape self-check

Each `### Alt: <name>` subsection carries the three labelled lines
`**Trade-off vs. chosen:**`, `**Reason for rejection:**`,
`**Source:**`. Missing labels make the self-check abort non-zero.

### Validation

- **`tech-spec-alternatives-triple-rejector`** — pass = an alternative missing any of the three labels triggers a non-zero abort with a `wm:` message naming the offending alternative; pass = an alternative with all three labels and a `Source:` value (canonical-memory wikilink, WebSearch URL, or `internal experience`) is accepted; fail = missing-label alternatives pass the self-check.

### Criterion FR-9 — Phase 3 absorbs sprint partition + task breakdown

`/yoke:acceptance-contract` produces both
`.yoke/acceptance-contracts/<slug>.md` and ≥ 1
`.yoke/sprints/<slug>-s<NN>.md` file with the existing
`templates/sprint.md` shape (frontmatter + five H2 sections + per-
task subsections with the four inline labels) — only the producer

### Validation

- **`acceptance-contract-stage-b-sprint-files-produced`** — pass = `wm_list_sprint_paths "$slug" | wc -l` returns `>= 1` after Phase 3; fail = no sprint file produced.
- **`acceptance-contract-sprint-file-five-h2-shape`** — pass = every sprint file matches `grep -cE '^## (Sprint objective|Sprint DoD|Tasks|Functional acceptance criteria|Sensors)$'` returning `5` AND headings in order; fail = any H2 missing or out of order.
- **`acceptance-contract-task-anchor-four-labels`** — pass = every `### Task <slug>-s<NN>-t<MM>` subsection contains all four inline labels (`**Story:**`, `**Technical implementation:**`, `**Validation:**`, `**Acceptance criterion:**`); fail = any task anchor is missing a label.

### Criterion FR-10 — Atomic Trigger 3 across contract + sprint files

## Inferential sensors

Sprint-3 placeholder shape preserved per the template note. The
twelve-section design-doc shape and the post-draft self-checks are
deliberately deterministic (grep + regex), so no inferential sensor
is required to gate the Phase-2 contract. The dogfood validation in
Scenario 6 carries one subjective check (the maintainer's "useful /
not useful" call on the produced spec) which is recorded as a
human-in-the-loop signal in the dogfood contract's `## Notes` block,
not as an automated inferential sensor in v0. If the dogfood run
surfaces a recurring miscalibration (e.g., the US-### lift produces
shallow technical context across multiple specs), a calibrated
semantic-judge sensor for the spec body becomes a follow-up PRD
candidate — out of scope for this contract.
