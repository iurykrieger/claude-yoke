## Introduction

Yoke v2.0.0 extracted the canonical-memory substrate code out of the
framework into a peer plugin (`claude-bedrock`), keeping only
`lib/canonical-memory/resolve-provider.sh` inside Yoke. The doctrine
that governs every canonical-memory read post-v2.0.0 is the
facade-vs-provider rule: Yoke code dispatches through the facades
`/yoke:search-canonical-memory` (read) and `/yoke:canonize` (write),
never against substrate-specific scripts. Two production sensors
under `lib/sensors/` were not migrated to the v2.0.0 contract and
still call removed scripts directly. Because both sensors silence
their substrate-resolution errors with `2>/dev/null` or rely on
`exit 2` paths that downstream callers treat as "environmental
skip", their drift signal never surfaces — they look like green
sensors but never actually evaluate their invariants.

The reader of this fix-spec is the Tech-Spec author (Phase 2) who
will pick between option (a) "delete the sensors" and option (b)
"rewrite to dispatch through the facade", based on whether each
sensor still has a load-bearing role under the v4.0 acceptance-
criteria shape. The fix-spec captures the contract violation and
the FR set the fix must satisfy; it does not pre-decide the
delete-vs-rewrite split, because that decision depends on whether
the sensor's binding contract still exists post-v4.0.

## What Broke

Two sensor scripts under `lib/sensors/` invoke canonical-memory
helpers that were removed during the v2.0.0 facade extraction. Both
violate the v2.0.0 facade rule and both fail in a way the test
harness treats as "environmental skip" rather than "drift detected".

- `lib/sensors/yoke-doctrine-round-trip.sh:43` calls
  `bash "$YOKE_PLUGIN_DIR/lib/canonical-memory/registry.sh" path-of
  iury-brain 2>/dev/null` to resolve the canonical-memory checkout
  path. `lib/canonical-memory/registry.sh` was removed in v2.0.0; the
  only file that survives under that directory is
  `resolve-provider.sh`. The `2>/dev/null` swallows the "command not
  found" diagnostic; the sensor body then sees an empty `$VAULT` and
  exits 2 with `round-trip: canonical-memory checkout not found`.
- `lib/sensors/contract-promotion-bidirectional.sh:70` sources
  `${_CPB_PLUGIN_ROOT}/lib/canonical-memory/resolve-memory.sh` and
  calls `yoke_resolve_memory`. Both `resolve-memory.sh` and the
  `yoke_resolve_memory` function were removed in v2.0.0 (they live
  in the `claude-bedrock` peer plugin now). The `if ! source ...`
  guard catches the missing file and exits 2 with
  `contract-promotion-bidirectional: failed to source
  resolve-memory.sh`.
- `tests/sensors/yoke-doctrine-round-trip.test.sh:8` documents the
  same removed contract in its header comment ("resolved via
  `lib/canonical-memory/registry.sh path-of iury-brain`") and its
  case (4) negative-path fixture creates a stub `registry.sh` to
  satisfy the sensor's expectations — both are stale relative to the
  v2.0.0 contract.

## Reproduction / Trigger

The trigger is any invocation of either sensor. Two reproduction
paths:

- Direct invocation from the framework's working tree:

  ```bash
  bash lib/sensors/yoke-doctrine-round-trip.sh
  # → "round-trip: canonical-memory checkout not found" → exit 2
  bash lib/sensors/contract-promotion-bidirectional.sh
  # → "contract-promotion-bidirectional: failed to source resolve-memory.sh" → exit 2
  ```

- Indirect invocation via the test harness or the per-cycle sensor
  pool. Any caller that runs these sensors (CI, smoke-test pipeline,
  council persona's per-cycle sensor pool) gets the exit-2 path; the
  harness treats exit 2 as "environmental / skip" by convention,
  which masks the breakage from the failing-sensor surface.

## Expected Behavior

The contract anchor is the v2.0.0 facade rule, which is doctrine in
canonical memory:

- `concepts/yoke-pattern-facade-vs-provider-verbs` — "Yoke skills
  MUST NOT invoke provider verbs directly. Only facades dispatch."
- `concepts/yoke-decision-2026-04-30-namespace-separation-yoke-vs-provider`
  — "Yoke skills MUST NOT invoke provider verbs directly. Only the
  two facades dispatch. Cross-plugin file references use plugin-
  relative paths (`<plugin_dir>/...`); never hard-code another
  plugin's filesystem location."
- `concepts/yoke-decision-2026-04-30-v2-0-0-hard-break-migration` —
  "The seven legacy skills (`ask`, `preserve`, `teach`, `compress`,
  `memory`, `confluence-to-markdown`, `gdoc-to-markdown`) are
  deleted from Yoke at v2.0.0 — they no longer exist to source the
  helper."
- `CLAUDE.md` migration history (2026-04-30, v2.0.0) — "the single-
  vendor canonical-memory implementation that was forked from
  Bedrock at Sprint 5 (seven skills + lib + entities + canonical
  templates) was extracted out of `claude-yoke` into the standalone
  `claude-bedrock` peer plugin."

Concretely, every Yoke-side script that needs canonical-memory data
either (i) reads it through `/yoke:search-canonical-memory`, or
(ii) does not read it at all. Sensors are no exception. Sensors
that cannot honor that contract — because their invariant requires
substrate-direct filesystem traversal that the facade does not
expose — are obsolete relative to the v2.0.0 doctrine and must be
deleted, not silently skipped.

A second contract anchor is the structured-output rule for sensors
(`concepts/yoke-pattern-sensors`): "Sensor output without precise
violation identification + location + correction instruction is
treated as a sensor bug, not as valid output." A sensor that exits
2 because its dependencies have been removed is producing an
infrastructure-error code, not a drift verdict — by the structured-
output rule, that is a sensor bug.

## Observed Behavior

Both sensors exit non-zero with infrastructure diagnostics, not with
drift verdicts:

- `yoke-doctrine-round-trip.sh` resolves an empty `$VAULT` (because
  `registry.sh` is missing and the heuristic ancestor-search for
  `memories.json` finds nothing — `memories.json` itself was retired
  in v2.0.0), prints `round-trip: canonical-memory checkout not
  found` to stderr, and exits 2. No round-trip queries are evaluated.
- `contract-promotion-bidirectional.sh` fails the `source
  resolve-memory.sh` guard, prints `contract-promotion-bidirectional:
  failed to source resolve-memory.sh`, and exits 2. No bidirectional-
  link invariant is evaluated.
- Neither sensor is registered in the post-v2.0 sensor catalog under
  `.yoke/sensors/<id>.md`; both are referenced only by historical
  acceptance contracts under `.yoke/acceptance-contracts/historical/`
  and by the legacy sprint snapshot
  `.yoke/sprints/2026-04-30-pluggable-canonical-memory-s02.md`.
- `tests/sensors/yoke-doctrine-round-trip.test.sh` "passes" against
  this state because its case (4) negative-path fixture explicitly
  expects exit non-zero with the literal stderr substring
  `canonical-memory checkout not found`. The structural test
  validates that the sensor remains broken in a stable way — it does
  not exercise the round-trip pass-state, which is gated to "CI
  integration tests (gated by Sprint 08)" per the test header.

## Blast Radius

**One module** — the post-v2.0 sensor pipeline (`lib/sensors/` plus
its self-tests under `tests/sensors/`). The change is contained to
two sensor scripts, one self-test, and any catalog metadata under
`.yoke/sensors/<id>.md` (which currently does not exist for either
sensor). Whoever depends on the violated contract is the binding-
sensor consumer surface — the council personas during Phase A's
per-cycle sensor pool, the CI tests workflow, and any human reading
the sensor self-test results. The success metric is binary: each
sensor either evaluates its invariant (option b) or stops being
referenced (option a), and the harness no longer interprets a
removed-script exit-2 as an "environmental skip".

The radius does not span cross-module: the two sensors are leaves of
the dependency graph (no other sensor sources them; their catalog
entries do not exist; the historical acceptance contracts referencing
them are under `.yoke/acceptance-contracts/historical/` and are
preserved on disk for archival per the no-historical-migration policy
ratified 2026-05-03).

## Root-Cause Hypothesis (optional)

Both sensors were authored at Sprint 5 / Sprint 02 of the doctrine-
canonization line, when `lib/canonical-memory/registry.sh` and
`lib/canonical-memory/resolve-memory.sh` were the v1.x substrate-
resolution surface. The 2026-04-30 v2.0.0 facade extraction migrated
**skills** (`ask`, `preserve`, `teach`, `compress`, `memory`,
`confluence-to-markdown`, `gdoc-to-markdown`) and the **library
helpers they consumed** out of Yoke into `claude-bedrock`, but the
sensor surface was not walked at the same time. The migration audit
that gated v2.0.0 (per `lib/sensors/no-vibeflow-refs.sh` and
adjacent) checked for direct-substrate references in skill bodies
and library helpers, not in `lib/sensors/*.sh`. That coverage gap is
why these two sensors slipped through — and is itself a signal that
should be addressed (FR-5 below).

## Functional Requirements

- **FR-1:** After this fix, every script under `lib/sensors/*.sh`
  MUST NOT reference any path under `lib/canonical-memory/` other
  than `lib/canonical-memory/resolve-provider.sh`. Specifically:
  references to `lib/canonical-memory/registry.sh` and
  `lib/canonical-memory/resolve-memory.sh` MUST be either deleted
  or replaced with a dispatch through `/yoke:search-canonical-memory`.
- **FR-2:** Every sensor that survives the fix (option b path for
  any given sensor) MUST resolve its canonical-memory data through
  `/yoke:search-canonical-memory`. Sourcing
  `lib/canonical-memory/resolve-provider.sh` directly is permitted
  only inside facade skills and runtime helpers, NOT inside sensor
  scripts; sensors are downstream of the facade.
- **FR-3:** Every sensor that is deleted (option a path for any
  given sensor) MUST also have its self-test under
  `tests/sensors/<sensor-id>.test.sh` deleted, and any references to
  the sensor in `.yoke/sensors/<sensor-id>.md`,
  `.yoke/acceptance-criteria/<slug>.md`, and `.yoke/contracts/<slug>.md`
  active files MUST be either removed (active artifacts) or left in
  place (`.yoke/acceptance-contracts/historical/**` files, per the
  no-historical-migration policy). The active-vs-historical split is
  the live-callsite boundary.
- **FR-4:** When this fix lands, invocation of every sensor under
  `lib/sensors/*.sh` either (i) exits 0 / 1 with a drift verdict in
  the structured shape required by `concepts/yoke-pattern-sensors`,
  or (ii) does not exist on disk. **Exit 2 from a missing-substrate-
  script path is no longer an acceptable outcome for any sensor**
  under `lib/sensors/`. Exit 2 from genuinely environmental causes
  (e.g. missing `shellcheck` binary) remains acceptable per existing
  doctrine.
- **FR-5:** The framework MUST gain a regression sensor that fails
  when any new file under `lib/sensors/*.sh` introduces a reference
  to `lib/canonical-memory/<X>` for any `<X>` other than
  `resolve-provider.sh`, OR sources any helper that was extracted to
  the active provider plugin in v2.0.0. The sensor is computational
  (deterministic textual scan, O(N) over `lib/sensors/*.sh`) and
  guards against the same coverage-gap that produced this fix.
- **FR-6:** When this fix lands, the test workflow that runs
  `tests/sensors/*.test.sh` MUST NOT carry a self-test whose
  documented contract still describes the removed substrate-
  resolution chain. `tests/sensors/yoke-doctrine-round-trip.test.sh`
  (and its header documentation) is in scope under this requirement.

## Non-Goals (Out of Scope)

- Re-introducing `lib/canonical-memory/registry.sh` or
  `resolve-memory.sh` as Yoke-side helpers. They live in the active
  provider plugin (`claude-bedrock`) and stay there.
- Migrating the historical acceptance contracts under
  `.yoke/acceptance-contracts/historical/**` to remove the dangling
  sensor references. The 2026-05-03 no-historical-migration policy
  preserves those files on disk.
- Inventing a new canonical-memory facade verb that exposes
  substrate-direct filesystem traversal to sensors. The facade is
  query-shaped, not filesystem-shaped, by design — see
  `concepts/yoke-pattern-facade-vs-provider-verbs`.
- Changing the host-project sensor catalog shape under
  `.yoke/sensors/<id>.md`. The fix is scoped to `lib/sensors/*.sh`
  and `tests/sensors/*.test.sh` plus, where warranted, deletion of
  active references in `.yoke/sensors/`, `.yoke/acceptance-criteria/`
  and `.yoke/contracts/` (active task only — no historical files).
- Shipping the option-b rewrite path "and also" deleting one of the
  sensors. The Tech Spec must commit to either (a) or (b) per
  sensor; ambiguity is exited at the Tech-Spec phase, not absorbed
  here.

## Risks

- **Removed sensor was load-bearing for an active acceptance
  criterion.** — A council persona's per-cycle sensor pool may
  reference `yoke-doctrine-round-trip` or
  `contract-promotion-bidirectional` as part of an active
  acceptance-criteria document. Signal: an active
  `.yoke/acceptance-criteria/<slug>.md` body lists either sensor id
  in its sensor pool. Mitigation: the Tech Spec must scan
  `.yoke/acceptance-criteria/**.md` (excluding the legacy
  `.yoke/acceptance-contracts/**`) for sensor-id references before
  picking the delete-vs-rewrite split per sensor.
- **Self-test validates broken state by accident.** — Removing
  `tests/sensors/yoke-doctrine-round-trip.test.sh` without first
  retiring the sensor it tests creates a coverage gap; conversely,
  retiring the sensor without retiring the test creates an
  always-red CI signal. Signal: CI exits non-zero with `bash:
  tests/sensors/yoke-doctrine-round-trip.test.sh: No such file or
  directory` or similar. Mitigation: pair the deletion of any
  sensor with the deletion of its self-test in the same change.
- **FR-5 regression sensor introduces its own substrate
  dependency.** — A sensor that scans `lib/sensors/*.sh` for
  forbidden references must itself be implementable without
  reading canonical memory. Signal: the FR-5 sensor sources
  anything under `lib/canonical-memory/` other than
  `resolve-provider.sh`. Mitigation: implement FR-5 as a pure
  textual scan (`grep` over `lib/sensors/*.sh`) — no canonical-
  memory access, no facade dispatch.
- **Tech-Spec deferral defers the breakage.** — If the Tech Spec
  picks option (b) but the implementation phase fails to land the
  facade-dispatch path inside the sensor, both sensors stay broken
  and FR-1 fails. Signal: post-fix, either sensor still references
  a removed script. Mitigation: the FR-5 regression sensor closes
  this gap by failing the build if any reference survives.
