# Fix-spec: Council persona prompts still author against the legacy "Acceptance Contract" vocabulary post v4.0.0

## Introduction

The v4.0.0 cutover (PRD `2026-05-03-acceptance-criteria-refactor`,
CHANGELOG entry "v4.0.0", CLAUDE.md "Migration history" 2026-05-03)
renamed the binding Phase-3 artifact from "Acceptance Contract" to
**Acceptance Criteria** and reshaped its body into User Stories →
Definition of Done → Acceptance Criteria → Sensor pool. The skills,
the working-memory path helpers, the templates, and the hooks were
migrated in that release. The three council persona prompts at
`agents/sr-eng.md`, `agents/sr-qa.md`, and `agents/sr-staff.md` were
not — they continue to instruct Phase-A authors to "close the next
failing **Acceptance-Contract** criterion(s)" and to author
"**acceptance-contract-anchored** tests" against the
"binding **Acceptance Contract**".

Each `/yoke:implement` cycle re-loads the persona prompts verbatim
into the Task call's system prompt at Phase A. With stale doctrine
in the prompt, every cycle re-introduces legacy vocabulary into the
council's per-cycle slice files, into runtime logs, and into any
artifact a persona writes — even though the host filesystem now
holds `.yoke/acceptance-criteria/<slug>.md` and `wm_acceptance_criteria_path`
is the only resolver.

The drift is invisible to CI: the smoke sensor
`tests/smoke/orphan-acceptance-contract-refs.test.sh` uses a
case-sensitive grep (`acceptance-contract(s)?`) that does not match
the title-cased `Acceptance-Contract` / `Acceptance Contract` forms
the persona prompts actually use, and its allowlist explicitly
accepts the lower-cased `acceptance-contract-anchored` substring as
an intentional v4.x retention. The drift therefore passes the
existing gate silently. The reporter (issue #47) flagged this as
"F1 — v4.0 doctrine drift" and noted "see also F10" for the sensor
coverage gap; sensor hardening is intentionally **out of scope** of
this fix (see Non-Goals).

## What Broke

The v4.0.0 cutover doctrine — "the binding Phase-3 artifact is the
**Acceptance Criteria** document; criterion identifiers are
`AC-<US>-<n>` or `FR-N`; tests anchor to that document, not to a
contract" — is contradicted by the three council persona prompts:

- `agents/sr-eng.md` — frontmatter `description:` (line 3) and
  `objective:` (line 5) instruct the Senior Engineer to close the
  "next failing Acceptance-Contract criterion(s)" and to defer
  "acceptance-contract-anchored tests" to Sr QA. Line 31 names the
  cycle's target as "the next failing Acceptance-Contract criterion
  (or coupled-criteria batch)". Line 36's body and line 140's
  anti-scope name "acceptance-contract-anchored tests".
- `agents/sr-qa.md` — frontmatter `description:` (line 3) and
  `objective:` (line 5) describe the Senior QA's authoring lane as
  "acceptance-contract-anchored tests" and reference "the binding
  contract's `### Validation` blocks". Body lines 24, 27, 37, and
  the anti-scope at line 184 use the same legacy form ("the binding
  Acceptance Contract", "Acceptance Contract's criteria",
  "**acceptance-contract-anchored tests**").
- `agents/sr-staff.md` — line 164's body names "Sr QA
  (acceptance-contract-anchored tests)" and line 176's anti-scope
  reads "Never relax the binding Acceptance Contract".

## Reproduction / Trigger

1. From the repository root, run:

   ```
   grep -nE 'acceptance-contract|Acceptance-Contract|Acceptance Contract' \
       agents/sr-eng.md agents/sr-qa.md agents/sr-staff.md
   ```

   The command returns 13 hits across the three files (5 in
   `sr-eng.md`, 6 in `sr-qa.md`, 2 in `sr-staff.md`).
2. Open any of the cited lines — the persona prompt instructs the
   Phase-A subagent to author work against an artifact ("Acceptance
   Contract") that has been renamed at the framework level since
   v4.0.0.
3. Trigger the live runtime path: invoke `/yoke:implement <slug>`
   on any current task. At Phase A the coordinator spawns the three
   personas; each Task receives the legacy vocabulary in its system
   prompt and authors per-cycle slices under
   `.yoke/runtime/cycles/<N>/<persona>.md` that propagate the
   legacy term into the merged view.

## Expected Behavior

The three council persona prompts must describe Phase-A and Phase-B
council work against the v4.0.0 binding artifact name and shape.
Anchors:

- **Doctrine source.** CLAUDE.md "Migration history" entry dated
  2026-05-03 (v4.0.0) — "the legacy 'Acceptance Contract' artifact
  is renamed to 'Acceptance Criteria' and reshaped from
  BDD-scenarios-with-flat-sensor-list to **User Stories →
  Definition of Done → Acceptance Criteria → Sensor pool**".
- **Filesystem anchor.** `.yoke/acceptance-criteria/<slug>.md` is
  the only path the active flow reads; the helper
  `wm_acceptance_contract_path` was deleted in v4.0.0 and
  `wm_acceptance_criteria_path` is the sole resolver
  (`lib/working-memory/paths.sh`).
- **Reference vocabulary already in use elsewhere.**
  `docs/architecture.md` line 30 already authors the same Sr QA
  description correctly as "Authors **acceptance-criteria-anchored**
  tests …" — that wording is the in-tree reference for the
  persona-prose form.

Concretely:

- "Acceptance-Contract criterion(s)" → "Acceptance Criterion(s)"
  (the v4.0.0 shape uses per-AC identifiers `AC-<US>-<n>` or `FR-N`;
  the prose reads naturally as "next failing Acceptance Criterion").
- "acceptance-contract-anchored tests" → "acceptance-criteria-anchored
  tests" (matches `docs/architecture.md` line 30).
- "the binding Acceptance Contract" / "Acceptance Contract's criteria"
  → "the binding Acceptance Criteria document" / "Acceptance
  Criteria document's criteria".

## Observed Behavior

- `grep -nE 'acceptance-contract|Acceptance-Contract|Acceptance Contract' agents/sr-eng.md agents/sr-qa.md agents/sr-staff.md`
  prints 13 hits.
- Each Phase-A `/yoke:implement` cycle re-loads stale doctrine into
  the persona Task spawn; per-cycle slice files written under
  `.yoke/runtime/cycles/<N>/<persona>.md` re-introduce the legacy
  term in their natural-language summaries.
- `bash tests/smoke/orphan-acceptance-contract-refs.test.sh` exits
  non-zero today, but **none of its current "unaccounted matches"
  output cites any of the three persona files** — the gate is blind
  to the persona drift because the matches are filtered by the
  allowlist (`acceptance-contract-anchored` is allowlisted; the
  title-cased `Acceptance-Contract` / `Acceptance Contract` form is
  not matched at all by the case-sensitive pattern).

## Blast Radius

**One module — council-persona doctrine layer.** Three files in
`agents/` (`sr-eng.md`, `sr-qa.md`, `sr-staff.md`), all consumed by
`lib/runtime/persona-loader.sh` at Phase A. The change set is
uniformly textual prose in markdown bodies and YAML frontmatter
string values. No executable code path, no working-memory helper,
no sensor, and no template body is touched.

## Root-Cause Hypothesis

The v4.0.0 cutover sprint (PRD `2026-05-03-acceptance-criteria-refactor`)
migrated the skills, helpers, templates, and hooks but did not
visit the council persona prompts in `agents/`. The likely reason:
the `orphan-acceptance-contract-refs` smoke sensor's allowlist
explicitly retains `acceptance-contract-anchored` and `<contract-slug>`
as "intentional historical references" (see lines 17–25 of
`tests/smoke/orphan-acceptance-contract-refs.test.sh`), which let
the persona-file drift appear deliberate to anyone reading the gate.
Combined with the case-sensitive grep pattern (which never matches
the title-cased `Acceptance-Contract` form the personas actually
use), the persona prompts fell off the v4.0.0 sweep checklist.

## Functional Requirements

- **FR-1:** All occurrences of the substring `Acceptance-Contract`
  (title-cased, hyphenated) and `Acceptance Contract` (title-cased,
  space-separated, when the phrase refers to the binding artifact's
  *name*) inside `agents/sr-eng.md`, `agents/sr-qa.md`, and
  `agents/sr-staff.md` must be migrated to the v4.0.0 vocabulary.
  Specific renames:
  - "Acceptance-Contract criterion(s)" → "Acceptance Criterion(s)".
  - "the binding Acceptance Contract" → "the binding Acceptance
    Criteria document".
  - "Acceptance Contract's criteria" → "Acceptance Criteria
    document's criteria".
- **FR-2:** All occurrences of the substring
  `acceptance-contract-anchored` inside the three persona files must
  be migrated to `acceptance-criteria-anchored`. The wording must
  match `docs/architecture.md` line 30, which already uses
  "acceptance-criteria-anchored tests" as the in-tree reference.
- **FR-3:** Frontmatter scope. The YAML frontmatter `description:`
  and `objective:` keys of `agents/sr-eng.md` and `agents/sr-qa.md`
  must reflect FR-1 + FR-2. Other frontmatter keys (`name`,
  `tools`) remain untouched.
- **FR-4:** Anti-scope-block scope. The `## Anti-scope` section of
  `agents/sr-qa.md` and `agents/sr-staff.md` must reflect FR-1
  ("Never relax the binding Acceptance Criteria document"). The
  list shape and bullet count are preserved.
- **FR-5:** Body-prose scope. All `agents/sr-eng.md`, `sr-qa.md`,
  and `sr-staff.md` body sections (everything between the
  frontmatter close and the end-of-file) reflect FR-1 + FR-2 with
  no surviving title-cased `Acceptance-Contract` / `Acceptance
  Contract` substring referring to the binding artifact's *name*.
- **FR-6:** Test-dir parameter retention. The string literal
  `<contract-slug>` inside the path
  `tests/acceptance/<contract-slug>/` MUST be left untouched. This
  retention is anchored to the existing
  `orphan-acceptance-contract-refs` sensor allowlist (rationale #3
  and #4 in that script), which classifies the parameter name as a
  "v4.x follow-up" out of scope. Any change to this token is a
  separate fix outside this spec.
- **FR-7:** Verification. After the migration, executing
  `grep -nE 'acceptance-contract|Acceptance-Contract|Acceptance Contract' agents/sr-eng.md agents/sr-qa.md agents/sr-staff.md`
  must return zero matches.
- **FR-8:** Sensor stability. After the migration, executing
  `bash tests/smoke/orphan-acceptance-contract-refs.test.sh` must
  exit with the **same exit code as before the fix** (the sensor's
  current pre-existing failures are unrelated to this fix's scope —
  they originate from `skills/`, `lib/`, and `docs/` and are out of
  scope per Non-Goals). The fix must not introduce new unaccounted
  matches into the sensor's output.
- **FR-9:** Containment. The fix must not modify any file outside
  `agents/sr-eng.md`, `agents/sr-qa.md`, and `agents/sr-staff.md`.
  Specifically excluded: `docs/architecture.md`, `docs/migration-v3-to-v4.md`,
  the project `CLAUDE.md` "Migration history" block, any
  `.yoke/` archive, any canonical-memory entity, any sensor under
  `tests/smoke/` or `lib/sensors/`, and any helper under
  `lib/working-memory/` or `lib/runtime/`.

  with the prose sweep, but the existing sensor allowlist
  explicitly retains `<contract-slug>` as a v4.x follow-up
  (see `tests/smoke/orphan-acceptance-contract-refs.test.sh`
  rationale lines 22–25). Any change to this token belongs to a
  separate fix that first amends the allowlist policy.
- Touching `docs/architecture.md`. Line 30 already uses the
  migrated prose form ("acceptance-criteria-anchored tests"); the
  only legacy reference there is the `<contract-slug>` parameter
  name, which is excluded per FR-6.
- Hardening the `orphan-acceptance-contract-refs` smoke sensor to
  catch the title-cased `Acceptance-Contract` / `Acceptance
  Contract` form. The reporter cross-references this as "F10";
  sensor coverage is a separate fix that should land *after* the
  prose sweep so the new gate immediately turns green.
- Migrating the historical `.yoke/acceptance-contracts/` directory
  (no-historical-migration policy ratified at v4.0.0).
- Touching legacy decision-token strings in
  `lib/ralph-loop/escalate.sh`
  (`acceptance-contract-violation`, `reformulate-acceptance-contract`)
  — these are runtime category strings out of scope per the
  sensor allowlist's rationale block.
- Touching skill bodies (`skills/`) or canonical-memory entities —
  those have already migrated in v4.0.0 and the smoke sensor's
  separate hits in skill bodies are not part of this fix.
- Authoring or modifying any sensor (`lib/sensors/**`,
  `tests/sensors/**`).

## Risks

- **Frontmatter parse drift.** `agents/*.md` frontmatter is consumed
  by `lib/runtime/persona-loader.sh validate-all` at Phase A. The
  FR set rewrites string values inside `description:` and
  `objective:`. Signal: a YAML-parse error or a Phase-A spawn that
  fails because a multi-line description got reflowed. Mitigation:
  the rewrites are in-place token swaps (substring replacements
  inside existing single-line YAML values); no field is added,
  removed, or reflowed; `persona-loader.sh validate-all` runs as
  the existing pre-Phase-A gate and is sensitive to this signal.
- **Persona slice carry-over from in-flight tasks.** Existing
  per-cycle slice files at `.yoke/runtime/cycles/<N>/<persona>.md`
  written by tasks that were mid-flight at the time of the fix
  still embed the legacy vocabulary in their slice bodies. Signal:
  a `/yoke:canonize` run after the fix may surface mismatched
  terminology in the staged hand-off for those particular tasks.
  Mitigation: `.yoke/runtime/` is gitignored and is wiped on every
  new `/yoke:fix` / `/yoke:discover` invocation by
  `wm_wipe_runtime`; tasks already mid-flight at the time the
  prompts migrate will re-spawn personas with the migrated prompt
  on their next cycle, so the carry-over is bounded to slices
  written before the next cycle boundary.
- **Reader cognitive friction from `<contract-slug>` retention.**
  The fix migrates surrounding prose to "acceptance-criteria-anchored
  tests" while keeping the test-dir parameter literally as
  `<contract-slug>` (per FR-6). Signal: a future reader may infer
  the parameter name should also rename and open a duplicate fix.
  Mitigation: this fix-spec's Non-Goals block names the retention
  explicitly; the existing sensor allowlist remains the durable
  contract anchor for the retention policy.
