# PRD: resolve-provider.sh hardening against set -u

> Generated by `/yoke:discover` on 2026-05-03.
> Status: approved
> Approved by: iurykrieger
> Approved at: 2026-05-03T06:24:36Z

## Introduction / Overview

Yoke v2.0.0's pluggable canonical-memory facade routes every skill that
needs the active provider through `lib/canonical-memory/resolve-provider.sh`.
The helper is designed to be sourced. In practice, several dispatch
paths source it via `bash -c "..."` or via `eval` — both spawn a
subshell whose `BASH_SOURCE[0]` is unset. Combined with the
`set -uo pipefail` declared at the top of the same file (line 46),
dereferencing `${BASH_SOURCE[0]}` aborts with
`BASH_SOURCE[0]: parameter not set`, the helper bails out, and the
operator sees a misleading
`wm: providers.yaml missing from plugin root (.../Workspace/providers.yaml)`
diagnostic against a bogus path.

The error has been observed in three independent transcripts (council
worktree on 2026-05-02 at session line 1336; chat-test on 2026-05-03
line 839; chat-test on 2026-05-02 line 146). It blocks `/yoke:status`,
`/yoke:canonize`, `/yoke:ask`, and `/yoke:search-canonical-memory`
whenever a calling skill dispatches the helper through `bash -c`.
Today it is worked around by every skill prefixing its dispatch with
`cd $PLUGIN; bash -c '...'` — that workaround is implicit, undocumented,
and easy to forget. Filed upstream as issue
[#28](https://github.com/iurykrieger/claude-yoke/issues/28).

## Goals

- Replace the unsafe `${BASH_SOURCE[0]}` deref in `_yoke_provider_plugin_dir`
  with a `set -u`-safe form that has a deterministic fallback.
- Surface a precise, actionable error when neither `BASH_SOURCE[0]` nor
  `YOKE_PLUGIN_DIR` is available, so misconfigurations fail loud rather
  than path-mangle silently.
- Add a regression smoke test that reproduces the failure mode
  (`bash -c "set -u; source <plugin>/lib/canonical-memory/resolve-provider.sh; yoke_resolve_provider"`
  from outside the plugin root) and asserts a clean resolution.

## Product invariants

- The helper MUST remain compatible with `set -uo pipefail` (which it
  sets itself at line 46).
- The helper MUST keep working when sourced normally (the documented
  usage); the fix is additive — it does not break call paths that
  already work.
- `YOKE_PROVIDER_*` exit codes 0 / 3 / 4 / 5 (documented at the file
  head) MUST stay byte-equivalent for every input that succeeded
  before this PRD. Any new failure mode introduced by the fix MUST
  surface as exit 5 with a stderr-prefixed `wm: ` diagnostic.

## User Stories

### US-001: Skill author sources resolve-provider.sh under bash -c

**Description.** As a Yoke skill prompt author dispatching
`bash -c "set -u; source $PLUGIN/lib/canonical-memory/resolve-provider.sh; yoke_resolve_provider"`
from the user's project root, I want the helper to resolve the plugin
root deterministically (via `BASH_SOURCE[0]` when available, falling
back to `YOKE_PLUGIN_DIR` when not) so that the resolution succeeds
without me having to first `cd $PLUGIN`.

**Acceptance criteria:**
- [ ] Running the exact command above from a directory other than the
  plugin root resolves `YOKE_PROVIDER_NAME` from the host project's
  `.yoke/config.yaml` and exits 0.
- [ ] No `BASH_SOURCE[0]: parameter not set` text appears on stderr.
- [ ] When `YOKE_PLUGIN_DIR` is exported and points at the plugin path,
  the helper uses it without consulting `BASH_SOURCE[0]`.
- [ ] `shellcheck` runs clean on
  `lib/canonical-memory/resolve-provider.sh`.

### US-002: Helper aborts cleanly when neither path is available

**Description.** As a Yoke skill prompt author who accidentally invokes
the helper from a context where `BASH_SOURCE[0]` is unset and
`YOKE_PLUGIN_DIR` is not exported, I want the helper to abort with a
clear, actionable message naming both fallback variables so I can see
what to fix.

**Acceptance criteria:**
- [ ] Running
  `bash -c "set -u; unset YOKE_PLUGIN_DIR; source <full-path>/resolve-provider.sh; yoke_resolve_provider"`
  (where `BASH_SOURCE[0]` expands to the absolute path it was sourced
  as — the documented happy path) still succeeds.
- [ ] When the helper is invoked in a degenerate context where neither
  variable is set (synthetic test), the helper exits non-zero with a
  `wm: ` prefix message that names both variables.
- [ ] The error message names the next step (e.g. "export
  `YOKE_PLUGIN_DIR=<plugin path>` before sourcing").

### US-003: Regression smoke test pins the bug shut

**Description.** As a Yoke maintainer, I want a smoke test under
`tests/smoke/` that exercises the failing dispatch path from the three
transcripts so that any future regression trips CI.

**Acceptance criteria:**
- [ ] A new file `tests/smoke/resolve-provider-set-u-safety.test.sh`
  exercises
  `bash -c "set -u; source <plugin>/lib/canonical-memory/resolve-provider.sh; yoke_resolve_provider"`
  from outside the plugin root.
- [ ] The test exits 0 (passes) when the fix is in place.
- [ ] The test exits non-zero when applied against the pre-fix code
  (validated by manual revert during PR review).
- [ ] The test is wired into `.github/workflows/tests.yml`.

## Functional Requirements

- **FR-1:** `_yoke_provider_plugin_dir` MUST replace the bare
  `${BASH_SOURCE[0]}` reference at line 55 with the
  `${BASH_SOURCE[0]:-}` form (or equivalent), eliminating the
  `parameter not set` error under `set -u`.
- **FR-2:** `_yoke_provider_plugin_dir` MUST keep its existing
  fallback to `${YOKE_PLUGIN_DIR:-}` (lines 50–53) and use it when
  `BASH_SOURCE[0]` is empty.
- **FR-3:** When both `BASH_SOURCE[0]` and `YOKE_PLUGIN_DIR` are empty,
  `yoke_resolve_provider` MUST return non-zero with a stderr message
  prefixed `wm: ` that names both variables and directs the user to
  export `YOKE_PLUGIN_DIR`.
- **FR-4:** The four documented exit codes (0 / 3 / 4 / 5) MUST remain
  byte-equivalent for every call path that succeeded before this PRD.
- **FR-5:** `tests/smoke/resolve-provider-set-u-safety.test.sh` MUST
  exist, be executable, and reproduce the failing transcript dispatch
  — passing post-fix, failing pre-fix.
- **FR-6:** The CI matrix (`.github/workflows/tests.yml`) MUST include
  the new smoke test.

## Non-Goals (Out of Scope)

- **Refactoring `lib/yoke-prelude.sh`** to pass plugin paths via env
  vars instead of source-based discovery. Considered, deliberately
  deferred. No changes to the prelude beyond what FR-1..FR-3 require
  for compatibility.
- **Migrating skills to a single dispatch entry-point that avoids
  `bash -c` entirely.** Considered, deliberately deferred.
- **Auditing other helpers** in `lib/canonical-memory/`,
  `lib/working-memory/`, or `hooks/` for analogous `set -u`-unsafe
  `${BASH_SOURCE[0]}` derefs. Out of scope; a follow-up PRD if the
  next instance of this bug class shows up.
- **Documenting the `cd $PLUGIN; bash -c` workaround as a permanent
  calling contract.** This PRD eliminates the need for the workaround
  in the helper; documentation choices for surrounding skills are
  deferred.
- **Removing the legacy `lib/canonical-memory/resolve-memory.sh`
  references from `/yoke:status` and `/yoke:ask`** (issue #31).
  Distinct drift; tracked separately.

## Design Considerations

None. Pure shell-helper hardening; no user-facing surface.

## Technical Considerations

### Technical
- The file declares `set -uo pipefail` at line 46, so the fix MUST
  work under that mode — it cannot rely on relaxing `set -u`.
- `${BASH_SOURCE[0]:-}` is portable bash 4+; CI runs bash 4+ per
  `CLAUDE.md :: Linting`.
- The fallback fast-path on `YOKE_PLUGIN_DIR` (lines 50–53) is
  unchanged; the change is to the slow-path that derives the plugin
  root from `BASH_SOURCE`.

### Regulatory
- None.

### Organizational
- None.

## Risks

- **Silent path-mangling under unforeseen sourcing context** — the
  helper could resolve to a wrong plugin root and the resulting
  `providers.yaml missing` error misleads the operator. Signal: any
  user-reported `wm: providers.yaml missing from plugin root` whose
  path does NOT contain `claude-yoke`. Mitigation: FR-3's actionable
  error names `YOKE_PLUGIN_DIR` so the operator can correct without
  guessing.
- **Regression test passes pre-fix** (false sense of security) — the
  test must reproduce the exact failure the transcripts showed.
  Signal: applying the test against the unfixed
  `_yoke_provider_plugin_dir` at `HEAD~1` must fail. Mitigation: the
  acceptance criterion explicitly requires this manual verification
  during PR review.

## Success Metrics

- Zero new occurrences of `BASH_SOURCE[0]: parameter not set` in
  transcripts collected after the fix lands (sample: next 10 sessions
  using `/yoke:status`, `/yoke:canonize`, `/yoke:ask`, or
  `/yoke:search-canonical-memory`).
- Regression test passes in CI on every PR.
- Skill prompts that currently rely on the implicit
  `cd $PLUGIN; bash -c '...'` workaround for `resolve-provider.sh` may
  drop the `cd` prefix without regressing (verifiable by `grep` across
  `skills/*/SKILL.md` post-fix; optional surface for this PRD).
