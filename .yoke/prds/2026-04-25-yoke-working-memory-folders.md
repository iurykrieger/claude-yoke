# PRD: Per-category folders for `.yoke/` working memory

> Generated by `/yoke:discover` on 2026-04-25.
> Status: approved
> Approved by: iury.krieger@stone.com.br
> Approved at: 2026-04-25

## Product invariants

What must hold regardless of implementation. Non-negotiable.

- **Working memory is organized by category, not by task.** `.yoke/` contains category folders (`prds/`, `tech-specs/`, `acceptance-contracts/`, `contracts/`, `query-traces/`, `runtime/`); each archive category holds one file per task, named `<YYYY-MM-DD>-<slug>.md`. There is no per-task umbrella folder.
- **One archive file per task per category.** A task named `2026-05-01-todolist-feature` has at most one PRD (`.yoke/prds/2026-05-01-todolist-feature.md`), one tech spec, one acceptance contract, one contracts file, and one query-trace. The slug `<YYYY-MM-DD>-<slug>` is the join key across categories.
- **Archive categories are committed to git; runtime state is not.** `prds/`, `tech-specs/`, `acceptance-contracts/`, `contracts/`, `query-traces/` are versioned by the host project. `runtime/` and the active-task pointer are gitignored.
- **The active task is tracked by a per-worktree pointer.** `.yoke/.current` is a plain-text file containing exactly the slug of the active task. Gitignored, so each git worktree carries its own active task independently. Downstream skills resolve "which file to read/write" by reading `.current` and constructing `.yoke/<category>/<slug>.md`.
- **Lazy category creation.** Each category folder is created the first time a skill writes a file of that category. `/yoke:bootstrap` creates only `.yoke/config.yaml` and `.yoke/.gitignore`; it does not pre-create any category folder.
- **Every `/yoke:discover` invocation starts a new task.** No "continue active task" branch. The new task gets a new slug and `.current` is overwritten. Old archive files remain on disk (and in git history) untouched.
- **Project-wide state stays at `.yoke/` root.** Specifically: `config.yaml` (versioned), `.gitignore` (versioned), `.current` (gitignored).
- **No automatic cleanup.** Past tasks' archive files persist indefinitely. Out-of-scope for this PRD.
- **No migration logic.** v1.0 has no production users; v0.6 makes a clean break against the flat layout.

## Business context

Today every Yoke implementation overwrites the previous one's `prd.md`, `tech-spec.md`, `acceptance-contract.md`, and `contracts.md`. As soon as the next feature kicks off `/yoke:discover`, the historical record of *why* the previous feature was built, *what was promised* in the binding contract, and *what was learned* during the runtime ralph loop is gone.

This breaks two of Yoke's load-bearing values. First, the manifesto's traceability invariant — "every canonical-memory write must be traceable to a past failure or hard constraint" — depends on having those past failures recorded. Without per-task archives, the working-memory tier (where those failures originate) only retains the most recent task. Second, `/yoke:drift-sense` is already specified to read historical artifacts "from completed tasks" (plural; see `skills/drift-sense/SKILL.md:54`) — but the current flat layout makes "completed tasks" a singleton, silently degrading drift sensing.

The category-folder shape (rather than per-task folders) was chosen to optimize for cross-task reading: drift-sense can `glob .yoke/contracts/*.md` directly, a future `/yoke:learn` can scan all PRDs at once, and a contributor browsing `.yoke/prds/` sees every product question the team has ever framed. It also keeps the host-project's commit diff cleanly grouped (a feature ship touches `.yoke/prds/foo.md`, `.yoke/tech-specs/foo.md`, `.yoke/acceptance-contracts/foo.md`, `.yoke/contracts/foo.md` — four files, four categories, one slug).

v1.0.0 just shipped with zero adopters, which makes this the cleanest possible window to fix the layout before adoption locks it in. Doing this in v0.6 (i.e., before the first user-visible release after 1.0.0) costs almost nothing; doing it later costs a migration path, deprecation warnings, and a long tail of mixed-layout host projects.

## Layout (target end-state)

```
.yoke/
├── config.yaml                       # versioned — project-wide configuration
├── .gitignore                        # versioned — declares what's ignored inside .yoke/
├── .current                          # gitignored — one line: the active task slug
├── prds/                             # versioned
│   └── 2026-05-01-todolist-feature.md
├── tech-specs/                       # versioned
│   └── 2026-05-01-todolist-feature.md
├── acceptance-contracts/             # versioned
│   └── 2026-05-01-todolist-feature.md
├── contracts/                        # versioned
│   └── 2026-05-01-todolist-feature.md
├── query-traces/                     # versioned — full /yoke:ask history per task
│   └── 2026-05-01-todolist-feature.md
└── runtime/                          # gitignored — current task only
    ├── progress.md
    ├── .cycle-counter
    ├── .trigger4-packet.yaml
    └── .snapshots/
        ├── cycle-1.yaml
        └── cycle-2.yaml
```

```
runtime/
```

## Known constraints

What the implementation must respect, grouped by source.

### Technical
- **Path references are spread across every skill.** A `grep` against `skills/`, `lib/`, and `hooks/` shows 16+ hard-coded `.yoke/<file>.md` references across `bootstrap`, `discover`, `tech-spec`, `acceptance-contract`, `implement`, `canonize`, `drift-sense`, `ask`, and `status`. The implementation must update each one and centralize resolution in a single helper (proposed: `lib/working-memory/paths.sh`) so future skills cannot re-introduce hard-coded paths.
- **Bash 4+ target unchanged.** No new runtime dependencies introduced.
- **Slug is the only identifier.** `<YYYY-MM-DD>-<slug>` regex `^[0-9]{4}-[0-9]{2}-[0-9]{2}-[a-z0-9][a-z0-9-]{0,49}$`. Date is local time at task creation; immutable once set.
- **Runtime state is single-tenant per worktree.** `.yoke/runtime/` holds the current task's runtime files only. New `/yoke:discover` clears `runtime/` before starting (or refuses if runtime appears mid-cycle — see Risks).
- **`.current` semantics.** Plain text, exactly one line, no trailing newline ambiguity (skills must trim whitespace on read). Absent `.current` = no active task; downstream skills abort with "no active task; run `/yoke:discover` first."
- **Worktree-friendly by construction.** Because `.current` and `runtime/` are gitignored, each git worktree gets independent active-task state without any per-worktree config. Two worktrees can run `/yoke:discover`, `/yoke:tech-spec`, `/yoke:implement` for different features simultaneously without colliding. Archive files (committed) propagate via git as usual.

### Regulatory
- None. Internal tooling layout; no regulated data flows are affected.

### Organizational
- Maintainer is solo (iurykrieger); no contributor coordination needed.
- This change should land in a single sprint (proposed v0.6) so the surface-area refactor is atomic — partial migration (some skills on flat, some on category folders) would silently corrupt working memory.

## Risks

### Skill refactor incompleteness
Every skill writes to `.yoke/<file>.md` directly today. If a skill is missed during the refactor, it writes to `.yoke/prd.md` (root) instead of `.yoke/prds/<slug>.md` — silent corruption of working memory.

Signal: a skill produces an artifact at the wrong path; downstream skills can't find it.

Mitigation: a single resolution helper (`lib/working-memory/paths.sh`) that all skills `source` and use; a smoke test (`tests/smoke/folder-isolation.test.sh`) that asserts no skill writes flat files like `.yoke/prd.md`, `.yoke/tech-spec.md`, etc.

### Query-trace write cadence
`query-trace.md` is now a fifth versioned category at `.yoke/query-traces/<slug>.md`, written directly (no `runtime/` staging). Every `/yoke:ask` invocation appends a YAML entry to this file, which means every query produces a working-tree change in the host project's git index.

Signal: noisy `git status` during active discovery/spec phases; many small commits if the host commits per-query.

Mitigation: this is a host-project commit-cadence concern, not a Yoke correctness issue. The file is append-only YAML; users can batch-commit `query-traces/` at task closeout (or per phase), or commit per-query if they want fine-grained traceability. `/yoke:status` may surface uncommitted query-traces as an informational hint (out of scope for this PRD — flag for a future refinement).

### Slug collision
Two `/yoke:discover` runs on the same day with the same slug produce identical filenames. Signal: `/yoke:discover` would silently overwrite an in-flight or archived PRD.

Mitigation: when the Generator-proposed `<YYYY-MM-DD>-<slug>` collides with any existing file in any category, the Generator regenerates the slug with the same semantic intent but different wording (e.g., `auth-flow` → `auth-pipeline` → `signin-handler`) until uniqueness is achieved, then surfaces the chosen slug to the user for confirmation. No deterministic numeric suffixes — slugs stay readable.

### Slug timing within `/yoke:discover`
The slug is part of every archive filename. The slug derives from the PRD title, but the title is only finalized after the discovery dialogue. Resolution: the Generator proposes a slug *at the moment the first file is written* (i.e., when drafting `prd.md`), and `.current` is set then. Before that point, an interrupted dialogue leaves zero on-disk trace. Acceptable: the dialogue itself is short (1–5 rounds) and fully recoverable from the user's last few messages.

### Stale `.current` after worktree removal or branch switch
A worktree can be removed (`git worktree remove`) while `.current` points at a task whose archives haven't been committed yet. Those archive files vanish with the worktree.

Signal: archive files referenced by past `.current` values don't exist on disk anywhere in git history.

Mitigation: `/yoke:discover` writes archives directly into the working tree (committed by the user as a normal git workflow). `/yoke:status` warns when `.current`'s slug has no corresponding archive file in any category.

### Runtime collision from interrupted task
If a previous task's runtime state (`.yoke/runtime/`) wasn't cleared before a new `/yoke:discover` runs (e.g., crash, kill -9), the new task starts with stale `progress.md` / `.cycle-counter` / `.snapshots/`.

Signal: cycle counter starts above 0; snapshots reference a different slug.

Mitigation: `/yoke:discover` always wipes `.yoke/runtime/` after confirming the new task is being created (after slug ratification), then writes the new `.current`. Hooks that rely on cycle counters re-initialize on missing files.

### `lib/canonical-memory/query.sh --trace` path is hardcoded
`/yoke:ask` invokes `lib/canonical-memory/query.sh --trace .yoke/query-trace.md`. The new helper must construct the active versioned trace path (`.yoke/query-traces/<slug>.md`, where `<slug>` comes from `.current`) before the call.

Mitigation: every callsite goes through `lib/working-memory/paths.sh::query_trace_path` (or equivalent), which resolves `.current` and returns the versioned path.

## Open questions

All questions resolved at PRD approval. Recorded here for traceability.

- **OQ-1 (resolved).** `/yoke:status` reports only the active task by default; `--all` flag lists every archived task across categories.
- **OQ-2 (resolved).** No automatic cleanup of past tasks. Out of scope; user manages manually with normal filesystem/git tools.
- **OQ-3 (resolved).** `query-trace.md` is promoted to a versioned fifth archive category at `.yoke/query-traces/<slug>.md`. Every `/yoke:ask` writes directly to the versioned path. Drift-sense reads the full history via `glob .yoke/query-traces/*.md`. Commit cadence is the host project's choice.
- **OQ-4 (resolved).** On slug collision the Generator regenerates the slug with the same semantic intent but different wording (`auth-flow` → `auth-pipeline` → `signin-handler`), iterating until uniqueness is achieved and surfacing the result for user confirmation. No numeric suffixes.
- **OQ-5 (resolved).** `/yoke:bootstrap` writes `.yoke/.gitignore` containing `.current` and `runtime/`. Host projects do not need to touch their root `.gitignore`.
