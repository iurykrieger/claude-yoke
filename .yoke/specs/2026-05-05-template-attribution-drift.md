## Context and Scope

became false at the Phase-2.5 cutover (commit `358dea2`, "split Phase
2.5 sprint synthesis from tech-spec"):

- `templates/sprint.md` — opening blockquote (lines 14–16) and
  closing trailer (lines 116–117) name `/yoke:tech-spec` (stage 3) as
  the producer and Trigger 2 as the ratifying gate. The real producer
  is `/yoke:generate-sprints`; the real gate is Trigger 2.5. The
  legacy-flow carve-out at lines 89–90 is intentionally retained — it
  is a historical statement about pre-cutover sprint files.
- `templates/task.md` — opening blockquote (lines 13–15) and the
  line-23 aside repeat the same false attribution. The file has zero
  product-code references; tasks are aggregated inline as `### Task
  <ID>` subsections inside sprint files per `templates/sprint.md`'s
  `## Tasks` section.

Scope of this spec:

- Edit `templates/sprint.md` opening blockquote and closing trailer
  to cite the correct producer (`/yoke:generate-sprints`) and trigger
  (Trigger 2.5).
- Delete `templates/task.md` after a pre-deletion search broader than
  `skills/`, `lib/`, `hooks/`, `agents/`, `tests/`, `docs/`,
  `CLAUDE.md`, and `README.md` (must additionally cover `.github/`,
  `.claude-plugin/`, plugin manifests, and any GitHub workflow file)
  confirms zero non-historical references.
- Add a new structural sensor at
  `lib/sensors/template-metadata-fidelity.sh` (with self-test at
  `tests/sensors/template-metadata-fidelity.test.sh`) that pins the
  producer / trigger lines of producer-owned templates against the
  skill file that owns the producer.

Out of scope: behavior changes, edits to skills / lib / hooks /
agents, edits to historical artifacts under
`.yoke/acceptance-contracts/`, edits to the legacy-flow carve-out at
`templates/sprint.md` lines 89–90.

Producer-owned templates are templates whose lifecycle is governed by
a producer skill — today, the only producer-owned template is

## Architecture

**Structural pure-bash sensor mirroring
`lib/sensors/no-vibeflow-refs.sh`.** Cite
[[yoke-pattern-sensors]] (computational sensor, structured output,
silent success) and
[[yoke-decision-2026-04-27-bidirectional-invariant-sensor-pattern]]
(pure-bash structural grep-and-assert with three test shapes).

The sensor is computational (deterministic) — no LLM, no external
dependencies beyond bash 4+ and standard text utilities. It encodes
an allowlist of producer-owned templates as bash arrays:

```bash
TEMPLATES=("templates/sprint.md")
PRODUCERS=("skills/generate-sprints/SKILL.md")
TRIGGERS=("Trigger 2.5")
```

For each `(template, producer, trigger)` triple, the sensor:

1. Verifies `templates/<template>` exists and `skills/<producer>/SKILL.md`
   exists (boundary check — surfaces a stale allowlist entry as a
   distinct violation class from a drift violation).
2. Asserts the template's opening blockquote (the first
   blockquote-paragraph after the H1) cites the producer's
   `/yoke:<skill-name>` slash command and the trigger's name.
3. Asserts the template's closing trailer (last blockquote in the
   file) cites the same.
4. Carves out **historical** statements: lines matching
   `legacy-flow|pre-cutover|legacy producer` are skipped (this
   preserves the carve-out at `templates/sprint.md` lines 89–90).

**Invariants the architecture guarantees:**

- Silent success: sensor exits 0 with empty stdout / stderr when all
  triples conform.
- Structured violation on failure: each violation emits an `id`,
  `location` (file path + line range), `correction_instruction`, and
  `reference: [[yoke-pattern-sensors]]` per
  [[yoke-pattern-sensors]] structured-output convention.
- Exit code: 0 on success; non-zero on any violation.
- Self-reference paradox handling: when the sensor itself contains
  example wording (e.g., the literal `Trigger 2 approves` string in a
  comment block), the search excludes the sensor's own basename and
  the self-test path, mirroring the `no-vibeflow-refs.sh` precedent
  at lines 36–37.

**Failure modes explicitly NOT handled:**

- Semantic drift inside the template body (e.g., the description of
  what a sprint is) — only producer/trigger attribution is pinned.
- Drift in non-producer-owned templates — out of scope by allowlist.
- Drift introduced by a producer rename that updates the skill file
  but not the allowlist; the boundary check (step 1) surfaces this
  as a `stale-allowlist` violation.

**Invocation site:** the sensor is exercised by its self-test under
`tests/sensors/`; CI runs the test suite on every PR
(`.github/workflows/tests.yml`). No hook integration in this fix —
hook wiring is a future concern (Open Question Q1).

## APIs and Data Model

**Sensor invocation contract:**

```
bash lib/sensors/template-metadata-fidelity.sh
  → exit 0 (silent) on success
  → exit 1 with structured stderr on any violation
```

No flags; no environment variables. The sensor is invoked directly
in the test harness and from CI via the test that wraps it.

**Violation output schema** (per
[[yoke-pattern-sensors]] structured-output convention; YAML on
stderr, one block per violation):

```yaml
- id: template-metadata-fidelity:<template>:<violation-class>
  location: <relative-path>:<line-range>
  correction_instruction: <one-line actionable fix>
  reference: "[[yoke-pattern-sensors]]"
```

Violation classes encoded by the sensor:

- `producer-mismatch` — the cited producer does not match the
  allowlist's producer for this template.
- `trigger-mismatch` — the cited trigger does not match the
  allowlist's trigger.
- `producer-skill-missing` — the allowlist names a
  `skills/<producer>/SKILL.md` that does not exist on disk
  (stale-allowlist signal).
- `template-missing` — the allowlist names a `templates/<file>`
  that does not exist on disk (stale-allowlist signal; mutually
  exclusive with the previous class).
- `legacy-string-leaked` — the literal `Trigger 2 approves`
  appears outside a `legacy-flow|pre-cutover|legacy producer`
  carve-out paragraph.

**Self-test contract** (positive / negative / reverse-fixture
subcases):

- **Positive subcase:** point the sensor at the real `templates/`
  tree post-fix; expect exit 0 with empty stderr.
- **Negative subcase:** copy `templates/sprint.md` into a tmpdir,
  re-introduce the false attribution, point the sensor at the tmpdir
  (via an internal `--templates-dir` argument or temporary working
  directory swap), expect exit 1 with the expected violation YAML on
  stderr.
- **Reverse-fixture subcase:** add a synthetic producer-owned
  template (`templates/__test_producer_owned.md`) and a synthetic
  producer skill (`skills/__test_producer/SKILL.md`) under a tmpdir,
  extend the allowlist, expect exit 0 — verifies that the allowlist
  is the only edit needed to onboard a future producer-owned
  template.

## Non-Functional Requirements

- **Latency:** sensor execution time p95 ≤ 100ms on the current
  `templates/` tree (15 files, ≤ 1 producer-owned), measured via
  `time` in the self-test's positive subcase.
- **Disk footprint:** sensor source ≤ 0.01MB; self-test source ≤
  0.02MB. Combined contribution of this fix to the repo: ≤ 0.03MB.
- **LLM dispatch cost:** 0ms LLM wall-clock per sensor invocation —
  the sensor is pure bash, no LLM call participates in the
  hot path.
- **Throughput:** sensor sustains ≥ 500 rps when allowlist size is
  ≤ 50 templates (derived from the 100ms latency budget at 50
  templates per invocation; headroom for future producer-owned
  templates).
- **Test coverage:** 100% of producer-owned templates currently
  enumerated in the allowlist are exercised by the positive
  subcase; 100% of declared violation classes (5 classes) are
  exercised by the negative subcase.

## Alternatives Considered

### Alt: LLM-based inferential sensor (semantic-judge style)

**Trade-off vs. chosen:** would catch semantic drift inside the
template body (not just producer/trigger lines), at the cost of
calibration metadata, per-run token cost, and false-positive /
-negative rates that drift with model upgrades.
**Reason for rejection:** the invariant is structural, not semantic
— a literal `/yoke:<producer>` slash command and a literal trigger
name. Pure-bash structural grep is deterministic and reproducible;
the umbrella pattern explicitly says "Computational sensors are
preferred over inferential ones. Promote inferential to
computational whenever a deterministic encoding becomes possible."
**Source:** `[[yoke-pattern-sensors]]` (Rules section).

### Alt: post-hoc check inside `/yoke:canonize` (or `/bedrock:compress`)

**Trade-off vs. chosen:** lower per-PR cost (sensor doesn't run on
every PR, only at canonize time), at the cost of detection
latency — drift would survive in the templates until the next
canonization run, with the audit trail attributing the regression
to the wrong cycle.
**Reason for rejection:** the bidirectional-invariant sensor
pattern explicitly rejects post-hoc detection: "Catching this drift
via `/yoke:compress` (post-hoc alignment) is too late: the PR has
already merged into canonical memory, and the audit trail attributes
the degradation to the wrong cycle." Eager detection at CI time is
the cheapest signal.
**Source:** `[[yoke-decision-2026-04-27-bidirectional-invariant-sensor-pattern]]` (Why section).

### Alt: single-line `grep` assertion inline in `.github/workflows/tests.yml`

**Trade-off vs. chosen:** zero new files (sensor logic lives inline
in CI YAML), at the cost of no self-test, no per-cycle observability
through `.yoke/sensors/<id>.md`, no readiness-mode integration with
`lib/sensors/ack-sensors.sh`, and no portability to non-GitHub CI.
**Reason for rejection:** Yoke's sensor convention requires
first-class persistent artifacts. The umbrella pattern's
"Implementation Mapping" section names `lib/sensors/<id>.sh` +
`tests/sensors/<id>.test.sh` as the persistent surface; inline CI
assertions are not discoverable by `ack-sensors.sh` and cannot
participate in the council's per-cycle sensor selection.
**Source:** `[[yoke-pattern-sensors]]` (Implementation Mapping
section).

### Alt: `templates/task.md` retained with corrected attribution

**Trade-off vs. chosen:** preserves a (potentially) discoverable
template file, at the cost of carrying dead code and an additional
allowlist entry in the new sensor.
**Reason for rejection:** the fix-spec FR-4 commits to deletion
after the broader pre-deletion search; tasks are aggregated inline
inside sprint files per `templates/sprint.md` `## Tasks` section,
and zero non-historical references to `templates/task.md` exist
under product directories. The deletion is reversible (git history
preserves the file) if the search uncovers an unexpected reference.
**Source:** `internal experience` (the broader pre-deletion search
in `## Technical Use Cases :: ### FR-4` is the load-bearing check).

## Trade-offs

- **Bash-only constrains expressiveness.** The sensor cannot judge
  semantic correctness of template bodies — only the structural
  match of producer / trigger lines. Accepted; semantic checks are
  out of scope by [[yoke-pattern-sensors]] preference.
- **Allowlist requires manual extension on producer changes.** When
  a future template gets a producer skill, the allowlist must be
  extended. The boundary checks (`producer-skill-missing`,
  `template-missing`) catch the inverse — a stale entry — but a
  *missing* entry slips through silently. Mitigation surfaced as
  Open Question Q2.
- **Adds ≤ 100ms to the test suite.** CI test runtime grows by the
  sensor's positive subcase. Acceptable per the bidirectional-
  invariant sensor pattern's tradeoff section ("<100ms on the
  100-entity dogfood substrate").
- **Carve-out wording is fragile.** The sensor uses
  `legacy-flow|pre-cutover|legacy producer` as the carve-out
  regex. A future contributor who introduces historical commentary
  with different wording could trip the `legacy-string-leaked`
  violation. Documented in the sensor's header comment; the
  negative-subcase test pins the carve-out's expected wording.

## Cross-cutting Concerns

- **Observability:** sensor emits structured YAML to stderr on
  failure (per [[yoke-pattern-sensors]]). The self-test produces a
  pass/fail line on stdout. No additional logging surfaces.
- **Security:** n/a — sensor reads files inside the repository, no
  network egress, no secrets, no privileged operations. Threat
  model matches the existing `no-vibeflow-refs.sh` shape.
- **Error handling:** `set -euo pipefail` at the top of the sensor;
  stale-allowlist conditions exit non-zero with a distinct
  violation class (the user can distinguish "sensor is wrong" from
  "templates are wrong" from the violation `id`).
- **i18n / a11y:** n/a — internal tooling; sensor and self-test
  emit only English.

**Edge cases:** the edit must NOT remove the second-paragraph aside

### FR-2 — `templates/sprint.md` closing trailer rewrite

**Components involved:** `templates/sprint.md` (lines 116–117 only).
**Contracts used:** sensor's `producer-mismatch` and

**NFRs applied:** sensor latency budget — both header and trailer

**Edge cases:** the trailer wording MUST match the opening

### FR-3 — Legacy-flow carve-out preserved

**Components involved:** `templates/sprint.md` lines 89–90 (the
US-trace clause's exception for pre-cutover sprint files).
**Contracts used:** sensor's `legacy-flow|pre-cutover|legacy
producer` carve-out regex MUST match the carve-out's surrounding

`legacy-string-leaked`.
**NFRs applied:** test coverage NFR — the negative-subcase test
includes a fixture that drifts the opening blockquote *while
keeping the carve-out intact* and asserts that exactly one
violation is reported (not two).
**Edge cases:** if the carve-out paragraph is reflowed during the
fix (line numbers shift), the sensor's region detection must be
regex-based (not line-based) so the carve-out continues to
register. The implementation MUST use regex region detection.

### FR-4 — `templates/task.md` deletion

**Components involved:** `templates/task.md` (deleted),
`.github/`, `.claude-plugin/`, plugin manifests, GitHub workflow
files, any other non-product directory the broader pre-deletion
search uncovers.
**Contracts used:** none — file deletion. Pre-deletion search uses

**NFRs applied:** none directly. Sensor's `template-missing`
