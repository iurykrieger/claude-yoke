## Overall objective

Decouple sprint generation from `/yoke:tech-spec` and from the
acceptance-criteria artifact, by introducing a new
`/yoke:generate-sprints` skill that synthesizes sprint runtime bundles
from the post-rename `(spec, acceptance-criteria)` pair. After this
work, the producer order is fixed: tech-spec carries only architecture
and decisions, acceptance-criteria carries only use cases (`UC-<n>`)
with their DoD / criteria / FRs / sensors, and `/yoke:generate-sprints`
is the single producer of `.yoke/sprints/<slug>-s<NN>.md` runtime
bundles. The new flow is `/yoke:discover` → `/yoke:tech-spec` →
`/yoke:acceptance-criteria` → `/yoke:generate-sprints` →
`/yoke:implement`. Legacy tasks (sprint files emitted by the legacy
`/yoke:tech-spec` stage 3) keep walking under `/yoke:implement`
unchanged; no automatic migration is performed.

The work is partitioned into four sprints. Sprint 1 lays the
template + AC-skill foundation. Sprint 2 builds the
`/yoke:generate-sprints` skill skeleton and the synthesis-input
contract. Sprint 3 ships the synthesis stage, the partition stage,
the bundle render stage, and the Trigger 2.5 approval gate. Sprint 4
performs the cutover — stripping sprint generation from
`/yoke:tech-spec`, wiring `/yoke:implement` and `/yoke:status` to the
new gate state, codifying legacy coexistence, shipping the full-flow
smoke test, and updating `docs/architecture.md`, `docs/lineage.md`,
and the canonize handoff packet.

## Sprints

Each sprint has a delivery objective (what is shippable at the end)
and is rendered as a self-contained **sprint runtime bundle** at
`.yoke/sprints/<slug>-s<NN>.md`. The sprint file is the cycle's
working set during `/yoke:implement` (one ralph cycle = one sprint
file as the working set, per `concepts/yoke-pattern-sprint-runtime-bundle`).

## Contracts and interfaces

- **`templates/acceptance-criteria.md` shape** — Each use case is a
  `### UC-<n>` heading with five sub-fields:
  - **Name:** one-line use-case name.
  - **Definition of done:** bullet list of binary, observable
    outcomes that must hold for the UC to be considered done.
  - **Acceptance criteria:** bullet list of binary, observable checks
    sensors / tests can decide.
  - **Functional requirements realized:** list of `FR-N` IDs from the
    PRD that this UC realizes.
  - **Sensors:** list of sensor IDs from `.yoke/sensors/` that gate
    this UC. Tests path: `tests/smoke/acceptance-criteria-shape.test.sh`.
  No task IDs anywhere in the artifact (verifiable by `grep -E
  '<slug>-s[0-9]+-t[0-9]+'` returning zero matches).

- **`/yoke:generate-sprints` invocation contract** — Resolves the
  active slug via `wm_active_slug` (no positional argument needed,
  matching `/yoke:tech-spec` and `/yoke:acceptance-criteria`).
  Internally derives the input paths via `wm_spec_path` and the new
  `wm_acceptance_criteria_path` helper. Pre-flight aborts non-zero
  with `wm:`-prefixed stderr on any of: missing config / missing
  provider, missing active slug, missing or unapproved spec, missing
  or unapproved acceptance-criteria.

- **`.yoke/runtime/.generate-sprints-plan.yaml` schema** — Gitignored
  intermediate. Top-level keys:
  ```yaml
  slug: <slug>
  generated_at: <iso8601>
  tasks:
    - task_id: <slug>-s<NN>-t<MM>
      realizes_ucs: [UC-1, UC-3]
      applies_decisions: ["<spec-section-anchor>", ...]
      instructions: |
        <unified instruction block — single block readable by
         Sr Eng, Sr QA, Sr Staff; no per-persona forks>
      sensors: [<sensor-id>, ...]
      acceptance_criterion: <one binary observable check>
  sprint_partition:
    - sprint_id: <slug>-s<NN>
      delivery_objective: <one paragraph>
      dod: [<binary check>, ...]
      task_ids: [<slug>-s<NN>-t01, <slug>-s<NN>-t02, ...]
  ```
  The plan is the contract between the synthesis stage and the render
  stage. A future revision could re-render bundles deterministically
  from the same plan.

- **Sprint-file UC-trace clause** — Each `### Task <ID>` subsection
  carries a `(Realizes: UC-N[, UC-M])` clause **adjacent to the
  `**Story:**` line** — same line, parenthesized. Example:
  `**Story:** As a Yoke user, I want X. (Realizes: UC-2, UC-5)`.
  Verifiable by a sensor that greps each task heading in a sprint
  file and asserts the realize clause is present and non-empty.

- **Sprint-file traceability frontmatter** — The `traceability:`
  field cites both `.yoke/specs/<slug>.md` and
  `.yoke/acceptance-criteria/<slug>.md`, semicolon-separated:
  `traceability: ".yoke/specs/<slug>.md; .yoke/acceptance-criteria/<slug>.md"`.

- **Flow-detection contract for `/yoke:implement` and `/yoke:status`**
  — Presence of `.yoke/acceptance-criteria/<slug>.md` indicates new
  flow (gate state cycles through `awaiting:tech-spec` →
  `awaiting:acceptance-criteria` → `awaiting:generate-sprints` →
  `running:implement` → `done`). Absence indicates legacy flow (gate
  state cycles through the legacy machine: `awaiting:tech-spec` →
  `awaiting:acceptance-contract` → `running:implement` → `done`). The
  detection rule is a single `test -f` check; it does not parse file
  contents.

- **Approval-menu wiring for Trigger 2.5** — `/yoke:generate-sprints`
  reuses `templates/approval-menu.md` with `artifact_label: "Sprint
  plan"`, `next_skill: /yoke:implement`, empty `binding_statement`
  (Trigger 2.5 ratifies the *partition*, not the *criteria*), and a
  custom `sprint_summary` block listing each produced sprint id with
  its delivery objective. On `approve` / `approve_and_continue`, the
  skill flips `status: draft` → `status: approved` in every produced
  sprint file's frontmatter atomically.

- **`wm_acceptance_criteria_path` helper** — New helper added to
  `lib/working-memory/paths.sh` resolving to
  `.yoke/acceptance-criteria/<slug>.md`. Mirrors `wm_spec_path` and
  `wm_prd_path`. The legacy `wm_acceptance_contract_path` is removed
  by the rename PR (out-of-scope here).

## Out of scope

- **Renaming `/yoke:acceptance-contract` → `/yoke:acceptance-criteria`**
  and the directory `.yoke/acceptance-contracts/` →
  `.yoke/acceptance-criteria/`. Tracked separately; presumed merged
  before Sprint 1 starts.
- **Migrating already-approved legacy tasks.** Decision 6A in the
  Discovery dialogue: legacy tasks remain as-is; no automatic
  migration; re-running `/yoke:generate-sprints` against a legacy
  task is a no-op rejection.
- **Council-protocol changes.** The bundle shape consumed by Phase A
  / Phase B / Phase C is unchanged; this work modifies only the
  producer side.
- **Per-persona sub-blocks inside a task.** Decision 5A: instructions
  are unified for Sr Eng / Sr QA / Sr Staff.
- **LLM-driven sprint-count estimation.** The partition stage is
  deterministic given the task list; if the user disagrees with the
  partition, they iterate via the `revise` verb of the approval
  menu.
- **A new sensor for sprint-bundle drift.** Existing invariants are
  sufficient.
- **Backporting the new flow into v3.0.0.** This work targets v3.1.0
  (or v4.0.0 if the rename PR triggers a major bump independently).
