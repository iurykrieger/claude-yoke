## Overall objective

Realign Yoke's sensor model with the harness-engineering frame (Fowler) by promoting sensors to a durable, project-level catalog with a hard `type: computational | inferential` discriminator, dual-channel cost (`token_cost`, `time_cost`), a curated body acting as knowledge base (not execution log), inferential dispatch via subagent (Task tool) with prompt + rubric + verdict-schema living in `## Calibration`, sensor-to-criterion binding moved into the Acceptance Contract as a per-criterion `### Validation` sub-section, and a new `/yoke:consolidate-sensors` skill that distills runtime evidence back into sensor files (append-only body + cost recalibration) at the end of each `/yoke:implement`. The 45 existing sensor files are triaged in a big-bang migration: roughly 15-20 generic harness-level sensors are kept as catalog members, ~25-30 doctrine-canonization one-shots are deleted. Delivered as one atomic release split into three sprints — each sprint is a coherent shippable unit (one ralph cycle = one sprint) and the three sprints together form the merge-ready state.

## Sprints

Each sprint has a delivery objective (what is shippable at the end) and is rendered as a self-contained sprint runtime bundle at `.yoke/sprints/<slug>-s<NN>.md`. The sprint file is the cycle's working set during `/yoke:implement` (one ralph cycle = one sprint file as the working set, per the 2026-04-27 sprint-as-cycle PRD).

### Sprint 1 — Schema, parser, lint, audit infrastructure
**Delivery objective:** the new sensor-file schema (frontmatter `type` / `token_cost` / `time_cost` / `command`-or-`agent`; body `## How to run` / `## Known issues` / `## Frequent errors` / `## Calibration` for inferential) is ratified in `templates/sensor.md`; `templates/acceptance-contract.md` carries the per-criterion `### Validation` sub-section; `lib/sensors/ack-sensors.sh` parser, body lint and upsert mode accept only the new schema; `lib/sensors/migration-audit.sh` produces a triage-ready report mapping the 45 existing sensors to `still-referenced` vs `orphan-candidate-for-delete`. Runtime hooks and agents are not yet touched — this sprint ends with an internally consistent set of templates and tooling, but `hooks/verify-acceptance.sh` and the catalog files remain on the legacy schema.

**Tasks:** see `.yoke/sprints/2026-04-30-sensor-harness-realignment-s01.md` `## Tasks` section.

### Sprint 2 — Runtime refactor and consolidate skill
**Delivery objective:** `hooks/verify-acceptance.sh` resolves sensor metadata from the per-sensor file, parses the per-criterion `### Validation` block from the contract, supports `--max-time-cost` / `--max-token-cost` filters in place of the removed `--tier` flag, and dispatches computational sensors via shell and inferential sensors via Task subagent spawn; `agents/validator.md` becomes a pure plan enforcer with no embedded scheduling heuristic; `agents/semantic-judge.md` becomes an instance of the new shape with the verdict envelope extended to carry `confidence` and `supporting_quotes`; the new `/yoke:consolidate-sensors` skill is implemented (no args, append-only body with citation, token_cost / time_cost recalibration, idempotent reentry); `skills/implement/SKILL.md` invokes the consolidation skill at teardown; `.yoke/config.yaml` template carries the `sensor_consolidation: review | auto | skip` key (default `review`). ## Contracts and interfaces

- **Sensor file frontmatter (new schema)** — YAML, mandatory:
  ```yaml
  id: <kebab-case-id>
  type: computational | inferential
  token_cost: <int>            # >= 0; typically 0 for computational
  time_cost: <int>              # estimated wall-clock seconds; >= 1
  command: <shell command>     # required iff type: computational
  agent: <subagent-id>         # required iff type: inferential
  ```
  Schema validated by `ack-sensors.sh` parser; legacy fields (`class`, `tier`, `applies_to`, `runs`) are rejected.

- **Sensor file body shape** — markdown sections, mandatory presence:
  - `## How to run` — any type, non-empty.
  - `## Known issues` — any type, non-empty.
  - `## Frequent errors` — any type, non-empty, bullets `- <pattern>: <fix>`.
  - `## Calibration` — only for `type: inferential`, with sub-sections `### Prompt`, `### Rubric`, `### Verdict schema`.

- **Acceptance Contract per-criterion validation block** — markdown, under each `### Criterion <id>`:
  ```markdown
  ### Validation
  - **<sensor-id>** — <interpretation guidance for this criterion>
  - **<sensor-id>** — <...>
  ```

- **Verdict schema (inferential sensors)** — JSON envelope:
  ```json
  {
    "criterion": "<criterion-id>",
    "sensor": "<sensor-id>",
    "status": "pass" | "fail",
    "location": "<file:line>" | null,
    "fix_instruction": "<text>" | null,
    "evidence": "<text>",
    "confidence": 0.0,
    "supporting_quotes": ["<quote>", "..."]
  }
  ```
  `confidence` is a float in `[0, 1]`, validated by the parser. `supporting_quotes` is a list of strings; minimum 1 entry when `status: fail`; empty list permitted when `status: pass`. Invalid verdict equals sensor fail.

- **`hooks/verify-acceptance.sh` flags (updated)**:
  - `--criterion <id>` (existing, retained).
  - `--max-time-cost <int>` (new) — filters sensors with `time_cost <= N`.
  - `--max-token-cost <int>` (new) — filters sensors with `token_cost <= N`.
  - Combined via AND when both passed.
  - `--tier cheap|expensive|all` is removed in the same atomic PR.

- **`/yoke:consolidate-sensors` skill contract**:
  - Arguments: none.
  - Inputs: reads `.yoke/runtime/.current` for the active slug; reads `.yoke/runtime/.judge-verdicts/`, `progress.md` and any other evidence persisted by the loop.
  - Outputs (writes): for each sensor involved in the active task:
    - Body: append-only into `## Known issues` / `## Frequent errors` / (inferential) `## Calibration`. Each appended bullet cites evidence: `(cycle N, fix-instruction X)`.
    - Frontmatter: recomputes `token_cost` and `time_cost` (simple mean over runs of the current implement; updates only if delta > 5%).
  - Reentrance: idempotent — citation already present in the body causes the bullet to be skipped; cost only updates on > 5% delta.
  - Diff-review: governed by `.yoke/config.yaml` key `sensor_consolidation: review | auto | skip` (default `review`). In `review`, the user sees the diff and confirms before write.

- **`agents/semantic-judge.md` shape post-refactor**: stays as the subagent definition (Claude Code agent file). Gains a sensor-file equivalent at `templates/sensors/semantic-judge.md` (or similar) with `type: inferential`, `agent: semantic-judge`, prompt / rubric / verdict-schema in `## Calibration`. Dispatch flows through the per-sensor file; the agent file is the "how it implements" and the sensor file is the "how to invoke and interpret".

- **`.yoke/config.yaml` additions**:
  ```yaml
  sensor_consolidation: review   # review | auto | skip
  ```

## Out of scope

- Post-merge sensors (GitHub Actions checks, webhooks, coverage gates) — the v0 shape must allow them as a future addition via optional frontmatter fields without a refactor; v0 itself does not implement them.
- Cross-project catalog — promoting sensors to the plugin (`<plugin_dir>/sensors/`) is explicitly deferred; sensors stay under the project.
- Auto-update of cost — there is no automated helper that adjusts `token_cost` / `time_cost` from telemetry; adjustment happens via `/yoke:consolidate-sensors` at the end of `/yoke:implement` or via manual edits.
- Promotion of sensor knowledge to canonical memory — sensor files stay in working memory; calibration does not become doctrine.
- Schema versioning — there is no `schema_version` field; we assume a single schema.
- Concurrent edit handling — there is no protection for simultaneous human edits during consolidation; the default `review` mode lets the human see the diff.
- Drift sensing over the catalog — the fifth Yoke phase (drift sensing) will cover orphan sensors in the future; v0 does not detect them.
- Modification of any manifesto invariant — shift-feedback-left, hard bounds, structured sensor output, etc. are preserved.
