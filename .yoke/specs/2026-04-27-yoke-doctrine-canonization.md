## Overall objective

Move every artifact under `.vibeflow/` to its proper destination —
doctrine (patterns, decisions, conventions, audits) into the
`iurykrieger/brain` canonical-memory vault under
`tags: [yoke-framework]`; project history (specs, PRDs) into the
working-memory archives `.yoke/specs/` and `.yoke/prds/` with
date-prefixed slugs; rewrite every framework file (`skills/`,
`agents/`, `hooks/`, `lib/`, `templates/`) to drop `.vibeflow/`
references in favor of `/yoke:ask` invocations and working-memory
paths; install a validation sensor that fails on any future
`.vibeflow/` reference; delete `.vibeflow/` as the final step.
The PRD's "Yoke building Yoke" dogfood signal is met if every
phase of this Spec executes through Yoke's own flow without
falling back to manual `.vibeflow/` edits.

## Contracts and interfaces

The shapes downstream phases (Phase 3 acceptance contract,
Phase 4 implement loop, Phase 5 canonization) and reusable artifacts
must respect.

- **Yoke-doctrine entity frontmatter** — every `concepts/yoke-*.md`
  and `discussions/yoke-audit-*.md` written into `iurykrieger/brain`
  carries the locked frontmatter from the PRD (`kind`, `tags`,
  `ratified`, `last_validated`, `traceability`, `status`, `project`).
  Schema: literal block in PRD §"Frontmatter contract for every
  Yoke-doctrine entity". Tests: a per-task validation step that
  re-reads the entity and asserts every required key is present
  with a non-empty value. Phase 3 BDD scenarios encode this as the
  Then clause for each migration task.
- **Slug-derivation function for `.yoke/specs/` and `.yoke/prds/`
  migration** — pure-bash function that takes a `.vibeflow/`
  filename and emits a `wm_validate_slug`-compliant slug. Inputs:
  the source path (used by `git log --diff-filter=A --follow
  --format=%cs -- <path>` to fetch the first-commit ISO date) and
  the original filename stem. Output: `<YYYY-MM-DD>-<stem>` truncated
  per the long-name rule (sprint 3 task 2 specifies). Tests:
  fixture-driven per-input expected-slug pairs; on collision after
  truncation, fail loud (do not auto-disambiguate).
- **Framework-surface validation sensor** — bash sensor invocable
  via `lib/sensors/no-vibeflow-refs.sh` (final path in sprint 5).
  Greps the framework surface (`skills/`, `agents/`, `hooks/`,
  `lib/`, `templates/`) for the literal string `.vibeflow/`. Exits
  non-zero with file:line:context output if any match; exits 0
  otherwise. Tests: a self-test fixture under `tests/sensors/` that
  asserts both the failure case (when a sample file with `.vibeflow/`
  is added) and the success case (when no matches exist).
- **`/yoke:teach` invocation pattern** — per-artifact ingestion
  call. The Generator builds a target-shape spec (kind, tags,
  destination path) and calls `/yoke:teach` with the source `.vibeflow/`
  path. The skill ingests, frontmatters, and writes into the registered
  vault checkout. The PR back to `iurykrieger/brain` is opened by the
  canonical-memory PR helper, not by individual task code.
- **`/yoke:ask` round-trip validation interface** — per-entity
  smoke check. After each entity is written, the validation step
  invokes `/yoke:ask` with a query that should hit the new entity
  (e.g., for `concepts/yoke-pattern-roles.md`, query "what is the
  Yoke role pattern?"). The check passes if the response cites the
  entity by name or contains a substring lifted from the entity body.
- **Backlinks index in `projects/claude-yoke.md`** — the project
  entity carries a backlinks list that every doctrine entity
  appends itself to during migration. Schema: a `## Doctrine
  entities` section with a flat bullet list. Tests: after sprint 2
  completes, the count of bullets equals (9 patterns + N decisions
  + 1 conventions + N audits).

## Dependencies

### External services and libraries
- **`gh` CLI ≥ 2.40** — used for canonical-memory PR creation by
  the `/yoke:preserve` skill and for vault-checkout sync. Already
  required by `/yoke:bootstrap`.
- **`git` ≥ 2.30** — `git mv` preserves history during sprint 3's
  spec/PRD migration; `git log --diff-filter=A --follow --format=%cs`
  is the slug-date source.
- **`python3`** — required by `lib/canonical-memory/registry.sh` for
  safe JSON rewrites. Already a hard dependency.

### Internal prior work
- **`/yoke:teach` skill** — the only ingestion path into canonical
  memory. Sprint-1 task 3 and sprint-2 tasks all invoke it. If
  `/yoke:teach` does not handle a particular `.vibeflow/`-shaped
  artifact gracefully, treat the failure as input to a Yoke fix
  (per the PRD's "recursive failure of dogfood" risk) — do not
  fork or patch `/yoke:teach` inside this Spec.
- **`/yoke:ask` skill** — the only retrieval path. Round-trip
  validation depends on it returning live results from the
  registered checkout at `iury-brain`.
- **`/yoke:preserve` skill** — the governed write surface. NOT used
  for the bulk migration itself (that goes through `/yoke:teach`),
  but used in sprint 5 to canonize any new doctrine that emerges
  from the migration (e.g., refined entity-naming rules).
- **`lib/working-memory/paths.sh`** — every `.yoke/` path constructs
  through these helpers. Sprint 3 may need a new helper if the
  long-name truncation rule needs centralizing — that decision lives
  in sprint-3 task 2.
- **`lib/canonical-memory/registry.sh`** — provides `path-of` /
  `default-name` lookup that resolves `iury-brain`'s checkout
  location. Already wired by `/yoke:bootstrap`; no changes here.
- **`bedrock:teach` upstream** — `/yoke:teach`'s parent. Out of scope
  per the PRD; if a vault behavior is wrong, file it upstream rather
  than patching here.

### Cross-team coordination
- **None.** The PRD names a single maintainer; no other teams are
  in the loop. Model C ratification simplifies to "maintainer
  approves the canonization PR" for every class.

## Out of scope

- **Generic `.vibeflow → Bedrock` migration framework.** This Spec
  builds throwaway shell glue around `/yoke:teach`. A reusable
  multi-vault converter is anti-scope.
- **Splitting `.vibeflow/conventions.md` into per-rule entities.**
  Sprint 2 migrates the doc as a single `concepts/yoke-conventions.md`
  policy entity. Per-rule splitting is a deferred follow-up if
  individual rules ever need to be queryable.
- **Changes to `bedrock:*` skills.** Yoke wraps Bedrock; this Spec
  does not modify the wrapped skills.
- **Renaming `iury-brain` to a Yoke-specific name.** The vault stays
  registered as today; namespacing is via frontmatter tag.
- **Per-rule splitting of `.vibeflow/index.md`.** Its content folds
  into `CLAUDE.md` updates (sprint 4 task 4) and `projects/claude-yoke.md`
  (sprint 1 task 2); no standalone migration entity.
- **Authoring new patterns or decisions during the migration.** The
  Spec ports what exists; it does not invent. New doctrine that
  emerges from the migration itself (e.g., naming refinements) is
  canonized via `/yoke:preserve` post-implement, not folded into
  the migration body.
- **Backfilling doctrine for pre-`.vibeflow/` Yoke history.** The
  initial bootstrap predates `.vibeflow/`; reconstructing that
  history is a separate effort.
- **Updating downstream Yoke users' projects.** Other repos using
  Yoke are unaffected by this Spec — their `.yoke/` and canonical
  memory are independent.
