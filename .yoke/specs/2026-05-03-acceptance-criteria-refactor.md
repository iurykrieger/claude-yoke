## Overall objective

Cut over Yoke's Phase 3 from the legacy "Acceptance Contract" artifact
to a renamed, restructured **Acceptance Criteria** artifact authored
through an interactive QA grill. The cutover is a breaking change
(plugin v4.0.0): the directory `.yoke/acceptance-criteria/`, the skill
`/yoke:acceptance-criteria`, the template
`templates/acceptance-criteria.md`, and the path helper
`wm_acceptance_criteria_path` replace their `acceptance-contract(s)`
counterparts; the legacy helpers and references are deleted, not
delegated. The artifact's shape pivots from "BDD scenarios anchored to
task IDs with a flat sensor list" to "User Stories → Definition of
Done → Acceptance Criteria → Sensor pool", mirroring standard QA
discipline. The skill that produces it becomes interactive in the same
shape as `/yoke:discover` and `/yoke:tech-spec`: it resumes the PRD +
Tech Spec back to the user (≤ 25 lines), then drives a 1–5 round
lettered-options grill scoped to base quality gates (US enumeration,
DoD per US, AC per US, sensor pool, cross-cutting FRs) before
materializing the artifact and rendering the Trigger 3 approval menu.
Council persona prompts (`agents/sr-qa.md`, `agents/sr-staff.md`) and
`lib/runtime/{cycle,council}.sh` are updated to read the new shape and
pick pool sensors at validation time; canonical-memory doctrine for
the Phase 3 pattern is superseded; docs and CLAUDE.md files reflect
the new flow. Files under `.yoke/acceptance-contracts/` are not
migrated — Yoke is in active development and the cutover is clean.

## Sprints

Each sprint has a delivery objective (what is shippable at the end)
and is rendered as a self-contained **sprint runtime bundle** at
`.yoke/sprints/<slug>-s<NN>.md`. The sprint file is the cycle's
working set during `/yoke:implement`.

`.yoke/acceptance-criteria/<slug>.md` with the Trigger 3 binding

with `next_skill = /yoke:implement`. Quick-Round fast-track is

## Contracts and interfaces

- **`wm_acceptance_criteria_path` (path helper)** — bash function in
  `lib/working-memory/paths.sh`. Signature: `wm_acceptance_criteria_path
  <slug>` → `.yoke/acceptance-criteria/<slug>.md`. Returns non-zero
  if `<slug>` fails the existing `wm_validate_slug` regex. Replaces
  the legacy `wm_acceptance_contract_path` (which is deleted in the
  same sprint). Tests: `tests/unit/working-memory-paths.test.sh`.
- **`/yoke:acceptance-criteria` (skill verb)** — invocable through
  the Skill tool with no positional arguments. Reads
  `.yoke/runtime/.current` for the active slug; aborts if PRD or Tech
  Spec is missing/unapproved. Output: filled artifact at
  `.yoke/acceptance-criteria/<slug>.md` plus rendered Trigger 3 menu.
  Schema: see `templates/acceptance-criteria.md` after Sprint 2.
- **Acceptance Criteria document schema** —
  ```
  # Acceptance Criteria — <task name>
  > PRD: <path>
  > Tech Spec: <path>
  > Status: <draft | ratified>
  > Ratified by: <user>
  > Ratified at: <iso8601>
  > Binding statement (Trigger 3): …

  ## User Stories
  ### US-001 — <title>
  As a <role>, I want <capability>, so that <benefit>.
  #### Definition of Done
  - [ ] <binary item>
  #### Acceptance Criteria
  - **AC-001-1:** <observable QA condition>
  - **AC-001-2:** <…>

  ## Functional Requirements
  - **FR-1:** …

  ## Sensor pool
  - <sensor-id>
  - <sensor-id>

  ## Open Questions
  - <…> | None.
  ```
  Parsed by Sr QA / Sr Staff at runtime; FRs and Sensor pool are
  flat. AC entries carry no inline sensor IDs.
- **Council persona slice schema (extended)** — `.yoke/runtime/cycles/<N>/sr-qa.md`
  gains a `## Sensor selection` section listing per-AC the sensors run
  this cycle, with one-line rationale. `agents/sr-qa.md` prompt enforces
  this shape; the per-cycle deterministic merge (`council-merge.sh`) is
  unchanged.

## Dependencies

### External services and libraries
- None. The refactor is internal to Yoke's bash + markdown surface.

### Internal prior work
- `lib/working-memory/paths.sh` — central indirection for working-
  memory paths; touched in Sprint 1.
- `templates/approval-menu.md` — shared 4-option menu shape; consumed
  in Sprint 3's Trigger 3 rendering.
- `templates/sprint.md` and `templates/spec.md` — referenced; not
  modified by this refactor.
- `lib/runtime/{cycle,council}.sh`, `lib/runtime/persona-loader.sh` —
  read the artifact path at runtime; touched in Sprint 4.
- `concepts/yoke-pattern-acceptance-contract` (canonical memory) —
  superseded by a new `concepts/yoke-pattern-acceptance-criteria`
  entity at canonization time (post-merge, via Model C cascade).

### Cross-team coordination
- Solo maintainer (`iury-krieger`); no cross-team coordination
  required. The host-project CLAUDE.md template change in Sprint 5
  affects downstream host-project bootstraps; users must re-bootstrap
  to pick up the new template (documented in
  `docs/migration-v3-to-v4.md`).

## Out of scope

- Migrating the 17 historical files under
  `.yoke/acceptance-contracts/`. They remain frozen.
- Changing the Phase 4 council protocol (Phase A / B / C, sync
  barrier, contradiction-detection arbiter machinery). Only the
  artifact shape changes; the cycle machinery stays as-is.
- Modifying sprint contracts (`.yoke/contracts/<slug>.md`) shape or
  semantics. They keep their name and behavior.
- Promoting any new MUST policy into canonical memory inside this
  task. Doctrine updates ride a separate canonization PR (Model C
  cascade) at task termination.
- Introducing a sensor classification taxonomy at authoring time
  (mandatory / complementary / etc.). The runtime council decides
  per-criterion which pool members apply.
- Modifying `templates/spec.md`, `skills/tech-spec/SKILL.md`, or
  `templates/sprint.md`. The Tech Spec stays as-is.
- Building any kind of legacy-shim or deprecation-warning mode. The
  cutover is hard.
