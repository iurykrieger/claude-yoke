## Overall objective

Extend the existing `/yoke:preserve` canonization cascade to recognise
sprint contracts whose `topic:` recurs across ≥ 2 prior task archives,
score them through the existing five-criterion filter, and promote
qualifying contracts into the canonical memory's `concepts/` folder as
ordinary concept entities — tagged `yoke-framework` for provenance and
bidirectionally linked to the host project's actor in `actors/`. The
deterministic threshold floor (exact-string match on `topic:`) is
computed before any LLM call; the existing LLM step inside
`/yoke:preserve` is extended with a semantic-overlap pass to recognise
topic-equivalent contracts whose prose differs. A new computational
sensor asserts the bidirectional-link invariant after every promotion.
No template change to `.yoke/contracts/<slug>.md`; no parallel doctrine
layer; pruning of stale promoted concepts remains the responsibility of
`/yoke:compress`.

## Sprints

Each sprint has a delivery objective (what is shippable at the end)
and an ordered task list. Each task is rendered as a one-line story
anchored on a stable task ID. The full technical implementation and
validation for each task lives in `.yoke/tasks/<task-id>.md` —
**this file carries no inline task body**.

Task ID shape: `<slug>-s<NN>-t<MM>`, where `<slug>` matches the
existing working-memory slug regex (`<YYYY-MM-DD>-<kebab-slug>`),
`<NN>` is the sprint number zero-padded to 2 digits, and `<MM>` is
the task number within the sprint zero-padded to 2 digits. Padding
is what makes lexical sort = positional order in
`wm_list_task_paths`.

### Sprint 1 — Promote recurring sprint contracts via the existing cascade
**Delivery objective:** A loop-termination invocation of
`/yoke:preserve --from-orchestrator` against a working memory that
contains a sprint contract whose `topic:` matches another contract in
a prior `.yoke/contracts/<*>.md` archive results in (a) a candidate
entry emitted by `lib/canonical-memory/canonization-criteria.sh`, (b)
a concept entity drafted at `concepts/<llm-summarized-slug>.md` with
the mandatory rippability frontmatter, the `yoke-framework` tag, an
`applies_to:` entry naming the host-project actor, and a bidirectional
backlink in the actor's body, (c) a passing run of the new
`lib/sensors/contract-promotion-bidirectional.sh` sensor against the
post-write state, and (d) a Model-C-routed PR against the canonical
substrate. Negative path: a single-occurrence contract produces zero
candidates and writes nothing.

## Contracts and interfaces

API shapes, data models, integration contracts. Include schemas,
endpoints, message formats, and any contract tests that should be
generated for the Acceptance Contract (Phase 3).

- **Cascade input enumeration contract** — extension of
  `lib/canonical-memory/canonization-criteria.sh`. New CLI behaviour:
  in addition to the active task's `<working-memory>/contracts.md`
  file (or the per-task `.yoke/contracts/<slug>.md` of the active
  slug), the script enumerates every `.yoke/contracts/*.md` archive
  in the host project's working memory, parses each contract block's
  `topic:` field, and tracks an occurrence count per exact `topic:`
  string across archives. Existing CLI flags and YAML output schema
  are preserved verbatim. New informational field per candidate:
  `occurrences: <int>` (the cross-archive count). Schema test: the
  YAML emitted by the script matches today's golden output for the
  single-archive case (no regression); a fixture with two archives
  containing the same `topic:` string emits a candidate with
  `occurrences: 2`.

- **Cascade scoring contract — semantic-overlap layer** — extension
  to `/yoke:preserve` Phase 3.2 (the existing LLM step inside the
  cascade). When the deterministic floor (exact-string `topic:`
  match) returns a candidate group with `occurrences ≥ 2`, the LLM
  step refines repeatability scoring by examining whether the
  grouped contracts genuinely resolve the same ambiguity (vs. a
  superficial prose collision). The semantic-overlap layer never
  *creates* candidates the deterministic floor did not admit and
  never *coalesces* contracts whose `decision:` fields contradict
  (the existing `non-contradiction` criterion already enforces
  this; the overlap layer simply respects it). Output schema is
  unchanged; the LLM judgment is captured in the candidate's
  existing `reason:` field.

- **Promoted-concept entity schema** — every promoted concept
  written under `concepts/` carries:
  - `type: concept`
  - `name: "<kebab-summarized-from-topic>"`
  - `aliases: ["<original topic prose>"]` (full topic preserved)
  - `description: "<one-line LLM summary>"`
  - `status: "active"`
  - `ratified: <YYYY-MM-DD>` (canonization date)
  - `model_calibrated_against: "<model id>"` (mandatory rippability)
  - `last_validated: <YYYY-MM-DD>` (mandatory rippability)
  - `traceability: "<list of source contract paths>"` (mandatory)
  - `impact_level: low | medium | high`
  - `tags: [type/concept, kind/contract, yoke-framework,
    status/active, domain/<host-domain>]`
  - `applies_to: [<host-actor-name>]` (graph edge, mandatory)
  - `depends_on: []`, `supersedes: []`, `contradicts_with: []`
  - `project: "<host-project-slug>"`

  Body sections (markdown): `# <title>`, a leading blockquote
  capturing the agreed interpretation verbatim, `## Description` (the
  LLM-expanded rationale), `## Originating contracts` (a bullet list
  of source `.yoke/contracts/<slug>.md` references with cycle
  numbers), `## Where it applies`, `## Related`.

- **Bidirectional-link contract** — for every promoted concept, the
  named host-project actor entity under `actors/<host-name>.md`
  gains an entry in its `## Recent Activity` body section pointing
  back to the new concept via a bare wikilink `[[<concept-name>]]`.
  The actor's frontmatter is not modified (no list-style backlink
  field is required by the canonical-memory schema; the body section
  is the canonical reverse-edge surface, matching how `[[sprint-contracts]]`
  already lists its instances under "Recent Activity"). On first
  promotion against an actor that does not yet exist, `/yoke:preserve`
  creates the actor entity from the canonical actor template under
  Model C — exactly as it would for any other first-time actor write.

- **Bidirectional-link sensor contract** —
  `lib/sensors/contract-promotion-bidirectional.sh`. A computational
  sensor invoked by `hooks/verify-acceptance.sh` and the
  `/yoke:ack-sensors` readiness flow. Input: the canonical-memory
  path (resolved via `lib/canonical-memory/resolve-memory.sh`).
  Behaviour: for every concept under `concepts/` whose `tags:`
  contains `yoke-framework` AND `kind/contract`, assert that for
  every actor name in `applies_to:`, the file
  `actors/<actor-name>.md` contains a wikilink `[[<concept-name>]]`
  in its body. For every wikilink in any actor's body that resolves
  to a `kind/contract`-tagged concept, assert the concept's
  `applies_to:` contains the actor name. Output is the standard
  structured-output shape (violation identification, location,
  correction instruction, reference) per [[yoke-pattern-sensors]].
  Pass: `exit 0` with empty violation list. Fail: non-zero exit with
  one structured violation per missing edge, naming the offending
  file and the missing wikilink.

## Out of scope

What this Spec does NOT cover. Prevents scope creep during runtime.

- Redefining the sprint-contract template, semantics, or per-task
  archive layout. The runtime contracts artifact is unchanged.
- Phase-3 surfacing of past contracts at acceptance-contract authoring
  time. That is a separate PRD (Option B in the discovery dialogue).
- A utilization tracker for promoted concepts. Pruning is delegated to
  `/yoke:compress`.
- Auto-supersession of a promoted concept on hard contradiction. The
  cascade's `non-contradiction` criterion escalates such cases to
  human ratification per Trigger 5.
- Drift-time re-validation of stale promoted concepts. Out of scope
  for this PRD; lives in `/yoke:drift-sense`'s remit.
- A new entity subtype (`concepts/yoke-contract-*`). Promoted contracts
  share the `concept` schema with every other concept entity; the
  `kind/contract` tag is the discriminator.
