## Context and Scope

Two sensor scripts under `lib/sensors/` were authored before the
v2.0.0 facade extraction and still source canonical-memory helpers
that have been moved into the `claude-bedrock` peer plugin:
`lib/sensors/yoke-doctrine-round-trip.sh:43` calls
`lib/canonical-memory/registry.sh path-of iury-brain` (silenced via
`2>/dev/null`); `lib/sensors/contract-promotion-bidirectional.sh:70`
sources `lib/canonical-memory/resolve-memory.sh`. Both scripts are
removed; the only surviving file under `lib/canonical-memory/` is
`resolve-provider.sh`. As a consequence, both sensors exit 2 with an
infrastructure diagnostic — the framework's CI / smoke harness
treats exit 2 as "environmental skip", so the breakage never surfaces
as a drift verdict. `tests/sensors/yoke-doctrine-round-trip.test.sh`
documents the broken contract in its header and "passes" because its
case (4) negative-path fixture stubs the missing `registry.sh` and
asserts the exit-2 diagnostic.

This spec changes (i) `lib/sensors/yoke-doctrine-round-trip.sh`,
(ii) `lib/sensors/contract-promotion-bidirectional.sh`,
(iii) `tests/sensors/yoke-doctrine-round-trip.test.sh`, and adds a
new regression sensor `lib/sensors/no-canonical-memory-direct-refs.sh`
+ its self-test. It does NOT modify `lib/canonical-memory/resolve-provider.sh`,
the active provider plugin, the host-project sensor catalog under
`.yoke/sensors/<id>.md`, the `claude-bedrock` peer plugin's substrate
implementation, or any file under `.yoke/acceptance-contracts/historical/**`
(preserved on disk per the no-historical-migration policy ratified
2026-05-03).

## Goals and Non-Goals

**Goals**

- Zero references to any path under `lib/canonical-memory/` from any
  script in `lib/sensors/*.sh` other than `lib/canonical-memory/resolve-provider.sh`.
- Every surviving sensor under `lib/sensors/*.sh` either exits 0 / 1
  with a structured drift verdict, or does not exist on disk; exit 2
  from a missing-substrate-script path is removed from the sensor
  surface.
- A new computational regression sensor — pure-bash, deterministic,
  zero LLM tokens — that fails the build when any future
  `lib/sensors/*.sh` file references a removed canonical-memory
  helper, closing the coverage gap that produced this fix.
- Test workflow remains green; deletions of sensor scripts pair 1:1
  with deletions of their self-tests in the same change.

**Non-Goals**

- Re-introducing `lib/canonical-memory/registry.sh` or
  `resolve-memory.sh` as Yoke-side helpers. They live in the active
  provider plugin (`claude-bedrock`) per the v2.0.0 namespace
  separation.
- Rewriting either broken sensor to dispatch through
  `/yoke:search-canonical-memory`. The query-shaped facade does not
  expose substrate-direct filesystem traversal by design; rewriting
  would require a new facade verb that the fix-spec anti-scope
  explicitly forbids.
- Migrating any file under `.yoke/acceptance-contracts/historical/**`.
  Historical contracts are preserved on disk untouched.
- Modifying the host-project sensor catalog shape under
  `.yoke/sensors/<id>.md`.
- Replacing the existing `lib/sensors/no-vibeflow-refs.sh` sensor.
  The new regression sensor is its sibling, scoped to
  `lib/canonical-memory/` references rather than `vibeflow/`
  references.

## System Context

The sensor surface sits between three actors and one data store:

```
council personas (Sr QA / Sr Staff)  ─┐
CI test workflow (.github/workflows)  ├──> bash lib/sensors/*.sh ──> structured YAML / exit code
ack-sensors readiness check           ─┘            │
                                                   reads
                                                    ▼
                                        lib/sensors/*.sh source tree
                                        (deterministic textual scan)
```

No actor reads canonical memory through the sensors after this
change — the regression sensor is a pure source-tree scan; the two
broken sensors are removed from the path. The sensor I/O contract
(silent-success / structured-YAML-violations) is governed by
`concepts/yoke-pattern-sensors`. The structural-pure-bash shape is
governed by `concepts/yoke-decision-2026-04-27-bidirectional-invariant-sensor-pattern`,
whose canonical implementation is `lib/sensors/no-vibeflow-refs.sh`
(the reference structural sensor inside this repo).

## Architecture

Chosen architecture: **structural pure-bash sensor — single deterministic
textual scan, no canonical-memory dependency**. Mirrors the shape
ratified in `concepts/yoke-decision-2026-04-27-bidirectional-invariant-sensor-pattern`:
pure bash 4+, no Python, no Node, no LLM, output convention =
silent on success / structured-YAML violation block per
`concepts/yoke-pattern-sensors` on failure (`id`, `location`,
`correction_instruction`, `reference`), exit 0 / non-zero binary.

Per-sensor decision (option a vs b from the fix-spec):

- **`yoke-doctrine-round-trip.sh` → option (a) DELETE.** No active
  acceptance-criteria document under `.yoke/acceptance-criteria/**`
  references the sensor id; the only references live under
  `.yoke/acceptance-contracts/historical/2026-04-27-yoke-doctrine-canonization.md`
  (historical, preserved by policy) and the legacy sprint snapshot
  `.yoke/sprints/2026-04-30-pluggable-canonical-memory-s02.md` (also
  historical). The round-trip invariant the sensor encoded —
  "every migrated entity class is retrievable by both filename and
  content substring" — is now a property of the active provider's
  substrate (`claude-bedrock`); equivalent coverage belongs to that
  plugin's test surface, not to Yoke's sensor pool.
- **`contract-promotion-bidirectional.sh` → option (a) DELETE.**
  Same coverage rationale: the bidirectional invariant between
  `kind/contract` concepts and their `applies_to` actors is a
  canonical-memory-substrate property; no active
  acceptance-criteria document references the sensor id.
  References live only in
  `.yoke/acceptance-contracts/historical/2026-04-27-sprint-contract-promotion.md`,
  `.yoke/contracts/2026-04-27-sprint-contract-promotion.md`
  (historical sprint contract, preserved), and
  `.yoke/sprints/2026-04-30-pluggable-canonical-memory-s02.md`
  (historical). The pattern doctrine
  (`yoke-decision-2026-04-27-bidirectional-invariant-sensor-pattern`)
  remains canonized in Bedrock; the sensor *implementation* moves
  to the provider plugin, not back into Yoke.
- **`no-canonical-memory-direct-refs.sh` (NEW) → ADD.** Single
  computational sensor mirroring the structural-grep shape of
  `lib/sensors/no-vibeflow-refs.sh`. Iterates `lib/sensors/*.sh`,
  greps each file for path patterns matching
  `lib/canonical-memory/<X>` where `<X>` is anything other than
  `resolve-provider.sh`, plus path patterns matching the legacy
  helper basenames (`registry.sh`, `resolve-memory.sh`,
  `write-promoted-concept.sh`, etc. — the v2.0.0-extracted set).
  Emits a structured violation block per match. Self-success
  silent; non-zero exit on any violation. The sensor self-applies
  (its own body must not match the forbidden pattern).

Invariants the architecture guarantees:

- After this change, `grep -lE 'lib/canonical-memory/(?!resolve-provider\.sh)'`
  over `lib/sensors/*.sh` returns zero files.
- `bash lib/sensors/<surviving-sensor>.sh` exits 0 or 1 (not 2)
  for every surviving sensor under post-fix `lib/sensors/`.
- Reintroducing a forbidden reference in any future PR fails the
  test workflow with an actionable structured-YAML violation
  citing the file:line and the correction instruction.

Failure modes the architecture explicitly does not handle:

- Forbidden references that arrive via dynamic `eval` or
  variable indirection (`local lib="lib/canonical-memory"; "$lib/registry.sh"`).
  The textual scan is exact-substring, not symbolic. Acceptable —
  the canonized anti-pattern (`yoke-decision-2026-04-27-bidirectional-invariant-sensor-pattern`)
  rejects LLM-judged structural invariants on cost / reproducibility
  grounds.
- References from outside `lib/sensors/`. The FR-5 sensor is
  scoped to its sibling tree on purpose; broader coverage is the
  job of `lib/sensors/no-vibeflow-refs.sh`'s framework-clean
  counterpart, out of this fix's scope.

## Stack and Dependencies

- **Language / runtime:** bash 4+ (matches the existing sensor surface).
- **Framework:** none — pure-bash structural scan.
- **Build / packaging:** plugin manifest (`.claude-plugin/plugin.json`);
  no compilation step. Sensor is invoked as `bash <path>`.
- **Testing:** existing bash test harness pattern (file at
  `tests/sensors/<sensor-id>.test.sh`, pattern set by
  `tests/sensors/no-vibeflow-refs.test.sh` and similar).

### External libraries

- `grep`, `awk`, `find` — POSIX core utilities; already required.
- `shellcheck` — linting, environmental (CI-only); the sensor must
  pass `shellcheck` clean per the existing `lib/sensors/no-vibeflow-refs.sh`
  precedent.

### Internal prior work

- `lib/sensors/no-vibeflow-refs.sh` — direct structural sibling.
  The FR-5 sensor copies its grep / emit-failure helper shape.
- `concepts/yoke-pattern-sensors` (canonical memory) — umbrella
  pattern: structured-output-on-failure, silent-success, exit-code
  semantics.
- `concepts/yoke-decision-2026-04-27-bidirectional-invariant-sensor-pattern`
  (canonical memory) — the structural pure-bash sensor decision the
  FR-5 sensor inherits from.
- `concepts/sensor-as-first-class-persistent-artifact-yokesensorsidmd`
  (canonical memory) — sensor catalog entry shape under
  `.yoke/sensors/<id>.md`, applied for the new regression sensor.
- `lib/sensors/ack-sensors.sh` — the `--mode readiness` surface that
  the new sensor must be discoverable through.

## APIs and Data Model

- **Sensor invocation contract** (FR-5 regression sensor) —
  Invocation: `bash lib/sensors/no-canonical-memory-direct-refs.sh [--scan-dir <dir>]`.
  Default `--scan-dir lib/sensors`. Exit 0 on no violations
  (silent stdout). Exit 1 on violations: stdout is a sequence of
  YAML violation blocks (`id`, `location`, `correction_instruction`,
  `reference`) per `concepts/yoke-pattern-sensors`. Exit 2 reserved
  for environmental causes (e.g. `--scan-dir` does not exist).
  Tests: positive fixture (clean tree → exit 0 silent), negative
  fixture (planted forbidden ref → exit 1 with one violation per
  match), reverse fixture (legitimate `resolve-provider.sh`
  reference → exit 0).
- **Forbidden-reference pattern** —
  Path-pattern match against each sensor file's body:
  `lib/canonical-memory/<X>` where `<X>` is any path component
  other than `resolve-provider.sh` (with or without `.sh`
  extension); plus exact basename matches against the v2.0.0-extracted
  helper set: `registry.sh`, `resolve-memory.sh`,
  `write-promoted-concept.sh`. Implementation: `grep -nE` with the
  union pattern; each match is one violation block.
- **Self-test contract** —
  `tests/sensors/no-canonical-memory-direct-refs.test.sh` —
  pattern matches existing `tests/sensors/<id>.test.sh` shape:
  positive subcase, negative subcase (planted ref in a tmp tree),
  reverse subcase (planted `resolve-provider.sh` reference). Test
  exits 0 on all-pass / 1 on any subcase failure.
- **Sensor catalog entry** —
  `.yoke/sensors/no-canonical-memory-direct-refs.md` — frontmatter
  per `concepts/sensor-as-first-class-persistent-artifact-yokesensorsidmd`:
  `id`, `command`, `type: computational`, `token_cost: 0`,
  `time_cost: 30`. Body has the four mandatory sections (per
  Sprint-02 sensor harness realignment) — purpose, how to run,
  frequent errors, known issues.

## Non-Functional Requirements

- **Latency:** Regression sensor invocation completes in < 500ms wall-clock over the full `lib/sensors/` tree (~12 files at fix-spec time).
- **Throughput:** 0 rps additional canonical-memory provider load — the regression sensor performs zero substrate I/O.
- **Disk footprint:** ≤ 5MB additional under the worktree (sensor + self-test + sensor-catalog md), well under the historical 10MB per-slug ceiling.
- **Availability:** 100% deterministic runs — no flaky external dependencies; bash + grep only.
- **Coverage delta:** ≥ 100% of currently-stale references in `lib/sensors/*.sh` flagged by the regression sensor on a planted-fixture replay.

## Alternatives Considered

### Alt: Rewrite both sensors to dispatch through `/yoke:search-canonical-memory` (option b)

**Trade-off vs. chosen:** Preserves the historical round-trip and
bidirectional-link invariants inside Yoke's sensor pool, instead of
delegating equivalent coverage to the provider plugin's test surface.
**Reason for rejection:** The substrate-direct filesystem traversal
both sensors require (vault path lookup, file-by-file iteration of
`actors/` and `concepts/`) is not exposed by the query-shaped
`/yoke:search-canonical-memory` facade by design. Re-implementing
would either duplicate substrate-specific logic in Yoke (violates the
v2.0.0 namespace separation ratified at
`yoke-decision-2026-04-30-namespace-separation-yoke-vs-provider`) or
require a new filesystem-shaped facade verb that the fix-spec
anti-scope explicitly forbids ("Inventing a new canonical-memory
facade verb that exposes substrate-direct filesystem traversal to
sensors").
**Source:** `concepts/yoke-pattern-facade-vs-provider-verbs`

### Alt: Inferential / LLM-judged regression sensor for FR-5

**Trade-off vs. chosen:** More flexible — could detect forbidden
references via dynamic `eval`, variable indirection, or close
paraphrases of the violation pattern.
**Reason for rejection:** Structural grep is sufficient for the
violation class (exact textual references to removed files);
LLM-judging is over-kill, costs tokens per cycle, and is explicitly
listed as an anti-pattern in
`yoke-decision-2026-04-27-bidirectional-invariant-sensor-pattern`
("LLM-judged structural invariant — over-kill; structural grep is
sufficient and reproducible").
**Source:** `concepts/yoke-decision-2026-04-27-bidirectional-invariant-sensor-pattern`

### Alt: Runtime-only check inside `/yoke:implement` instead of a standalone sensor

**Trade-off vs. chosen:** Smaller file footprint — no new sensor
script, no new self-test, no new catalog entry; the check would
fire as a per-cycle hook inside the implement loop.
**Reason for rejection:** Defeats discoverability via
`bash lib/sensors/ack-sensors.sh --mode readiness`, which is the
single source of truth for sensor inventory per
`yoke-pattern-sensors`. Hiding a structural invariant inside a
runtime hook makes it invisible to readers and to CI; the
canonized doctrine is that sensors are first-class persistent
artifacts (`sensor-as-first-class-persistent-artifact-yokesensorsidmd`).
**Source:** `concepts/yoke-pattern-sensors`

### Alt: Keep the broken sensors and fix only the harness's exit-2-as-skip behavior

**Trade-off vs. chosen:** Smallest possible change — leave the
sensor scripts alone, change the harness so exit 2 surfaces as a
fail rather than a skip.
**Reason for rejection:** The sensors' invariants are
substrate-direct (round-trip queries against vault files,
bidirectional-link traversal across `concepts/` + `actors/`); even
with the harness change, the sensors would never evaluate their
invariants in this repo's working tree (no vault under the worktree).
The exit-2 surfacing change without a sensor rewrite gives a
permanently-red CI signal with no underlying drift information —
worse than the silent-skip baseline, not better.
**Source:** internal experience

## Trade-offs

- **Sensor pool surface area shrinks.** Deleting both sensors
  reduces Yoke's sensor pool from N to N−2; the round-trip and
  bidirectional-link invariants leave Yoke's surface entirely.
  The chosen approach accepts this cost because the invariants
  are substrate properties — equivalent coverage belongs to the
  provider plugin, not to the framework.
- **Regression sensor scope is narrow by design.** The new
  `no-canonical-memory-direct-refs.sh` only scans `lib/sensors/`,
  not the rest of the framework tree (`skills/`, `hooks/`,
  `agents/`, `lib/runtime/`, `lib/working-memory/`). Broader
  coverage is `lib/sensors/no-vibeflow-refs.sh`'s framework-clean
  responsibility; duplicating it would create overlapping
  diagnostics on every PR.
- **Exact-textual matching misses dynamic references.** A future
  author who introduces `local helper="lib/canonical-memory"; "$helper/registry.sh"`
  would not be flagged by the regression sensor. The chosen
  approach accepts this gap (canonized anti-pattern bans the
  LLM-judged alternative); a code-review-time human check is
  the backstop.

## Cross-cutting Concerns

- **Observability:** Sensor emits structured-YAML violation blocks
  per `concepts/yoke-pattern-sensors`; per-cycle evidence lands at
  `.yoke/sensors/no-canonical-memory-direct-refs.md` runtime
  evidence section when the sensor is invoked through the council
  pool. CI workflow (`tests/run-all.sh` family) surfaces failures
  as a single red signal with the violation block in the log.
- **Security:** No secrets, no network, no auth boundary. Pure
  source-tree scan.
- **Error handling:** Exit 0 = silent success; exit 1 = one or
  more violations (structured stdout); exit 2 = environmental
  (e.g. `--scan-dir` missing). The harness's existing exit-2
  semantics ("environmental skip") remain correct for the new
  sensor — but no removed-script path produces it.
- **i18n / a11y:** n/a — internal tooling, structured stdout.

## Technical Use Cases

### FR-1 — Zero forbidden references in `lib/sensors/*.sh`

**Components involved:** `lib/sensors/yoke-doctrine-round-trip.sh` (delete), `lib/sensors/contract-promotion-bidirectional.sh` (delete), `lib/sensors/no-canonical-memory-direct-refs.sh` (new — verifies the invariant on every CI run).
**Contracts used:** sensor invocation contract (exit 0 silent / exit 1 with violations); forbidden-reference pattern (path-pattern match against `lib/canonical-memory/<X>` where `<X>` ≠ `resolve-provider.sh`, plus the v2.0.0-extracted basename set).
**NFRs applied:** Latency, Coverage delta, Availability.
**Edge cases:** Comment-only references (e.g. `# see lib/canonical-memory/registry.sh`) — flagged because they leak stale doctrine into reader expectations. Must update or remove. Self-reference inside the new regression sensor itself — exempt via a pinned allow-list comment marker `# nocrm:self-pattern` recognized by the sensor's own scan, OR by anchoring the regex to lines that are not preceded by the marker; pick the simpler option at implementation time.

### FR-2 — Surviving sensors dispatch only via the facade

**Components involved:** every surviving file under `lib/sensors/*.sh` (post-deletion).
**Contracts used:** facade rule from `concepts/yoke-pattern-facade-vs-provider-verbs` — sensors that need canonical-memory data go through `/yoke:search-canonical-memory`; sensors are downstream of the facade. Sourcing `lib/canonical-memory/resolve-provider.sh` directly is permitted only inside facade skills + runtime helpers, NOT inside sensors.
**NFRs applied:** Throughput (zero substrate I/O from the post-fix sensor surface).
**Edge cases:** A future sensor that legitimately needs canonical-memory data will need to invoke the facade via `Skill` — but Skill is not callable from a bash sensor body (it is an LLM-tool harness primitive). The current post-fix surface has zero such sensors; if one is needed, the design must evolve (out of this fix's scope).

### FR-3 — Deletion atomicity (sensor + self-test + active references)

**Components involved:** `tests/sensors/yoke-doctrine-round-trip.test.sh` (delete), `tests/sensors/contract-promotion-bidirectional.test.sh` (delete if exists), `.yoke/sensors/<id>.md` for both sensors (no-op — neither has an active catalog entry post-v2.0), historical files under `.yoke/acceptance-contracts/historical/**` (preserved untouched).
**Contracts used:** v3.0.0 active-vs-historical split — historical files are preserved on disk per the no-historical-migration policy; active references must be removed.
**NFRs applied:** Disk footprint (net negative — deletions outweigh the new sensor + test + catalog entry).
**Edge cases:** The historical sprint snapshot
`.yoke/sprints/2026-04-30-pluggable-canonical-memory-s02.md` and the
historical contract `.yoke/contracts/2026-04-27-sprint-contract-promotion.md`
both reference the deleted sensors as part of their cycle history;
they must NOT be modified (would invalidate the historical record).
The test runner `tests/run-all.sh` discovers tests via filesystem
glob, so deleted self-tests stop running automatically — no
explicit deregistration step required.

### FR-4 — Exit-2-from-missing-substrate-script eliminated

**Components involved:** post-fix `lib/sensors/*.sh` surface (verified by FR-1's regression sensor).
**Contracts used:** sensor exit-code semantics from `concepts/yoke-pattern-sensors` — exit 2 reserved for environmental causes (missing binaries, unreachable paths the sensor itself did not author); exit 0/1 for drift verdicts.
**NFRs applied:** Availability (deterministic).
**Edge cases:** A future PR that re-introduces a forbidden reference would re-create the exit-2-from-missing-substrate-script class; FR-1's regression sensor (FR-5 in the fix-spec) catches that at PR time, not at runtime.

### FR-5 — Regression sensor exists and is discoverable

**Components involved:** `lib/sensors/no-canonical-memory-direct-refs.sh` (new), `tests/sensors/no-canonical-memory-direct-refs.test.sh` (new), `.yoke/sensors/no-canonical-memory-direct-refs.md` (new — sensor catalog entry).
**Contracts used:** sensor structural shape from `concepts/yoke-decision-2026-04-27-bidirectional-invariant-sensor-pattern`; sensor catalog frontmatter shape from `concepts/sensor-as-first-class-persistent-artifact-yokesensorsidmd`; readiness surface from `lib/sensors/ack-sensors.sh --mode readiness`.
**NFRs applied:** Latency (< 500ms), Throughput (zero substrate I/O), Disk footprint, Availability, Coverage delta.
**Edge cases:** Self-pattern matching — the sensor's own body contains the forbidden patterns by necessity (they are its detection regex); exempt the sensor's own file from the scan, or anchor the regex to lines that are not preceded by a documented allow-list marker. Test fixtures live in `tests/sensors/fixtures/no-canonical-memory-direct-refs/` per the existing per-sensor fixture convention.

### FR-6 — Self-test of deleted sensor is also deleted

**Components involved:** `tests/sensors/yoke-doctrine-round-trip.test.sh` (delete).
**Contracts used:** test-runner discovery contract — `tests/run-all.sh` and the `.github/workflows/tests.yml` workflow discover test files via filesystem glob; deleted files stop running automatically.
**NFRs applied:** Disk footprint (net deletion).
**Edge cases:** The self-test's case (4) negative-path fixture creates a stub `lib/canonical-memory/registry.sh` inside `mktemp -d`; the deletion removes that fixture creation along with the file. No runtime side-effects (the stub lives only inside `$tmp`).
