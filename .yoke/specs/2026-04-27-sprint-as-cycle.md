## Overall objective

Replace the per-task working-memory file shape (`.yoke/tasks/<slug>-s<NN>-t<MM>.md`)
with a per-sprint shape (`.yoke/sprints/<slug>-s<NN>.md`) where each sprint
file is a self-contained ralph-cycle runtime bundle: sprint objective +
sprint DoD + each task with its DoD + sensor IDs + AC criterion IDs.
Migrate the 62 legacy `<slug>-part-N.md` spec files and the 16 existing
doctrine-canonization task files into the new shape inside the same
`/yoke:implement` run. Rewrite every consumer (skills, agents, lib,
progress.md shape) to read sprints serially with per-sprint cycle
hard-bounds, and hard-remove the legacy `wm_task_*` path helpers and
the `tasks` archive category. The end state: one ralph cycle = one
sprint file as the working set; phase artifacts (PRD / spec / AC /
sensor / contracts) keep their per-task one-file shape; sources of
truth (AC, sensors) remain authoritative and are referenced by ID
from sprint files, never inlined.

## Sprints

Each sprint has a delivery objective and an ordered task list. Each
task is rendered as a one-line story anchored on a stable task ID.
The full technical implementation and validation lives in
`.yoke/tasks/<task-id>.md` for the duration of this run; at run-end
those task files concatenate into per-sprint files in `.yoke/sprints/`
as the final migration step.

## Contracts and interfaces

The shapes downstream phases (Phase 3 acceptance contract, Phase 4
implement loop, Phase 5 canonization) and reusable artifacts must
respect.

- **Sprint file shape (`.yoke/sprints/<slug>-s<NN>.md`).** Frontmatter: `sprint: <N>` (unpadded integer), `slug: <slug>`, `status: draft|approved`, `created_at: <iso8601>`, `model: ""`, `traceability: ""`, optional `Migrated-from: [<path>, ...]` array for migrated sprints. Body sections in order: `## Sprint objective` (one paragraph), `## Sprint DoD` (bullet list of binary checks), `## Tasks` (one `### Task <ID>` subsection per task with `**Story:**`, `**Technical implementation:**`, `**Validation:**`, `**Acceptance criterion:**` inline labels), `## Functional acceptance criteria` (bullet list of criterion IDs referencing `acceptance-contracts/<slug>.md`), `## Sensors` (bullet list of sensor IDs referencing `.yoke/sensors/<id>.md`).
- **Sprint ID shape.** `<slug>-s<NN>` where `<NN>` is zero-padded 2 digits (1–99). The padding ensures `wm_list_sprint_paths` returns lexically = positionally ordered paths. Per the supersession of `yoke-decision-2026-04-25-task-ids-zero-pad-to-2-digits-filename-only`, the zero-pad rule now applies to sprint IDs only; task IDs (now anchors inside sprint files) keep `t<MM>` zero-padding by convention but are not a filename concern.
- **`progress.md` shape.** Frontmatter: `current_sprint: <NN>` (zero-padded 2 digits), `completed_sprints: [<NN>, ...]` (array of zero-padded sprint IDs that converged), `cycle_count: <N>` (resets at sprint boundaries), `cycle_log:` array of per-cycle entries. Body: free-form notes per cycle. The file is single — never split into per-sprint files.
- **`/yoke:implement` walk contract.** Reads `current_sprint:` from `progress.md`. Loads `.yoke/sprints/<slug>-s<current_sprint>.md` as the cycle's working set. Runs ≤8 cycles per sprint to convergence. On convergence: appends `<current_sprint>` to `completed_sprints:`, increments `current_sprint:`, resets `cycle_count:` to 0, writes the sprint-scoped contract section to `.yoke/contracts/<slug>.md`. On hard-bound exhaustion: emits Trigger 4 escalation packet keyed on the active sprint.
- **`.yoke/contracts/<slug>.md` shape.** Single file per task; sprint-scoped agreements append as `## Sprint <NN> contract` H2 sections at convergence. Generator and Validator co-write the matching section on consensus; the file accumulates across all sprints of the task.
- **Sensor ID resolution.** A sprint file's `## Sensors` list contains sensor IDs (e.g., `bash-syntax-clean`, `frontmatter-yaml-valid`). The Validator resolves each ID via `.yoke/sensors/<id>.md` at cycle execution. Sprint files NEVER inline sensor logic; they reference by ID only.
- **AC criterion ID resolution.** A sprint file's `## Functional acceptance criteria` list contains criterion IDs (e.g., `AC-1`, `AC-2.3`). The Validator resolves each ID via the binding `acceptance-contracts/<slug>.md`. Sprint files NEVER inline criterion text beyond a one-line projection annotation.
- **Migration script semantics.** No standalone bash script artifact. The migration is a sequence of tasks inside sprints 2 and 4 of this spec. Each task uses `git mv` (not `mv` + `git add`) so history is preserved. The pre-flight backup task copies originals to `.yoke/.legacy-archive/2026-04-27-pre-migration/` (gitignored) before any move; failure mode is restore-from-archive.
- **Pattern-doc canonization packet.** `.yoke/runtime/.preserve-packet.md` carries: (a) the new entity body for `concepts/yoke-pattern-sprint-runtime-bundle.md`, (b) the diff against `concepts/yoke-pattern-memory-model.md` adding `refined_by: [yoke-pattern-sprint-runtime-bundle]` and superseding the per-task-file clauses with a reference to the new entity, (c) the new decision body for `concepts/yoke-decision-2026-04-27-sprint-id-zero-pad-supersedes-task-id-zero-p.md` with `supersedes: [yoke-decision-2026-04-25-task-ids-zero-pad-to-2-digits-filename-only]`. Phase 5 (`/yoke:preserve`, post-loop, Orchestrator-only) consumes this packet and opens the canonical-memory PR under Model C.
