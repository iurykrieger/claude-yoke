## Context and Scope

The Yoke plugin's three council persona prompts at `agents/sr-eng.md`,
`agents/sr-qa.md`, and `agents/sr-staff.md` are loaded verbatim into
the Phase-A subagent system prompt by `lib/runtime/persona-loader.sh
validate-all` and consumed at runtime by `lib/runtime/cycle.sh
pre-spawn` / `lib/runtime/council.sh phase-b`. The v4.0.0 cutover
(see [[yoke-decision-2026-05-03-acceptance-criteria-cutover]]) renamed
the binding Phase-3 artifact from "Acceptance Contract" to "Acceptance
Criteria" and reshaped its body to User Stories → Definition of Done
→ Acceptance Criteria → Sensor pool, but the persona prompts were
not visited by the v4.0.0 sweep. The drift was masked at CI time by
two confounding allowlist filters in
`tests/smoke/orphan-acceptance-contract-refs.test.sh` (case-sensitive
grep + `acceptance-contract-anchored` allowlist) — see Phase-1
artifact "Root-Cause Hypothesis".

**This spec changes:** the prose and frontmatter values of three
files — `agents/sr-eng.md`, `agents/sr-qa.md`, and `agents/sr-staff.md`
— as a single in-place token-substring rewrite anchored to the v4.0.0
Acceptance-Criteria pattern ([[yoke-pattern-acceptance-criteria]]).

**This spec does not change:** any executable code path, any
working-memory helper, any sensor body, any template, any historical
`.yoke/acceptance-contracts/<slug>.md`, the `<contract-slug>`
test-dir parameter convention (retained per
[[yoke-decision-2026-05-03-no-historical-migration-policy]]),
`docs/architecture.md` (its prose is already migrated; only its
`<contract-slug>` reference would be in scope, and that's
intentionally retained), or the historical `Migration history`
narrative blocks in `CLAUDE.md` and `docs/migration-v3-to-v4.md`.

## Goals and Non-Goals

**Goals**

- After the fix, `grep -nE 'acceptance-contract|Acceptance-Contract|Acceptance Contract' agents/sr-eng.md agents/sr-qa.md agents/sr-staff.md` returns 0 matches.
- After the fix, `bash tests/smoke/orphan-acceptance-contract-refs.test.sh` exits with the same exit code as before the fix (sensor exit-code parity, NFR-1).
- After the fix, `lib/runtime/persona-loader.sh validate-all` exits 0 against the three modified files (NFR-2: persona-loader-validation parity).
- After the fix, every Phase-A `/yoke:implement` cycle loads persona prompts that describe authoring against the v4.0.0 Acceptance Criteria document, not the v3.x Acceptance Contract.

**Non-Goals**

- Rename the test-dir parameter `<contract-slug>` to `<criteria-slug>`. Anchored to [[yoke-decision-2026-05-03-no-historical-migration-policy]] and the existing sensor allowlist; out of scope per Phase-1 artifact FR-6.
- Touch `docs/architecture.md`. Its prose at line 30 already uses the migrated form ("acceptance-criteria-anchored tests"); its only legacy reference is the `<contract-slug>` parameter, retained per the prior bullet.
- Harden `tests/smoke/orphan-acceptance-contract-refs.test.sh` to catch the title-cased `Acceptance-Contract` / `Acceptance Contract` form. Tracked separately ("F10" in the issue tracker).
- Migrate the 17 historical `.yoke/acceptance-contracts/<slug>.md` files. Forbidden by [[yoke-decision-2026-05-03-no-historical-migration-policy]].
- Rename legacy decision-token strings in `lib/ralph-loop/escalate.sh` (`acceptance-contract-violation`, `reformulate-acceptance-contract`). Out of scope per the existing sensor allowlist's rationale block.
- Author or modify any sensor under `lib/sensors/**` or `tests/sensors/**`.
- Add any compatibility shim, dual-track alias, or feature-flag for the v3.x vocabulary. Forbidden by [[yoke-decision-2026-05-03-acceptance-criteria-cutover]] ("a soft alias defeats the cutover signal").

## Architecture

**Chosen pattern: doctrine-prose forward rename, no shim.**

Anchored to [[yoke-decision-2026-05-03-acceptance-criteria-cutover]]
which canonized the cutover discipline as breaking-clean: *"a soft
alias defeats the cutover signal — failure surface (command-not-found)
is exactly what makes a breaking change loud and resumable."* This
fix extends the same discipline to persona prompts that the v4.0.0
sweep missed: hard-rename the prose in place, no transitional alias,
no dual vocabulary.

**Invariants the architecture guarantees:**

- **Single edit pass.** Each of the three files is modified once by
  text substitution against a fixed token map (FR-1 through FR-5).
  No iterative or LLM-driven rewrites; every replacement is
  string-deterministic.
- **No executable surface change.** No file under `lib/`, `hooks/`,
  `tests/`, `templates/`, or `skills/` is touched. The three target
  files are markdown bodies + YAML frontmatter strings.
- **Forward-only.** No legacy term remains in the three files post-fix
  (FR-7); legacy terms in `lib/ralph-loop/escalate.sh`,
  `.yoke/acceptance-contracts/`, the test-dir parameter
  `<contract-slug>`, and the migration narrative blocks are
  preserved untouched per [[yoke-decision-2026-05-03-no-historical-migration-policy]].
- **Containment.** The fix's regression surface is exactly the three
  modified files plus their two consumers (`persona-loader.sh
  validate-all`, `tests/smoke/orphan-acceptance-contract-refs.test.sh`)
  — both already exist as gates in the repo.

**Failure modes explicitly not handled:**

- *Slice carry-over from in-flight tasks.* If a `/yoke:implement` run
  is mid-flight at fix-merge time, slice files at
  `.yoke/runtime/cycles/<N>/<persona>.md` written before the merge
  may still embed the legacy term. Mitigation: those slices are
  gitignored runtime artifacts and the next cycle re-spawns personas
  with the new prompt.
- *Reader confusion at the `<contract-slug>` retention boundary.*
  The fix migrates surrounding prose to "acceptance-criteria-anchored
  tests" while keeping the test-dir parameter as `<contract-slug>`.
  A reader may infer the parameter should also rename. Mitigation:
  the Non-Goals section pins the retention; the existing sensor
  allowlist's rationale block (lines 22–25 of
  `tests/smoke/orphan-acceptance-contract-refs.test.sh`) is the
  durable contract anchor.

## APIs and Data Model

This fix changes no APIs and no on-disk data models. The contracts it
touches are *prose contracts inside Markdown bodies and YAML
frontmatter string values*. Three contracts are exercised:

- **Persona-loader frontmatter contract.** `lib/runtime/persona-loader.sh
  validate-all` parses the YAML frontmatter of `agents/sr-*.md` and
  asserts that `name`, `description`, `objective`, and `tools` keys
  exist with parseable string values. Schema: YAML 1.1 single-line
  string scalars. Tests: `lib/runtime/persona-loader.sh validate-all`
  (existing self-test exit-code gate).
- **Smoke-sensor allowlist contract.** `tests/smoke/orphan-acceptance-contract-refs.test.sh`
  uses a fixed `grep -RInE 'acceptance-contract(s)?'` against
  `SCAN_PATHS=(skills/ agents/ hooks/ lib/ templates/ CLAUDE.md
  .claude-plugin/ docs/)` followed by an allowlist filter chain.
  Schema: text-line stream; pre/post counts compared in NFR-1. Tests:
  `bash tests/smoke/orphan-acceptance-contract-refs.test.sh` exit-code
  parity (existing gate).
- **Phase-A spawn prompt contract.** `lib/runtime/cycle.sh pre-spawn`
  reads each persona's full body into the spawned Task's system prompt.
  Schema: opaque markdown bytes. Tests: `tests/smoke/ralph-loop-sprint-walk.test.sh`
  end-to-end smoke (existing gate; no new assertion added).

- **Token-count delta:** the byte-count delta of the three files combined is ≤ 1% of the union pre-fix byte size (case-corrected v4.0.0 vocabulary is ≈ 1 byte longer per occurrence than v3.x; ~13 occurrences yields well under the 1% bound).
- **CI smoke runtime:** the `tests/` workflow's smoke job at `.github/workflows/tests.yml` finishes in ≤ 60s post-fix (existing baseline; the fix adds no new test).
- **Disk footprint:** the three modified files combined remain ≤ 0.05 MB after the fix (existing baseline ≈ 0.03 MB; budget is 0.05 MB upper bound).

## Alternatives Considered

### Alt: Soft-alias dual vocabulary (keep both terms, deprecate one)

**Trade-off vs. chosen:** Less disruptive to any reader cached on the
v3.x vocabulary; preserves every legacy phrase intact alongside the
new one.
**Reason for rejection:** Forbidden by [[yoke-decision-2026-05-03-acceptance-criteria-cutover]]:
"*a soft alias defeats the cutover signal — failure surface
(command-not-found) is exactly what makes a breaking change loud and
resumable.*" Persona prompts are doctrine; dual vocabulary in doctrine
is exactly the drift this fix exists to remove.
**Source:** [[yoke-decision-2026-05-03-acceptance-criteria-cutover]]

### Alt: Migration script that rewrites all 17 historical `.yoke/acceptance-contracts/<slug>.md` files at the same time

**Trade-off vs. chosen:** Single-pass alignment of every legacy
reference in the working-memory archive, not just the three persona
files; eliminates any historical/active vocabulary mismatch.
**Reason for rejection:** Forbidden by [[yoke-decision-2026-05-03-no-historical-migration-policy]]:
"*The historical files are read-only audit artifacts; rewriting them
in the new shape adds no information to closed-out tasks. Migration
scripts are a known correctness hazard (frontmatter drift, link rot,
etc.) and would need to be tested across all 17 files.*" The cutover
is forward-only by design.
**Source:** [[yoke-decision-2026-05-03-no-historical-migration-policy]]

### Alt: Rebuild the persona prompts from the canonized pattern entity (regenerate from `[[yoke-pattern-acceptance-criteria]]`)

**Trade-off vs. chosen:** A regenerated persona prompt is guaranteed
to track the canonized doctrine for every future cutover, not just
v4.0.0; eliminates the manual-sweep failure mode that produced this
drift.
**Reason for rejection:** Out of scope for a fix-shaped task. The
persona prompts hold prose nuance (anti-scope phrasing, body cadence,
example wording) that is not derivable from the canonical-memory
pattern entity alone; the regenerator does not exist as tooling and
building it would be a feature-add, not a fix. The reporter's
"Suggested fix" was a sweep + replace, and that's what this spec
ratifies.
**Source:** internal experience

## Trade-offs

- **Scoped retention is not zero-cost cognitively.** The fix migrates surrounding prose to "acceptance-criteria-anchored tests" while keeping the test-dir parameter as `<contract-slug>`. A future reader of `agents/sr-qa.md` line 47 will see the migrated phrase next to the unmigrated parameter and may file a duplicate fix. The spec mitigates this by naming the retention explicitly in *Non-Goals* and citing the durable allowlist anchor — but the cognitive friction is the price of forward-only-no-shim.
- **No regenerator built.** The fix codifies the rename by hand, not by tooling. Future doctrine cutovers (vN+1) will pay the same manual-sweep cost. Building a persona-prompt regenerator was rejected as out-of-scope, accepting that we'll re-sweep manually next time.
- **Sensor remains blind to the title-cased form.** The `tests/smoke/orphan-acceptance-contract-refs.test.sh` sensor's case-sensitive grep is a known coverage gap (the reporter's "F10"). This fix does not patch the sensor; the sensor will pass after the fix because it was already passing (it never matched the title-cased forms). A subsequent fix is needed to harden the sensor — without that fix, this drift could regress and CI would not catch it.

## Cross-cutting Concerns

- **Observability:** The fix's success is observable via the two existing exit-code gates: `tests/smoke/orphan-acceptance-contract-refs.test.sh` (sensor exit parity, NFR-1) and `lib/runtime/persona-loader.sh validate-all` (frontmatter parse, NFR-2). No new logging or telemetry is added.
- **Security:** None applicable. The fix changes only documentation prose; no auth boundary, secret, or threat surface is touched.
- **Error handling:** The fix produces no new runtime error paths. Failure of FR-1 through FR-5 (silent skip, partial application) is caught at PR review and at CI by the smoke gate.
- **i18n / a11y:** n/a — internal tooling. The repository's en-US language invariant ([[yoke-conventions]]) applies to the rewritten prose; all replacement tokens are en-US.

## Technical Use Cases

### FR-1 — Title-cased `Acceptance-Contract` / `Acceptance Contract` substring rename

**Components involved:** `agents/sr-eng.md`, `agents/sr-qa.md`, `agents/sr-staff.md` (frontmatter `description:` + `objective:` keys, body prose, `## Anti-scope` block).
**Contracts used:** Persona-loader frontmatter contract; Phase-A spawn prompt contract.
**NFRs applied:** Sensor exit-code parity, persona-loader validation latency, line-count delta.
**Edge cases:** The phrase "Acceptance Contract" appears as the literal artifact name (target of rename) AND inside the `> **Lineage.**` quote blocks where it cites Vibeflow / Bedrock upstream lineage (those are sensor-allowlisted intentional historical citations and MUST NOT be renamed if any persona file carries one). Audit before rewriting: `grep -B2 -A2 'Acceptance Contract' agents/sr-*.md` and confirm context. Currently no `Lineage` block in `agents/sr-*.md`, so the simple rewrite is safe; surface the audit anyway as guard-rail.

### FR-2 — `acceptance-contract-anchored` substring rename

**Components involved:** `agents/sr-eng.md` (lines 3, 5, 36, 140), `agents/sr-qa.md` (lines 3, 5, 27), `agents/sr-staff.md` (line 164).
**Contracts used:** Persona-loader frontmatter contract; Phase-A spawn prompt contract; smoke-sensor allowlist contract.
**NFRs applied:** Sensor exit-code parity (`acceptance-contract-anchored` is currently allowlisted; renaming to `acceptance-criteria-anchored` removes the matches before the allowlist filter sees them, and the allowlist's `acceptance-contract-anchored` filter line becomes a no-op for these files — sensor still exits with the same code because the per-file matches that filter neutralized are now zero).
**Edge cases:** The wording in `docs/architecture.md` line 30 already uses "acceptance-criteria-anchored tests"; FR-2's chosen target string MUST match that wording for cross-doc consistency.

### FR-3 — Frontmatter scope (`description:` and `objective:` keys)
