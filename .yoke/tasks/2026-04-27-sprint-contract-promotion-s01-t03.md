# Task 2026-04-27-sprint-contract-promotion-s01-t03 — Implement the promoted-concept write helper that produces a `concepts/` entity with mandatory rippability frontmatter, the `yoke-framework` tag, and bidirectional links to the host-project actor under `actors/`

> Generated by `/yoke:tech-spec` (stage 3) from
> `.yoke/specs/2026-04-27-sprint-contract-promotion.md`. Status flips to `approved` when Trigger 2
> approves the parent spec.

## Story

t01 admits the candidate; t02 refines its scoring; this task
materialises it. When `/yoke:preserve` Phase 5 receives a cascade
candidate flagged for promotion (impact class assigned, cascade
filters all green), it must produce a concrete file pair: a new
concept entity in the canonical memory's `concepts/` folder
encoding the promoted contract, and a backlink in the host-project
actor's body under `actors/`. The concept must carry the mandatory
rippability frontmatter so a future model upgrade can re-validate
or deprecate it; the bidirectional edge to the actor is the graph
property the framework relies on for traceability and pruning. Both
must land in a single Phase-6 PR so Model C governs the write
atomically.

## Technical implementation

Three changes, all inside `/yoke:preserve` Phase 5 (the entity-write
phase before the Phase 6 PR open):

1. **Promoted-concept write helper.** Add a new helper
   `lib/canonical-memory/write-promoted-concept.sh` invoked by
   `/yoke:preserve` Phase 5 when a candidate's source kind is
   `sprint-contract-promotion`. The helper takes (candidate YAML
   block, host-project actor name, output directory = canonical
   memory's `concepts/`) and writes one markdown file with:
   - **Filename.** `<llm-summarized-slug>.md`. The slug is produced
     by a one-shot LLM summarisation call that takes the cohesive
     `topic:` (from t02's group rationale or the single-contract
     `topic:` for an exact-match group) and emits a kebab-case ≤50-char
     title. Collisions in `concepts/` are resolved by the
     regenerate-and-retry rule already used for PRD slugs in
     `lib/working-memory/paths.sh::wm_slug_in_use`. Concrete
     prefix is not added (no `yoke-contract-` namespace) — the
     filename is the topic-summary alone, per the PRD invariant
     "no new entity subtype".
   - **Frontmatter (mandatory rippability per
     [[yoke-pattern-memory-model]]).** Exactly the fields:
     `type: concept`, `name`, `aliases` (carrying the original
     topic prose verbatim), `description`, `status: active`,
     `ratified` (canonization date), `model_calibrated_against`
     (the model id that produced the cohesive judgment in t02),
     `last_validated` (same as `ratified` at promotion time),
     `traceability` (every originating
     `.yoke/contracts/<slug>.md#<contract-id>` reference),
     `impact_level` (from cascade), `tags` (must include
     `type/concept`, `kind/contract`, `yoke-framework`,
     `status/active`, plus any host-project domain tag from
     `.yoke/config.yaml`), `applies_to` (must contain the host-project
     actor name), `depends_on: []`, `supersedes: []`,
     `contradicts_with: []`, `project` (host-project slug from
     `.yoke/config.yaml`).
   - **Body.** Title `# <description>`, leading blockquote with the
     cohesive decision verbatim, `## Description` (LLM-expanded
     rationale lifted from cascade `reason:`), `## Originating
     contracts` (bullet list of `.yoke/contracts/<slug>.md#<contract-id>`
     references with their cycle numbers), `## Where it applies`
     (one-line tying back to the host actor), `## Related` (empty
     section reserved for future graph edges).
2. **Host-project actor backlink.** The same helper, after writing
   the concept, edits `actors/<host-actor-name>.md` to append (or
   create-then-append-to) a `## Recent Activity` body section. The
   appended line is `- <YYYY-MM-DD> — [[<concept-slug>]] — <one-line
   summary>` (mirroring the existing shape used by
   [[sprint-contracts]]'s "Recent Activity" entries today). If the
   actor file does not yet exist, the helper creates it from the
   canonical actor template under Model C and writes the backlink
   into the seeded body (the canonical write path treats this as
   an actor-create + concept-create batch under one PR).
3. **Project-actor resolution.** The host-project actor name is
   read from `.yoke/config.yaml` via a new helper
   `lib/working-memory/host-actor.sh::wm_host_actor_name` that
   returns the canonical actor name for the host project (the field
   `host.actor_name` in `config.yaml`; default = the kebab-case of
   `host.project_name` if `actor_name` is unset). On a host project
   that has not yet declared `host.actor_name` in `config.yaml`,
   the helper writes the default into `config.yaml` on first use
   (idempotent; the user can edit it later) and proceeds.

## Validation

1. **Concept frontmatter completeness test.** A scripted invocation
   of the helper against a synthetic candidate with
   `kind: sprint-contract-promotion`, two originating contract
   references, and a known cohesive `reason:`. Asserts the written
   file's frontmatter contains every mandatory field with non-empty
   values, the `tags` list contains `kind/contract` and
   `yoke-framework`, and the `applies_to` list contains exactly the
   resolved host-project actor name. Lives under
   `tests/canonical-memory/promoted-concept-frontmatter.test.sh`.
2. **Bidirectional backlink test.** Same fixture as test 1; asserts
   that after the helper runs, the `actors/<host-actor-name>.md`
   file's `## Recent Activity` section contains a line with a bare
   wikilink `[[<concept-slug>]]` whose target slug matches the
   concept written. Both directions of the edge present →
   bidirectional invariant satisfied. Lives under
   `tests/canonical-memory/promoted-concept-backlink.test.sh`.
3. **Actor-create-on-first-use test.** Fixture starts without an
   actor file. Asserts the helper creates the actor entity from the
   canonical actor template, the seeded body contains the
   `## Recent Activity` section with the backlink, and the actor's
   frontmatter is well-formed (matches `entities/actor.md` shape).
   Lives under
   `tests/canonical-memory/promoted-concept-actor-create.test.sh`.
4. **Slug-collision retry test.** Fixture has an existing
   `concepts/<topic-slug>.md`. Asserts the helper retries
   summarisation up to 5 times to produce a non-colliding slug,
   matching the PRD-slug retry rule in `lib/working-memory/paths.sh`.
   On exhaustion, the helper exits non-zero with a diagnostic
   naming the colliding slug.

The four tests cover: completeness, bidirectional invariant,
actor-create flow, and the slug-collision contract. They run
without the live LLM by stubbing the summarisation call to a fixed
output for tests 1–3 and to a colliding output for test 4.
