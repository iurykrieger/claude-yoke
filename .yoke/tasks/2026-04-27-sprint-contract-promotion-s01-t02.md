# Task 2026-04-27-sprint-contract-promotion-s01-t02 — Add semantic-overlap topic recognition inside `/yoke:preserve` Phase 3.2 cascade scoring without altering the cascade's structured-YAML output schema

> Generated by `/yoke:tech-spec` (stage 3) from
> `.yoke/specs/2026-04-27-sprint-contract-promotion.md`. Status flips to `approved` when Trigger 2
> approves the parent spec.

## Story

The deterministic floor delivered by t01 catches contracts whose
`topic:` strings are byte-identical across archives. It misses the
common case in practice: two contracts that resolve the same
underlying ambiguity but whose authors wrote the topic prose
slightly differently — different word order, alternative noun
choices, an extra qualifier. Without a recognition step that looks
past surface prose, the threshold of 2 occurrences would rarely
fire, and durable consensus would stay buried. This task adds a
semantic-overlap layer inside `/yoke:preserve` Phase 3.2's existing
LLM step so contracts that resolve the same ambiguity with different
words are recognised as the same topic, increasing repeatability
scoring without bypassing the deterministic floor and without
producing candidates that the floor did not admit.

## Technical implementation

Edit `skills/preserve/SKILL.md` Phase 3.2 (the cascade-scoring step
that consumes the YAML candidate list emitted by
`lib/canonical-memory/canonization-criteria.sh`). The change is
additive: the existing cascade-scoring prose stays intact; a new
sub-step is inserted before the existing repeatability/generality
scoring text:

1. **Group candidates by topic-equivalence (LLM judgment).** The
   cascade-scoring LLM call receives the candidate list as input and,
   for every group of candidates whose `occurrences:` counter is ≥ 2
   under the deterministic floor, evaluates whether the contracts in
   the group genuinely resolve the same ambiguity. The judgment is a
   binary per-group decision: the group is *cohesive* (the LLM can
   write a single rationale that captures all member contracts'
   `decision:` fields) or *split* (the prose collision was
   superficial; member contracts resolve different ambiguities).
2. **Splits decrement the count.** Every member of a split group is
   re-emitted with its `occurrences:` reduced to its own intra-group
   count (often 1). The group is dissolved.
3. **Cohesive groups merge.** Members of a cohesive group keep their
   collective `occurrences:` value; the LLM's rationale is captured
   in the group's `reason:` field, replacing whatever
   deterministic-stage rationale the cascade script emitted.
4. **Hard-contradiction respect.** If two members of a group carry
   `decision:` fields whose plain-text content directly contradicts
   (e.g., one contract says "use single quotes", another says "use
   double quotes" for the same selector context), the group is
   *split* — never coalesced — and a new top-level note is added to
   the cascade output: `notes:` gains an entry citing the
   contradiction. The existing `non-contradiction` criterion (cascade
   filter #5) consumes this note and routes the impact class to
   `regulatory`-equivalent escalation per [[yoke-pattern-model-c-governance]],
   which surfaces as a Trigger 5 ratification request rather than an
   auto-merge.
5. **No new candidates.** The semantic layer never invents a
   candidate the deterministic floor did not admit. A topic that
   appears once in archives is never promoted to `occurrences: 2` by
   semantic recognition alone — that would defeat the deterministic
   floor's reproducibility property.

The output schema is unchanged: the same YAML shape the cascade
script emits today; the same fields consumers read. Only the values
of `occurrences:` and `reason:` may differ between the deterministic
floor and the post-LLM-overlap pass.

Files touched:
- `skills/preserve/SKILL.md` — Phase 3.2 prose extension. New
  numbered sub-step inserted before the existing cascade-criteria
  text. The Phase 3.2 entry-point signature is unchanged.
- `lib/canonical-memory/canonization-criteria.sh` — no change in this
  task; its YAML output is consumed verbatim. The semantic layer
  reads and rewrites the YAML in-memory inside `/yoke:preserve`.

Patterns cited:
- [[yoke-pattern-model-c-governance]] — existing five-criterion
  cascade is preserved; semantic-overlap is a refinement of the
  *first* criterion (repeatability), not a new criterion.
- [[yoke-pattern-sensors]] — the LLM step inside `/yoke:preserve`
  Phase 3.2 is a deliberate inferential step (LLM judgment with
  structured output); the semantic-overlap pass conforms to that
  pattern's expectations (structured input, structured rationale in
  `reason:`, no plain-prose-only output).
- [[yoke-conventions]] — "blueprints wrapping agentic nodes": the
  deterministic floor (t01) wraps the agentic semantic-overlap step
  (this task), in that order; the LLM never runs before the
  deterministic floor admits candidates.

## Validation

Two validation surfaces:

1. **Skill-level smoke (manual + scripted).** A scripted invocation
   of `/yoke:preserve --from-orchestrator` against a synthesised
   `.yoke/` fixture containing two archives. Subcases:
   - **Cohesive case** — two archives, contracts whose `topic:`
     strings differ in surface prose but resolve the same ambiguity
     (e.g., "single-quote redirect URL" vs "use single quotes for
     redirect URLs"); decisions match. Expected: post-cascade YAML
     emits one cohesive group with `occurrences: 2` and a `reason:`
     synthesising both contracts.
   - **Split case** — two archives, contracts whose `topic:` strings
     are similar but resolve different ambiguities. Expected:
     post-cascade YAML emits two candidates, each with
     `occurrences: 1`. No cohesive group.
   - **Contradiction case** — two archives, contracts whose `topic:`
     strings are similar but `decision:` fields directly contradict.
     Expected: split, plus a `notes:` entry citing the contradiction;
     impact class escalates to require synchronous human ratification
     per Model C.
2. **Unit-level (LLM-stub).** A stub LLM judge that returns
   pre-canned cohesive/split/contradiction verdicts against fixed
   inputs proves the YAML-rewriting logic is correct independent of
   live LLM behaviour. The test fixture lives under
   `tests/canonical-memory/semantic-overlap-rewrite.test.sh`.

The skill-level smoke is the primary acceptance signal because the
LLM judgment is the load-bearing semantic step; a stub-only test
would not exercise the calibration. The smoke runs against
`claude-opus-4-7[1m]` (recorded in `model_calibrated_against:` on
any concept this run promotes) and is gated behind a flag in CI so
it does not run on every push.

## Acceptance criterion

The scripted skill-level smoke against the cohesive-case fixture
results in a post-cascade YAML output that contains exactly one
candidate with `occurrences: 2` and a `reason:` field that
references both originating contracts; the split-case fixture
results in two candidates each with `occurrences: 1` and no
cohesive group; the contradiction-case fixture results in a `notes:`
entry citing the contradiction.
