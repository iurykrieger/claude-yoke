# Task 2026-04-27-sprint-contract-promotion-s01-t01 — Extend cascade input to enumerate prior `.yoke/contracts/<*>.md` archives and emit a per-topic occurrence count

> Generated by `/yoke:tech-spec` (stage 3) from
> `.yoke/specs/2026-04-27-sprint-contract-promotion.md`. Status flips to `approved` when Trigger 2
> approves the parent spec.

## Story

A new task lands in the working memory of a host project that is
already running yoke. The task hits an interpretive ambiguity at
runtime; Generator and Validator reach consensus and pin a sprint
contract whose `topic:` reads, character-for-character, identical to
a contract pinned in a previous task's archive. The framework should
recognise this as the second occurrence of the same ambiguity. Today
it cannot: the cascade script only reads the active task's archive.
This task delivers the deterministic floor — the gate that admits a
recurring contract into cascade scoring — by extending the cascade's
input enumeration to walk every `.yoke/contracts/*.md` archive in the
host project and tracking an exact-string `topic:` count across them.
This is the load-bearing piece described as "the deterministic floor"
in the PRD's Known constraints; without it, no further scoring layer
can fire.

## Technical implementation

Edit `lib/canonical-memory/canonization-criteria.sh` (the existing
cascade entry point invoked from `/yoke:preserve` Phase 3.2) to add a
cross-archive topic-occurrence pass before the existing per-candidate
scoring loop:

1. Glob `${working_memory}/contracts/*.md` (in addition to the legacy
   single-file `${working_memory}/contracts.md` path the script reads
   today). Both shapes coexist: the legacy single-file path is
   preserved for backward compatibility; the new per-task glob is
   additive.
2. For each archive file, parse contract blocks delimited by
   `## Contract <id>` and extract the `topic:` field's quoted string
   verbatim. Use POSIX `awk` with a state machine matching the
   existing block-parser shape used elsewhere in the script.
3. Build an associative array keyed by the exact `topic:` string,
   value = list of `<archive-path>#<contract-id>` references where
   the topic appeared. Walking is purely deterministic; no LLM call.
4. When the script reaches the candidate-emission stage, every
   candidate that derives from a contract whose `topic:` appears in
   ≥ 2 distinct archives carries a new informational field:
   `occurrences: <int>` (the count from the associative array). The
   `traceability:` list is extended with every cross-archive
   reference.
5. Single-occurrence contracts are still emitted as candidates today
   (the existing scoring may rank them low); the new field is
   `occurrences: 1` for them — no behavioural change for that path.

Files touched:
- `lib/canonical-memory/canonization-criteria.sh` — additive parser +
  occurrence counter + new `occurrences:` YAML field; existing CLI
  flags and primary output schema preserved.
- No changes to the structured YAML schema's required fields — the
  new `occurrences:` field is informational and optional, so existing
  consumers (today: only `/yoke:preserve` Phase 3.2) keep working.

Patterns cited (no canonical-memory direct read at implementation
time; these are referenced via `/yoke:ask` if needed):
- [[yoke-pattern-model-c-governance]] — the cascade lives inside
  `/yoke:preserve` Phase 3.2; this task does not change Model C
  routing or PR behaviour.
- [[yoke-pattern-memory-model]] — working memory's per-task layout
  (`.yoke/contracts/<slug>.md`) is the input shape for the new
  enumeration.

Performance: the existing <5s budget on 1000 contract blocks must
hold. The new pass is O(N) over archive files and O(M) over contract
blocks; both fit within the budget.

## Validation

Self-tests under `tests/canonical-memory/` (matching the existing
test pattern for shell-script primitives):

1. **Backward-compatibility golden test.** A fixture working memory
   with a single `contracts.md` file and no `contracts/` directory.
   Expected stdout matches today's golden output byte-for-byte
   except for the addition of `occurrences: 1` lines. Asserts no
   regression for existing callers.
2. **Single-task per-archive test.** A fixture with one
   `.yoke/contracts/<slug-a>.md` containing one contract block.
   Expected: one candidate with `occurrences: 1` and a
   `traceability:` list containing the single archive reference.
3. **Cross-archive recurrence test.** A fixture with two archives
   (`<slug-a>.md` and `<slug-b>.md`) each containing a contract whose
   `topic:` strings are byte-identical. Expected: candidates emitted
   with `occurrences: 2`, and the `traceability:` list contains both
   archive references with their contract ids.
4. **Distinct-topic isolation test.** A fixture with two archives
   containing contracts whose `topic:` strings differ by even one
   character. Expected: each contract reports `occurrences: 1`. No
   coalescing.
5. **Performance test.** A synthesised fixture with 1000 contract
   blocks across 50 archives; the script must complete in <5s on a
   stock developer machine. Asserts the existing performance contract.

Each test is a `tests/canonical-memory/cascade-occurrences.test.sh`
script that builds the fixture in a tmpdir, invokes the cascade
script via `--working-memory <tmpdir>/.yoke`, and diffs stdout
against an expected YAML golden file. Existing test runners pick it
up.

## Acceptance criterion
