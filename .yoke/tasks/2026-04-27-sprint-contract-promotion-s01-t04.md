# Task 2026-04-27-sprint-contract-promotion-s01-t04 — Add a computational sensor that asserts the bidirectional-link invariant between every promoted concept and its named actor, and wire its readiness check into `/yoke:preserve` Phase 5

> Generated by `/yoke:tech-spec` (stage 3) from
> `.yoke/specs/2026-04-27-sprint-contract-promotion.md`. Status flips to `approved` when Trigger 2
> approves the parent spec.

## Story

The PRD identifies bidirectional-link drift as a real risk: a
promoted concept exists without its actor backlink, or vice versa,
and the graph silently degrades. Tests in t03 prove the helper
writes both edges atomically *at creation time*, but nothing
guarantees the invariant holds *after* a future `/yoke:preserve`
run, a `/yoke:compress` realignment, or a hand edit. The framework
already treats sensors as the standing-guard mechanism for
invariants that must hold across mutations
([[yoke-pattern-sensors]]). This task adds a computational sensor
that asserts the invariant after every `/yoke:preserve` write
involving a `kind/contract` concept, and wires its readiness check
into the existing sensor-acknowledgement flow so the contract is
visible to operators.

## Technical implementation

Three changes:

1. **The sensor itself.**
   `lib/sensors/contract-promotion-bidirectional.sh`. Pure bash. The
   sensor follows the structural-grep shape of the existing
   `lib/sensors/no-vibeflow-refs.sh` so review and onboarding are
   trivial. Behaviour:
   - Resolve the canonical-memory path via
     `lib/canonical-memory/resolve-memory.sh`.
   - For every file under `concepts/` whose frontmatter `tags:`
     contains both `yoke-framework` AND `kind/contract`, parse the
     `applies_to:` YAML list. For every actor name in that list,
     assert the file `actors/<actor-name>.md` exists AND its body
     contains at least one bare wikilink `[[<concept-slug>]]` where
     `<concept-slug>` is the concept's filename without the `.md`
     extension. Record one structured violation per missing edge.
   - For every file under `actors/`, scan the body for bare
     wikilinks. For every wikilink whose target resolves to a
     `concepts/<target>.md` file whose frontmatter `tags:` contains
     `kind/contract`, assert that concept's `applies_to:` list
     contains the actor's name. Record one structured violation per
     missing reverse edge.
   - Output (per [[yoke-pattern-sensors]]'s structured-output rule):
     each violation is a YAML block with `id` (the concept or actor
     filename), `location` (file path, optionally line range),
     `correction_instruction` (concrete fix: which file to edit and
     what link to add), `reference` (a wikilink to
     [[yoke-pattern-memory-model]] for the bidirectional rule).
     Success is silent (empty output, exit 0). Any violation → exit
     non-zero.
2. **The sensor's self-test.**
   `tests/sensors/contract-promotion-bidirectional.test.sh`. Mirrors
   the existing `tests/sensors/no-vibeflow-refs.test.sh` shape:
   plants a positive-fixture canonical memory (concept and actor
   with both edges) and asserts the sensor exits 0 with empty
   output; plants a negative-fixture (concept with `applies_to:`
   referencing an actor whose body lacks the backlink) and asserts
   the sensor exits non-zero with at least one structured violation
   block naming the offending file path. Same shape for the reverse
   case (actor wikilinks a `kind/contract` concept whose
   `applies_to:` does not list the actor).
3. **Wire the sensor into the readiness flow.** Add an entry for
   `contract-promotion-bidirectional` to whatever sensor catalog
   the framework's existing readiness flow relies on (probed by
   `/yoke:ack-sensors` when invoked in catalog mode). The catalog
   entry names the script path
   (`lib/sensors/contract-promotion-bidirectional.sh`), the sensor
   class (computational), the default tier (cheap), and the
   readiness check (file exists and is executable). The readiness
   check is the standard cheap probe; it does not run the full
   sensor.
4. **Optional: post-write invocation in `/yoke:preserve`.** Add a
   prose line to `skills/preserve/SKILL.md` Phase 5 (after the
   promoted-concept and actor-backlink writes complete, before the
   Phase 6 PR open) instructing the skill to run the new sensor
   against the staged canonical-memory state and abort the PR if
   the sensor fails. This is the eager check; the readiness flow
   (point 3) is the lazy/observability check. Both surfaces are
   useful: the eager check stops a bad write before it lands; the
   readiness check makes the invariant operationally visible.

Files touched:
- `lib/sensors/contract-promotion-bidirectional.sh` — new file.
- `tests/sensors/contract-promotion-bidirectional.test.sh` — new
  file.
- The sensor catalog wiring (location depends on the existing
  catalog file; the contract here is "the new sensor is discoverable
  via `/yoke:ack-sensors` catalog mode"). If catalog wiring requires

- `skills/preserve/SKILL.md` — Phase 5 prose extension; one or two

Patterns cited:
- [[yoke-pattern-sensors]] — computational sensors, structured
  output, success-is-silent, default tier "cheap".
- [[yoke-pattern-memory-model]] — bidirectional graph invariant the
  sensor enforces.

Performance budget: O(N) over `concepts/` files and `actors/` files;
target <2s on a canonical memory of 1000 concepts and 100 actors.
Falls within the existing computational-sensor performance envelope.

## Validation

The validation surface for this task IS the sensor's self-test plus
two integration checks:

1. **Self-test passes.** `bash
   tests/sensors/contract-promotion-bidirectional.test.sh` exits 0.
   This proves both fixture branches (positive: silent exit 0;
   negative: exit non-zero with a structured violation) work.
2. **Catalog readiness probe passes.** `bash lib/sensors/ack-sensors.sh
   --mode readiness` (or whichever existing entry-point exposes
   catalog readiness; the contract is the readiness mode reports the
   new sensor as reachable and executable).
3. **End-to-end with t03's fixture.** Running the sensor against the
   canonical-memory state produced by t03's
   `promoted-concept-backlink.test.sh` exits 0 (the bidirectional
   invariant is satisfied at write time, as t03 guarantees, so the
   sensor must agree). Running the sensor against a fixture where
   the actor backlink has been hand-deleted exits non-zero with a
   structured violation naming the missing reverse edge.

The integration test (item 3) is the load-bearing one — it proves
the sensor and the helper agree on the invariant. Discrepancy
between the two surfaces is a known failure mode for invariant
sensors; the test catches it before either change ships.

## Acceptance criterion

`bash tests/sensors/contract-promotion-bidirectional.test.sh` exits
0 covering both the positive and negative fixtures (silent pass and
structured failure respectively); AND running the sensor against a
canonical memory whose actor backlink has been removed produces a
non-zero exit with at least one structured violation YAML block whose
`location:` field cites the actor file and whose
`correction_instruction:` field names the missing wikilink to add.
