## Sprint objective

Refactor `hooks/verify-acceptance.sh` to resolve sensor metadata from the per-sensor file (no more inline contract metadata), parse the per-criterion `### Validation` block from the contract, expose `--max-time-cost` and `--max-token-cost` filters in place of the removed `--tier` flag, and dispatch computational sensors via shell while spawning inferential sensors via Task subagent. Strip the embedded "expensive when cheap green" heuristic from `agents/validator.md` so the Validator becomes a pure plan enforcer. Re-cast `agents/semantic-judge.md` as an instance of the new shape, with the verdict envelope extended to carry `confidence` and `supporting_quotes`. Implement the new `/yoke:consolidate-sensors` skill (no args, append-only body with citation, token_cost / time_cost recalibration, idempotent reentry). Wire the consolidation skill into `skills/implement/SKILL.md` teardown and add the `sensor_consolidation: review | auto | skip` key to the `.yoke/config.yaml` template. The 45 legacy sensor files remain on disk untouched in this sprint — runtime is fully ready, but real contracts still cannot be exercised end-to-end until Sprint 3 migrates the catalog.

## Sprint DoD

- `bash hooks/verify-acceptance.sh --max-time-cost 30` against a fixture with sensors of `time_cost` 10/30/60 invokes only the first two AND `bash hooks/verify-acceptance.sh --tier cheap` exits non-zero with a message citing the removal of the flag.
- `bash hooks/verify-acceptance.sh --criterion <id>` against a fixture with one computational and one inferential sensor produces a shell marker for the computational sensor AND a verdict JSON file under `.yoke/runtime/.judge-verdicts/cycle-0/` for the inferential sensor with the key `confidence` populated.
- `grep -cE '\b(tier|cheap|expensive)\b|^[[:space:]]*(runs|class|applies_to):' agents/validator.md` returns `0` AND `grep -c 'Per-criterion validation' agents/validator.md` returns at least `1`.
- A canonical sensor template for `semantic-judge` exists under `templates/sensors/` (or equivalent) with `type: inferential`, `agent: semantic-judge`, and the three Calibration sub-sections AND the verdict parser rejects a verdict with `"confidence": 1.5` AND rejects a verdict with `"status": "fail"` plus `"supporting_quotes": []`.
- `/yoke:consolidate-sensors` against a fixture with 1 sensor and 3 cycles of distinct evidence appends at least one bullet containing the substring `cycle ` and `fix-instruction ` AND a second invocation against the unchanged fixture results in zero diff vs the post-first-run state.
- `.yoke/config.yaml` template carries the key `sensor_consolidation` AND `skills/implement/SKILL.md` invokes `/yoke:consolidate-sensors` at teardown (verifiable by grep on the skill's body).

### Task 2026-04-30-sensor-harness-realignment-s02-t02

**Story:** Materialize the computational/inferential discriminator at runtime: shell for one, subagent (Task tool, lag-by-one) for the other. Without type-aware dispatch, inferential sensors remain shell-with-LLM-inside instead of becoming first-class agentic capability.

**Technical implementation:** Branch on `type` inside `hooks/verify-acceptance.sh` (or a new helper `lib/sensors/dispatch.sh` invoked by the hook, if inflation is excessive). For `type: computational`: run `command:` via `bash -c`, capture exit code + stdout + stderr, materialize the verdict JSON envelope `{ criterion, sensor, status (mapped from exit code), location: null, fix_instruction, evidence }` (no `confidence` / `supporting_quotes` — those are inferential-only fields). Persist at `.yoke/runtime/.judge-verdicts/cycle-<N>/<criterion>-<sensor>.json`. For `type: inferential`: extract `agent: <id>` from frontmatter; read `## Calibration` (Prompt + Rubric + Verdict schema) from the sensor file; materialize a Task spawn envelope (`subagent_type: <agent-id>`, prompt assembled from template + rubric + schema + diff under review, `run_in_background: true`); spawn via Task tool. The subagent writes its verdict to the deterministic path. Lag-by-one: cycle N spawns, cycle N+1 reads. Honor the `runtime.inferential_sensor_concurrency` cap from `.yoke/config.yaml`. Both branches converge on the same envelope (extended fields ignored when absent for computational). Honors `concepts/yoke-pattern-runtime-loop`, `concepts/yoke-pattern-roles`, `concepts/yoke-pattern-sensor-output`.

**Validation:** Fixtures: `tests/fixtures/dispatch/sensors/computational-echo.md` (`type: computational`, `command: touch /tmp/yoke-dispatch-marker-comp`), `tests/fixtures/dispatch/sensors/inferential-stub.md` (`type: inferential`, `agent: dispatcher-test-stub`, populated `## Calibration`); a stub agent file at `agents/dispatcher-test-stub.md` that emits a canonical verdict envelope. Run `verify-acceptance.sh --criterion <fixture-criterion>` and assert the marker file exists post-run (computational) plus the verdict JSON exists post-run with parseable JSON (inferential).

**Acceptance criterion:** After `bash hooks/verify-acceptance.sh --criterion fixture-criterion` against a fixture with one `type: computational` sensor (command `echo X`) and one `type: inferential` sensor, the captured stdout/log contains `X` (computational executed) AND a file at `.yoke/runtime/.judge-verdicts/cycle-0/fixture-criterion-<inferential-sensor-id>.json` exists post-run and parses as JSON containing the key `confidence`.

### Task 2026-04-30-sensor-harness-realignment-s02-t03

**Story:** Reduce the Validator to a pure plan enforcer: for each criterion, read the contract's `### Validation` interpretation guidance, fetch the matching verdicts, and decide pass/fail strictly per the guidance. Remove every embedded scheduling heuristic so policy stops being decided in two places (contract and Validator) with potentially divergent rules.

**Technical implementation:** Edit `agents/validator.md`. Strike the section describing the heuristic "expensive authorized when cheap green this cycle" and any reference to `runs:` history (the field no longer exists; durable knowledge lives in body sections of the sensor file, consumed as context only — never as a scheduling signal). Remove every `tier`, `cheap`, `expensive` token. Add a "Per-criterion validation protocol" section: for each active criterion in this cycle, read the `### Validation` block from the contract, then for each `(sensor-id, interpretation)` fetch the verdict at `.yoke/runtime/.judge-verdicts/cycle-<N>/<criterion>-<sensor>.json` and apply the interpretation guidance — the guidance is natural-language text describing how to read the verdict (e.g. "passes when exit code == 0" or "passes when `confidence` ≥ 0.8 and `status: pass`"). Overall criterion passes iff every sensor passes per its guidance. Preserve contract co-authoring on convergence. Preserve the verdict-emission protocol.

**Validation:** Inspect the updated agent file: assert no occurrences of legacy tokens, presence of "Per-criterion validation". Smoke validation downstream is exercised by `consolidation-stage.test.sh` in Sprint 3, which runs a real cycle and asserts the Validator applies interpretation guidance correctly against the new contract shape.

**Acceptance criterion:** `grep -cE '\b(tier|cheap|expensive)\b|^[[:space:]]*(runs|class|applies_to):' agents/validator.md` returns `0` AND `grep -c 'Per-criterion validation' agents/validator.md` returns at least `1`.

### Task 2026-04-30-sensor-harness-realignment-s02-t05

**Story:** Stop runtime learnings from evaporating. Each `/yoke:implement` produces dozens of fix-instructions, calibration drifts and durations; without this skill, all of it disappears at loop exit. The skill distills evidence (LLM, not regex) and persists it back into the sensor files: append-only body bullets with mandatory citation (which doubles as idempotence key) and frontmatter cost recalibration.

**Technical implementation:** Create `skills/consolidate-sensors/SKILL.md` (Yoke-skill structure: pre-flight, body, output contract, anti-patterns, see-also). Pre-flight: source `lib/working-memory/paths.sh`, read `.yoke/runtime/.current` (abort if missing), require presence of `.yoke/runtime/.judge-verdicts/`, read `.yoke/config.yaml` for the `sensor_consolidation` key (`review` | `auto` | `skip`, default `review`). No arguments. Evidence collection: read every cycle in `.yoke/runtime/.judge-verdicts/cycle-*/`, parse every verdict, read `.yoke/runtime/progress.md` for cycle outcomes and durations, accumulate `(sensor-id, evidence)` tuples grouped by sensor. Distillation per sensor (the agentic node): for each involved sensor, spawn a sub-call carrying the current sensor file content + the collected evidence list, instruct production of candidate bullets for `## Known issues` / `## Frequent errors` / (inferential) `## Calibration`, each citing evidence as `(cycle N, fix-instruction X)`. Idempotent reentry: before inserting any candidate bullet, grep the sensor file body for the citation; skip the bullet if already present. Cost recalibration: simple mean of observed runs per sensor for both `token_cost` and `time_cost`; only update the frontmatter when the delta vs the declared value is greater than 5% (avoids trivial oscillation). Diff-review by mode: `review` renders the cumulative diff (body appends + cost deltas) to the user with a 4-option prompt (`accept all` / `accept partial` / `skip` / `cancel`), `auto` applies directly, `skip` is a silent no-op. Writes via Edit tool, body appends inserted at the end of the target section before the next `## ` header or EOF; cost updates via Edit on the frontmatter line. Atomicity: per-file Edit calls; failure on one file does not roll back earlier writes but reports non-zero exit. Final stdout summary: `<N> sensors updated, <M> bullets added, <K> cost values recalibrated, <S> skipped due to no delta`. Honors `concepts/yoke-pattern-skills-structure`, `concepts/yoke-pattern-runtime-loop` (consume runtime artifacts), `concepts/yoke-conventions` ("blueprints wrapping agentic nodes" — distillation is the only agentic node; the rest is deterministic).

**Validation:** Fixture under `tests/fixtures/consolidate/`: `.yoke/runtime/.current` pointing at a fixture slug, `.yoke/runtime/.judge-verdicts/cycle-{0,1,2}/` with three cycles of verdicts (mixed pass/fail across two sensors — one computational, one inferential), `.yoke/runtime/progress.md` with synthetic durations, two new-schema sensor files with curated initial body bullets, `.yoke/config.yaml` with `sensor_consolidation: auto`. Run 1: invoke skill, snapshot post-run state. Run 2: invoke again without changing evidence; assert byte-identical state vs post-run-1. Validation surface is exercised by the permanent `consolidation-stage.test.sh` test in Sprint 3.

**Acceptance criterion:** After `/yoke:consolidate-sensors` (mode `auto`) against a fixture with one sensor and three cycles of distinct evidence yielding at least one fix-instruction, the sensor file gains at least one new bullet containing the substring `cycle ` and `fix-instruction `; running the skill a second time without changing evidence results in a byte-identical state vs the post-first-run state (diff returns empty).

### Task 2026-04-30-sensor-harness-realignment-s02-t06

**Story:** Plumb the consolidation skill into the loop's teardown so it runs automatically on every successful or paused `/yoke:implement`, and surface the user's policy choice (auto / review / skip) via a stable config key. Without integration, the skill is dormant and the central PRD invariant — "learning is distilled at the end of each /yoke:implement" — does not hold.

**Technical implementation:** Two changes. (1) Extend `templates/yoke-config.yaml.template` (or the equivalent template — verify via `find templates -name '*config*'`) to include `sensor_consolidation: review   # review | auto | skip` with an inline comment describing the three modes; default `review` so opting into automatic writes is explicit. Update any documentation that lists `.yoke/config.yaml` keys. (2) Edit `skills/implement/SKILL.md` teardown stage (after convergence or hard-bound, before final exit). Detect availability of the Skill tool; when available, invoke `/yoke:consolidate-sensors` via Skill (the skill itself reads the config and short-circuits to `skip` when configured). When unavailable, print a clear instruction telling the user to run the skill manually. Non-blocking: a failure inside consolidation does not roll back the implement's exit (the skill itself handles `skip` cleanly). Position the call after the final `progress.md` persistence so the consolidation reads the up-to-date durations.

**Validation:** Fixtures under `tests/fixtures/consolidation-teardown/`: three `.yoke/config.yaml` variants (`mode-skip/`, `mode-auto/`, `mode-review/` with stubbed input). Smoke run of `/yoke:implement` with forced convergence after one cycle; assert teardown invokes the skill; in `skip` mode the catalog is byte-identical pre/post; in `auto` mode at least one sensor file is modified.

**Acceptance criterion:** In a fixture with `.yoke/config.yaml` carrying `sensor_consolidation: skip`, after a `/yoke:implement` run reaches teardown, `git diff --quiet .yoke/sensors/` exits `0` (no modification); in an equivalent fixture with `sensor_consolidation: auto` and valid synthetic evidence, `git diff --name-only .yoke/sensors/` returns at least one path.
