### Task 2026-05-03-generate-sprints-skill-s02-t02

**Story:** As a Yoke user invoking `/yoke:generate-sprints`, I want pre-flight to fail fast with a clear stderr message when any prerequisite is missing, so I never run the synthesis stage on a half-configured project. (Realizes: US-003)

**Technical implementation:** Inside `skills/generate-sprints/SKILL.md`'s Pre-flight section, codify five sequential gate checks. (1) `source <plugin_dir>/lib/yoke-prelude.sh && yoke_require_provider || exit 1` — provider hard break (FR-6). (2) `source <plugin_dir>/lib/working-memory/paths.sh` then `slug="$(wm_active_slug)"` — aborts non-zero with the helper's existing `no active task` stderr if `.yoke/runtime/.current` is missing. (3) `wm_prd_path "$slug"` exists and frontmatter `status` is `approved` (lift the existing approval-status helper from `/yoke:tech-spec` body into a shared lib if not already there — `lib/working-memory/check-approved.sh`). (4) `wm_spec_path "$slug"` exists and is approved. (5) `wm_acceptance_criteria_path "$slug"` exists and is approved. Each failure surfaces a `wm:`-prefixed stderr naming the missing or unapproved file path and the action the user should take next (e.g., `wm: spec missing or unapproved at <path>. Run /yoke:tech-spec first.`). The diagnostics are exact strings, not formatted templates — they get asserted character-for-character in the smoke test.

**Validation:** `tests/smoke/generate-sprints-preflight.test.sh` exercises each negative branch via fixture directories that selectively omit one prerequisite at a time. Each branch asserts the skill exits non-zero AND stderr contains the documented exact substring. The test exits 0 only when all five negative branches pass.

**Acceptance criterion:** `bash tests/smoke/generate-sprints-preflight.test.sh` exits 0 and stdout contains exactly five lines starting with `PASS:`.

### Task 2026-05-03-generate-sprints-skill-s02-t03

**Story:** As the synthesis stage of `/yoke:generate-sprints`, I need to read the approved spec and the approved acceptance-criteria into structured intermediates that downstream stages can consume, so that synthesis works against parsed data and not raw markdown. (Realizes: US-003)

**Technical implementation:** Add helper functions to a new file `lib/generate-sprints/parse-inputs.sh`. Function `parse_acceptance_criteria <ac-path>` reads the AC file and emits a JSON object on stdout: `{"ucs": [{"id": "UC-1", "name": "...", "dod": [...], "criteria": [...], "frs": [...], "sensors": [...]}]}`. Use `awk` (or a portable mini-parser) to walk the file and extract each `### UC-<n>` block plus its five sub-field bullet lists. Function `parse_spec_architecture <spec-path>` reads the spec file and emits a JSON object: `{"objective": "...", "contracts": [...], "dependencies": {...}}`. Both helpers exit non-zero on parse failure with a `wm:`-prefixed stderr line. The `/yoke:generate-sprints` skill's Read-inputs stage invokes both helpers and stores their stdout in temporary files under `.yoke/runtime/.generate-sprints-tmp/` (gitignored) for later stages.

**Validation:** Unit-style smoke `tests/smoke/parse-inputs.test.sh` runs both helpers against the happy-path fixture and asserts: (a) `parse_acceptance_criteria` stdout is valid JSON parseable by `python3 -c 'import json,sys; json.load(sys.stdin)'`; (b) the `ucs` array length equals the count of `### UC-` headings in the fixture file; (c) the negative case (malformed UC block missing `**Definition of done:**`) exits non-zero with stderr `wm: malformed UC block`.

**Acceptance criterion:** `bash tests/smoke/parse-inputs.test.sh` exits 0 and the test prints `PASS: ucs parsed N=<count>` for the happy-path fixture.
