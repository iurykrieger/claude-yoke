## Sprint objective

Wire the Sprint-1 infrastructure into `/yoke:implement` and run the
council protocol end-to-end for the first time. Each cycle now has
three explicit phases: Phase A spawns three persona Tasks in parallel
and waits on the file-marker sync barrier; Phase B runs up to the
configured number of réplica rounds, detecting quiescence
deterministically and invoking the new contradiction-detection
arbiter subagent only when a round produced at least one réplica;
Phase C either enters the next cycle on consensus or fires Trigger 4
with a generalized N=3 escalation message on unresolved divergence.
The v2.x runtime is gated behind a feature flag for the duration of
this sprint and removed at sprint end (no parallel paths
post-cutover). Persona prompts at this point are minimal stubs
sourced from Sprint 1 agent files — full retooling lands in Sprint 3.

## Sprint DoD

- `/yoke:implement`'s cycle loop has three named phases (A, B, C) reflected in `progress.md` cycle entries.
- A dogfood fixture cycle with three engineered persona stubs runs end-to-end, produces three slices, merges them, and exits with status `consensus` when slices carry no contradictions.
- The same fixture with engineered direct contradiction between two slices exits with status `trigger-4` and writes a Trigger-4 message to the existing escalation surface.

## Tasks

### Task 2026-05-01-agent-council-s02-t01

**Story:** as `/yoke:implement` opening a cycle under v3.0, I spawn three persona Tasks in parallel for Phase A and block until every persona has written its phase-A-done file marker before opening Phase B.

**Technical implementation:** rewrite the cycle entry path inside `skills/implement/SKILL.md` and `lib/runtime/cycle.sh` (existing helper, extended). On cycle entry: invoke `clear-markers` from `lib/runtime/sync-barrier.sh` to clear any leftover markers from a prior interrupted cycle; call the persona loader's `validate-all agents/` (Sprint 1 t03) — fail-fast on any invalid persona; then issue three Task invocations in a single tool-use block, one per persona, each prompted with the persona's body template + the cycle's working set + an instruction to write its slice and its phase-A-done marker before exiting. Block on Task completion (Task semantics give the wait for free); then call `wait-all` from `lib/runtime/sync-barrier.sh` as a defensive guard with a generous timeout — failures here are sensor-bug or harness-bug, not normal flow. Phase A's progress is logged to `progress.md` as a single `cycle-N phase-A spawned` entry with the three Task invocation IDs.

**Validation:** `tests/runtime/phase-a-orchestration.test.sh` exercises `/yoke:implement` against a fixture working set with three persona stubs that each write their slice + marker; the test asserts all three slices are present in `.yoke/runtime/cycles/0/` and all three markers exist in `.yoke/runtime/`. A second engineered fixture has one persona stub fail to write its marker; the test asserts `wait-all` times out with a `wm:`-prefixed diagnostic naming the missing marker.

**Acceptance criterion:** running `/yoke:implement` against `tests/runtime/fixtures/working-set-three-personas/` produces exactly `.yoke/runtime/cycles/0/sr-eng.md`, `.yoke/runtime/cycles/0/sr-qa.md`, `.yoke/runtime/cycles/0/sr-staff.md` AND `tests/runtime/phase-a-orchestration.test.sh` exits 0.

### Task 2026-05-01-agent-council-s02-t02

**Story:** as `/yoke:implement` after Phase A, I run Phase B as a bounded loop of réplica rounds with deterministic quiescence detection and an LLM contradiction-detection arbiter call between rounds that produced réplicas, terminating on consensus or escalating Trigger 4 on cap exhaustion.

**Technical implementation:** introduce `lib/runtime/council.sh` exposing `phase-b <slug> <cycle-N>`. The function loops up to the configured `council_rounds_max` (read from `.yoke/config.yaml :: overrides.runtime.council_rounds_max`, default 3): for each round R, prompt every persona via three parallel Task calls to read the merged view from the prior round's state and append its `## Phase B round R — readings` and optional `## Phase B round R — réplica` sections to its slice; after the round, count newly-appended réplica sections; if zero (quiescence), exit with `consensus`; if at least one, invoke `agents/council-arbiter.md` (Sprint 2 t03) with the merged view + the round's réplicas, parse the JSON verdict; if the verdict declares consensus, exit; if the cap is reached, exit with `trigger-4` (handed to Sprint 2 t04 for escalation rendering). Round counter, per-round réplica counts, and arbiter verdict summary are appended to `progress.md`.

**Validation:** `tests/runtime/council-phase-b.test.sh` exercises the three branches (immediate quiescence, arbiter-detected consensus after one round, cap-exhausted divergence). A round-cap test at `tests/runtime/round-cap-config.test.sh` flips `council_rounds_max` to 1 and 5 in fixture configs and asserts the loop respects the override.

**Acceptance criterion:** `tests/runtime/council-phase-b.test.sh` exits 0 across the three branch fixtures AND `tests/runtime/round-cap-config.test.sh` exits 0.

### Task 2026-05-01-agent-council-s02-t03

**Story:** as `/yoke:implement` between réplica rounds that produced disagreement, I spawn a dedicated contradiction-detection arbiter subagent that reads the merged view + round réplicas and emits a structured JSON verdict the council loop can branch on.

**Technical implementation:** create `agents/council-arbiter.md` with the Claude Code agent frontmatter (`name: council-arbiter`, `description`, `tools: Read`). The body specifies the arbiter's prompt: read the merged view + the round's réplica subset; classify each pairwise disagreement per the dispute rubric specified in the spec's `### Contradiction-detection arbiter` contract (direct contradiction counts; importance disagreement counts; tone-only does NOT count); emit exactly one JSON object matching the schema in the spec. The arbiter is read-only; it does not write any file. `lib/runtime/council.sh` (Sprint 2 t02) parses the JSON via `jq`, validates required fields, and uses the consensus boolean plus the contradictions count to drive the loop. Cite `concepts/yoke-pattern-roles` and `concepts/yoke-conventions` (structured-sensor-output contract) in the arbiter file's body header.

**Validation:** four engineered fixtures under `tests/runtime/fixtures/arbiter/`: `consensus.cycle/`, `direct-contradiction.cycle/`, `importance-disagreement.cycle/`, `tone-only.cycle/`. Each fixture is a fully-built cycle directory; `tests/sensors/council-arbiter.test.sh` invokes the arbiter against each and asserts the JSON output matches the expected verdict (consensus true/false, contradiction count, persona pairs cited). The sensor's expected output lives alongside each fixture as `expected.json`.

**Acceptance criterion:** `tests/sensors/council-arbiter.test.sh` exits 0 across all four fixtures AND on the `direct-contradiction.cycle/` fixture the arbiter output parses to a JSON object with consensus false and exactly one entry in contradictions.

### Task 2026-05-01-agent-council-s02-t04

**Story:** as the user when the council exhausts its round cap with unresolved disagreements, I receive a single Trigger-4 escalation message that lists every unresolved persona pair, the round's arbiter verdict, and a directive to ratify a verdict or supply a third resolution.

**Technical implementation:** generalize the existing Trigger-4 escalation surface (today: 2-party Implementation↔Validation arbitration). Add `lib/runtime/trigger-4.sh::render` which takes the merged view + the last arbiter verdict and emits the escalation message per the spec's `### Trigger 4 escalation message` contract (markdown render, persona pairs listed, directive line). The user's reply is captured by the existing parser; extend it to accept a persona name as a verdict ratification (`ratify sr-staff`) and a free-form text as a third resolution. Document the new escalation shape under `concepts/yoke-pattern-human-triggers` via an inline reference comment in the rendered file; full pattern doc rewrite is Phase 5 / Sprint 4. Update `lib/ralph-loop/escalate.sh` callers to wire the new render path.

**Validation:** `tests/sensors/trigger4-escalates-on-divergence.test.sh` engineers a cycle that exhausts the round cap with two unresolved contradictions; runs `/yoke:implement` against the fixture; asserts the escalation message is written to the existing surface and contains: each persona pair listed, the arbiter's last verdict summary, and the directive line. A second test asserts user replies `ratify sr-qa` and `rework needed: <text>` are parsed and applied as the cycle's resolution.

**Acceptance criterion:** `tests/sensors/trigger4-escalates-on-divergence.test.sh` exits 0 AND the rendered escalation message for the fixture contains every persona pair name (e.g. `sr-eng × sr-qa`, `sr-qa × sr-staff`) when both pairs are flagged contradictions.
