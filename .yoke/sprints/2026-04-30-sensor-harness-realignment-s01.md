## Sprint objective

Ratify the new sensor-file schema (frontmatter `type` / `token_cost` / `time_cost` / `command`-or-`agent`; body `## How to run` / `## Known issues` / `## Frequent errors` / `## Calibration` for inferential) in `templates/sensor.md`; ratify the per-criterion `### Validation` sub-section in `templates/acceptance-contract.md`; refactor `lib/sensors/ack-sensors.sh` so its parser, body lint and upsert modes accept only the new schema and reject the legacy fields; implement `lib/sensors/migration-audit.sh` to produce a triage-ready report mapping the 45 existing sensors to `still-referenced` vs `orphan-candidate-for-delete`. Sprint exit state is internally consistent at the templates and tooling layer — runtime hooks and the catalog are not yet touched, and `verify-acceptance.sh` is intentionally left on the legacy schema until Sprint 2.

## Tasks

### Task 2026-04-30-sensor-harness-realignment-s01-t01

**Story:** Establish the canonical sensor-file template at the new schema (frontmatter discriminator `type`, dual costs `token_cost`/`time_cost`, mutually exclusive `command`/`agent`, fixed body shape with inferential-only `## Calibration` sub-sections) so every downstream task — the parser refactor, the body lint, the upsert mode, and the Sprint 3 big-bang migration — has a single source of truth to validate against.

**Technical implementation:** Full rewrite of `templates/sensor.md`. Header comment cites `.yoke/prds/2026-04-30-sensor-harness-realignment.md` (drop the legacy `.vibeflow/...` reference) and re-states the "knowledge base, not execution log" invariant. Frontmatter carries `id`, `type` (computational | inferential), `token_cost` (int, ≥ 0), `time_cost` (int, ≥ 1), `command` (only when computational), `agent` (only when inferential), with inline comments documenting the `command ⊕ agent` exclusivity. Body has the four mandatory headers `## How to run`, `## Known issues`, `## Frequent errors` (with bullet-format hint `- <pattern>: <fix>`), `## Calibration` (only for inferential, with sub-sections `### Prompt`, `### Rubric`, `### Verdict schema`). No `class:`, `tier:`, `applies_to:`, `runs:` placeholders. Honors `concepts/yoke-pattern-plugin-structure` (templates live under `templates/`) and the manifesto invariant of structured sensor output.

**Validation:** Visual inspection of the rewritten template against the spec's "Sensor file frontmatter" and "Sensor file body shape" contracts. Confirm presence of the four headers, the three sub-headers under `## Calibration`, and the absence of legacy field tokens via grep. Smoke check: feed the template (or a sensor file derived from it) into the parser refactored in t03 and confirm readiness exits 0.

**Acceptance criterion:** `grep -lE '^(class|tier|applies_to|runs):' templates/sensor.md` produces empty output AND `grep -cE '^## (How to run|Known issues|Frequent errors|Calibration)$' templates/sensor.md` returns `4` AND `grep -cE '^### (Prompt|Rubric|Verdict schema)$' templates/sensor.md` returns `3`.

### Task 2026-04-30-sensor-harness-realignment-s01-t02

**Story:** Move the sensor-to-criterion binding into the Acceptance Contract: each criterion in the contract template carries a `### Validation` sub-section listing which sensors gate it and how to interpret their feedback. Inline sensor metadata (command, class, tier) is removed from the contract — it lives in the per-sensor file.

**Technical implementation:** Edit `templates/acceptance-contract.md`. Remove the legacy `## Sensors registry` section and any inline `class:` / `tier:` references; add a clear note that dispatch metadata lives in `.yoke/sensors/<id>.md`. Under each `### Criterion <id>`, add a `### Validation` sub-section in the form `- **<sensor-id>** — <interpretation guidance>` with at least one bullet required (a criterion with zero sensors is undecidable). Update the example block to show one criterion gated by one computational sensor and one criterion gated by a mixed (computational + inferential) pair — for both, the bullets describe interpretation only, never invocation. Honors `concepts/yoke-pattern-plugin-structure` and preserves the binding-spec invariant from the manifesto.

**Validation:** Inspect the updated template against the spec's "Acceptance Contract per-criterion validation block" contract. Smoke check downstream in Sprint 2 (parser of `verify-acceptance.sh` reads `### Validation` blocks from contracts authored against this template).

**Acceptance criterion:** `grep -c '^## Sensors registry' templates/acceptance-contract.md` returns `0` AND `grep -cE '^### Validation$' templates/acceptance-contract.md` returns at least `1` AND `grep -qE '^[[:space:]]+(class|tier):' templates/acceptance-contract.md` returns non-zero (no matches).

### Task 2026-04-30-sensor-harness-realignment-s01-t03

**Story:** Make the sensor-catalog parser the gate that enforces the new schema everywhere. `ack-sensors.sh` is the canonical entry point for catalog validation; without rewriting its parser, every new-schema sensor file would be rejected at readiness and downstream tasks would have nothing to validate against.

**Technical implementation:** Edit `lib/sensors/ack-sensors.sh`. Remove parsing for `class:`, `tier:`, `applies_to:`, `runs:`; any file carrying these fields fails readiness with a message citing the legacy field and pointing at migration to `type:` / `token_cost:` / `time_cost:`. Add a frontmatter parser (awk or yq inline, matching the existing script's style) that validates `id` (regex `^[a-z0-9][a-z0-9-]*$`), `type` (∈ `{computational, inferential}`), `token_cost` (int, ≥ 0), `time_cost` (int, ≥ 1), `command` (required iff `type: computational`), `agent` (required iff `type: inferential`). Reuse the existing `fail_check` / `pass_check` helpers; emit path:line plus correction-instruction on every failure. Preserve the `catalog` mode (parser-agnostic) and the script's overall mode-dispatch structure. Honors `concepts/yoke-pattern-sensor-output` (path + violation + correction) and the manifesto's structured-sensor-output invariant.

**Validation:** Create fixtures under `tests/fixtures/sensors/parser/`: `valid-computational.md`, `valid-inferential.md`, `legacy-class.md`, `legacy-tier.md`, `legacy-applies-to.md`, `legacy-runs.md`, `missing-type.md`, `missing-command-comp.md`, `missing-agent-inf.md`, `invalid-token-cost.md`. Run `bash lib/sensors/ack-sensors.sh --mode readiness <fixture>` against each and assert the expected exit code (0 for valid, non-zero for invalid). The fixtures are reused by the permanent `body-lint.test.sh` test in Sprint 3.

**Acceptance criterion:** `bash lib/sensors/ack-sensors.sh --mode readiness tests/fixtures/sensors/parser/valid-computational.md` exits `0` AND `bash lib/sensors/ack-sensors.sh --mode readiness tests/fixtures/sensors/parser/legacy-class.md` exits non-zero with stderr containing the substring `class:`.

### Task 2026-04-30-sensor-harness-realignment-s01-t04

**Story:** Enforce body shape strictly so the sensor file becomes a usable knowledge base, not free-form prose. Without strict lint, authors drift into unsearchable ad-hoc text and the PRD's central value (curated knowledge per sensor) erodes.

**Technical implementation:** Extend `lib/sensors/ack-sensors.sh` `readiness` mode. After the frontmatter parser (t03) validates the type-driven invariants, run body checks: the headers `## How to run`, `## Known issues`, `## Frequent errors` must be present and the block under each must be non-empty (whitespace-stripped length > 0); under `## Frequent errors`, every non-blank line must match `^- [^:]+: .+$` (single-line `- pattern: fix`); blank lines are accepted as separators and HTML comments are skipped; multi-line bullets are rejected in v0. For `type: inferential`, `## Calibration` must be present along with `### Prompt`, `### Rubric`, `### Verdict schema`, each non-empty; for `type: computational`, `## Calibration` must be absent (warning, not fail; flagged via `warn_check`). Implementation via awk multi-pass or a lightweight bash parser that extracts blocks per header.

**Validation:** Add fixtures under `tests/fixtures/sensors/body-lint/`: `valid-comp.md`, `valid-inf.md`, `missing-how-to-run.md`, `missing-known-issues.md`, `missing-frequent-errors.md`, `empty-known-issues.md`, `malformed-bullet-frequent-errors.md`, `missing-prompt-on-inferential.md`, `missing-rubric-on-inferential.md`, `missing-verdict-on-inferential.md`, `calibration-on-computational.md`. Each fixture exercises a specific failure mode; the permanent `body-lint.test.sh` test in Sprint 3 reuses the fixtures.

**Acceptance criterion:** `bash lib/sensors/ack-sensors.sh --mode readiness tests/fixtures/sensors/body-lint/missing-prompt-on-inferential.md` exits non-zero with stderr containing the substring `### Prompt` AND `bash lib/sensors/ack-sensors.sh --mode readiness tests/fixtures/sensors/body-lint/malformed-bullet-frequent-errors.md` exits non-zero with stderr containing the substring `Frequent errors`.

### Task 2026-04-30-sensor-harness-realignment-s01-t05

**Story:** Update the upsert mode so it materializes new-schema sensor files from the contract registry while preserving any curated content already on disk. Without this, the Sprint 3 big-bang migration has no scaffolding tool, and authors cannot produce a fresh sensor file with sane defaults.

**Technical implementation:** Rewrite the `upsert` branch in `lib/sensors/ack-sensors.sh`. Walk every Acceptance Contract under `.yoke/acceptance-contracts/`, extract every `sensor: <id>` reference (matching the format introduced in t02), and produce a deduplicated set of ids. For each id missing under `.yoke/sensors/<id>.md`, create the file from `templates/sensor.md` (ratified in t01) with substitutions: `<kebab-case-id>` → the id; `<computational | inferential>` → `computational` by default (no contract-level type hint in v0); `<int>` placeholders → conservative defaults (`token_cost: 0` and `time_cost: 30` for computational; `token_cost: 1000` and `time_cost: 60` for inferential when explicitly chosen); `command` / `agent` → empty with a `<!-- TODO: fill -->` placeholder. The body sections initialize empty with `<!-- TODO: fill -->` markers — readiness (t04) will warn until they are populated. For each id with a file already present, reparse the frontmatter via t03's parser; if any required field is missing or body lint surfaces a structural defect, emit a warning citing the gap **without modifying the file** — the human curates manually. Curated content (Known issues bullets, Frequent errors entries, Calibration prompt) is preserved verbatim because upsert never touches an existing file. Update the `--mode upsert` help message accordingly.

**Validation:** Fixtures under `tests/fixtures/sensors/upsert/`: a `contracts/example-contract.md` referencing three ids (`existing-curated`, `new-comp`, `new-inf`); a `sensors/existing-curated.md` carrying a curated `## Known issues` bullet (e.g. "- Times out under 30s on cold DB"). Run `bash lib/sensors/ack-sensors.sh --mode upsert` (or a variant accepting a root override). Assert: `new-comp.md` and `new-inf.md` exist with the expected frontmatter; `existing-curated.md` is byte-identical to its pre-run snapshot.

**Acceptance criterion:** After `bash lib/sensors/ack-sensors.sh --mode upsert` against the upsert fixture, `diff tests/fixtures/sensors/upsert/sensors/existing-curated.md.snapshot tests/fixtures/sensors/upsert/sensors/existing-curated.md` exits `0` (byte-identical) AND `tests/fixtures/sensors/upsert/sensors/new-sensor.md` exists post-run and contains the token `type:` in its frontmatter.

### Task 2026-04-30-sensor-harness-realignment-s01-t06

**Story:** Provide an audit script that maps every `sensor: <id>` reference in the existing contracts against the on-disk catalog, distinguishing `still-referenced` ids from `orphan-candidate-for-delete` ids. Without this audit, the Sprint 3 big-bang migration is a blind decision and the orphan-stranded-sensor risk from the PRD becomes load-bearing.

**Technical implementation:** Create `lib/sensors/migration-audit.sh` (executable). Read every `.yoke/acceptance-contracts/*.md` and extract every `sensor: <id>` reference using two patterns: the new shape (bullet `- **<sensor-id>** —` under `### Validation`, post-t02) and the legacy shape (line `sensor: <id>` under `## Sensors registry`, pre-migration). Read the on-disk catalog under `.yoke/sensors/*.md` and produce two sets: `still-referenced` (catalog ∩ referenced), `orphan-candidate-for-delete` (catalog \ referenced). Detect dangling references (referenced \ catalog) and emit them with a non-zero exit code so a contract pointing at a missing sensor is surfaced before any destructive migration. Print a parseable, fixed-column tabular report on stdout with a trailing summary line `# <total> total: <X> still-referenced, <Y> orphan-candidate, <Z> dangling`. Honors the structured-sensor-output convention.

**Validation:** Fixture under `tests/fixtures/sensors/migration-audit/`: a `contracts/example.md` referencing 3 ids (`keep-1`, `keep-2`, `delete-1`); 5 sensor files in the catalog (`keep-1.md`, `keep-2.md`, `delete-1.md`, `orphan-1.md`, `orphan-2.md`). Run with `--root` override and assert: 3 `still-referenced` lines, 2 `orphan-candidate-for-delete` lines, 0 `dangling-reference` lines, exit 0. A second fixture with a contract referencing a `ghost-sensor` (not on disk) exercises the dangling path and asserts non-zero exit.

**Acceptance criterion:** `bash lib/sensors/migration-audit.sh --root tests/fixtures/sensors/migration-audit/` prints exactly `3` lines containing `still-referenced` AND exactly `2` lines containing `orphan-candidate-for-delete` AND exits `0`.
