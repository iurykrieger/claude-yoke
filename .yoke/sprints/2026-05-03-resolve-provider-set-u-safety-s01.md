`_yoke_provider_plugin_dir` helper survives `bash -c "set -u; source ..."`
from any working directory, plus a regression smoke test wired into

regression test guards every future PR.

### Task 2026-05-03-resolve-provider-set-u-safety-s01-t01

**Story:** As a Yoke skill prompt author dispatching `bash -c "set -u; source <plugin>/lib/canonical-memory/resolve-provider.sh; yoke_resolve_provider"` from the user's project root, the helper resolves the plugin root via `BASH_SOURCE[0]` (when set) or `YOKE_PLUGIN_DIR` (when set), without ever tripping `parameter not set`.

**Technical implementation:** Edit `lib/canonical-memory/resolve-provider.sh` `_yoke_provider_plugin_dir` (lines 49–57). Reorder the deref so the `YOKE_PLUGIN_DIR` fast-path stays first (already correct). Replace the bare `${BASH_SOURCE[0]}` at line 55 with the safe form `${BASH_SOURCE[0]:-}`. Capture the result into a local first; if non-empty, derive `script_dir` and `printf` the plugin root as today. Do **not** modify the file's `set -uo pipefail` declaration. Keep the helper signature, contract, and stdout shape byte-equivalent for every previously-succeeding input. Touched files: `lib/canonical-memory/resolve-provider.sh` only.

**Validation:** Manual reproduction from a temp directory containing a fixture `.yoke/config.yaml` (provider name registered in `providers.yaml`): `bash -c "set -u; source <abs-path-to-plugin>/lib/canonical-memory/resolve-provider.sh; yoke_resolve_provider; printf '%s' \"$YOKE_PROVIDER_NAME\""` — prints the provider name, no stderr noise, exit 0. Same dispatch executed from inside the plugin root (existing happy path) prints the same provider name. `shellcheck lib/canonical-memory/resolve-provider.sh` exits 0.

**Acceptance criterion:** Running `bash -c "set -u; source <plugin>/lib/canonical-memory/resolve-provider.sh; yoke_resolve_provider"` from outside the plugin root with a valid host-project `.yoke/config.yaml` exits 0 and prints zero occurrences of `BASH_SOURCE[0]: parameter not set` on stderr.

### Task 2026-05-03-resolve-provider-set-u-safety-s01-t02

**Story:** As a Yoke skill prompt author who accidentally invokes the helper from a context where `BASH_SOURCE[0]` is unset and `YOKE_PLUGIN_DIR` is not exported, the helper aborts with a single clear message naming both fallback variables and pointing at the next step.

**Technical implementation:** Inside `_yoke_provider_plugin_dir`, after the `YOKE_PLUGIN_DIR:-` fast-path and the new `BASH_SOURCE[0]:-` slow-path, add a final guard: if both are empty, emit to stderr `wm: cannot resolve plugin root — neither YOKE_PLUGIN_DIR nor BASH_SOURCE[0] is set. Export YOKE_PLUGIN_DIR=<plugin path> before sourcing.` and `return 5`. Update the calling chain so that `_yoke_providers_yaml_path` propagates the failure (returning early on non-zero from `_yoke_provider_plugin_dir`) and `yoke_resolve_provider` surfaces exit code 5 with the plugin-root error preceding the existing `wm: providers.yaml missing from plugin root` line — they are mutually exclusive failure modes; only the first applies. Document the new failure mode in the file's header comment (the "Exit codes" block) by adding one bullet under exit code 5: "`5` — provider name unknown to `providers.yaml` **OR** plugin root unresolvable (neither `YOKE_PLUGIN_DIR` nor `BASH_SOURCE[0]` set)."

**Validation:** Synthetic test: `bash -c "set -u; unset YOKE_PLUGIN_DIR; BASH_SOURCE=(); source <abs-path>/resolve-provider.sh; yoke_resolve_provider" 2>&1` exits 5 and stderr contains the literal substrings `wm:`, `YOKE_PLUGIN_DIR`, and `BASH_SOURCE[0]`. Existing exit-code paths (3 — config missing; 4 — provider key missing; 5 — provider not registered) keep their stderr text byte-for-byte (regress with `grep` against the pre-patch error strings).

**Acceptance criterion:** When neither `BASH_SOURCE[0]` nor `YOKE_PLUGIN_DIR` is set, `yoke_resolve_provider` returns exit code 5 and prints exactly one `wm: `-prefixed stderr message naming both variables.
