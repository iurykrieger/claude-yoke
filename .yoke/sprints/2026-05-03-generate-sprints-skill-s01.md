# Sprint 01 of 04: Foundation — templates and AC-skill reshape

> Generated by `/yoke:tech-spec` (stage 3) from
> `.yoke/specs/2026-05-03-generate-sprints-skill.md`. Status flips to

## Sprint objective

Lay the producer-side foundations for the sprint-synthesis flow without
disrupting the legacy `/yoke:tech-spec` stage 3 yet. After this sprint,
a Yoke user can author an acceptance-criteria document that lists use
cases (`UC-<n>`) with their DoD, criteria, FR mapping, and sensor list,
free of any task IDs. The new path helper `wm_acceptance_criteria_path`
is callable from any skill body. The `(Realizes: UC-N)` Story-line
convention is documented in `templates/sprint.md` so the Sprint-3
producer (`/yoke:generate-sprints`) has a contract to lift. The legacy
`/yoke:tech-spec` skill is intentionally untouched in this sprint —
the cutover is staged in Sprint 4 — so in-flight tasks keep working.

## Sprint DoD

- `test -f templates/acceptance-criteria.md` returns 0.
- `bash -c 'source lib/working-memory/paths.sh && wm_acceptance_criteria_path foo'` prints exactly `.yoke/acceptance-criteria/foo.md` and exits 0.
- `tests/smoke/acceptance-criteria-shape.test.sh` exits 0.
- `grep -c '(Realizes:' templates/sprint.md` returns an integer ≥ 1.
- `grep -EIn '<slug>-s[0-9]+-t[0-9]+' templates/acceptance-criteria.md` returns zero matches.
- `git diff --name-only main...HEAD -- skills/tech-spec/` returns zero entries (legacy `/yoke:tech-spec` is untouched in this sprint; cutover lives in Sprint 4).

## Tasks

### Task 2026-05-03-generate-sprints-skill-s01-t01

**Story:** As a Yoke user authoring acceptance-criteria, I want a template at `templates/acceptance-criteria.md` that documents the UC-IDed shape so I can author UCs without referring to task IDs. (Realizes: US-002, US-008)

**Technical implementation:** Create `templates/acceptance-criteria.md` mirroring the file shape used by `templates/spec.md` and `templates/prd.md`. Top of file: a one-line title `# Acceptance Criteria: <title>`, followed by a blockquote header (`> Generated by /yoke:acceptance-criteria from an approved Spec on <date>.` plus PRD/Spec citation lines + Status / Approved by / Approved at fields). Body sections in fixed order: `## Overall objective` (one paragraph mapping the AC to the PRD's goal), `## Use cases` (introductory paragraph), then one or more `### UC-<n>: <name>` blocks. Each UC block carries five inline labels in fixed order: `**Name:**`, `**Definition of done:**` (bullet list of binary checks), `**Acceptance criteria:**` (bullet list of binary checks), `**Functional requirements realized:**` (`FR-N` ID list), `**Sensors:**` (sensor ID list). Add a closing trailer line `> When ready, run /yoke:generate-sprints to advance to Phase 2.5.`. The template MUST contain at least one example `### UC-1` block fully filled with placeholder text so authors can copy it. The template MUST NOT contain any string matching `<slug>-s[0-9]+-t[0-9]+` (no task references). Cite `concepts/yoke-pattern-memory-model` in a comment block at the top.

**Validation:** Run `tests/smoke/acceptance-criteria-shape.test.sh` (added in Task t05) which asserts the template exists, has the required headings, contains ≥ 1 `### UC-` block, and contains no task-ID strings.

**Acceptance criterion:** `test -f templates/acceptance-criteria.md && grep -c '^### UC-' templates/acceptance-criteria.md` returns 0 status with stdout integer ≥ 1, AND `grep -EIn '<slug>-s[0-9]+-t[0-9]+' templates/acceptance-criteria.md` exits non-zero (no matches).

### Task 2026-05-03-generate-sprints-skill-s01-t02

**Story:** As a Yoke skill body, I need a path helper `wm_acceptance_criteria_path` that returns `.yoke/acceptance-criteria/<slug>.md` so I never hand-concatenate paths. (Realizes: US-002)

**Technical implementation:** Edit `lib/working-memory/paths.sh`. Add a new function `wm_acceptance_criteria_path` mirroring `wm_spec_path` exactly: takes one argument `slug`, calls `wm_validate_slug "$slug"` (the existing helper), aborts non-zero with the existing diagnostic on invalid slug, otherwise prints `${WM_ROOT}/acceptance-criteria/${slug}.md` to stdout. Add a peer predicate `wm_acceptance_criteria_in_use(slug)` that mirrors `wm_slug_in_use` for the new path (returns 0 if the file exists, 1 otherwise). Place both functions immediately below `wm_spec_path` / `wm_spec_in_use` so the file's grouping convention is preserved. Do NOT remove or rename the legacy `wm_acceptance_contract_path` — that retirement is owned by the rename PR (out-of-scope for this work).

**Validation:** Extend `tests/wm-paths.test.sh` (or the equivalent existing test file under `tests/`; create one if absent) with two cases: (a) calling `wm_acceptance_criteria_path` with a valid slug `"2026-01-01-foo"` prints exactly `.yoke/acceptance-criteria/2026-01-01-foo.md` and exits 0; (b) calling it with `"INVALID SLUG"` aborts non-zero and writes the existing `wm:`-prefixed slug-validation stderr line. A third case (c) asserts `wm_acceptance_criteria_in_use` returns 0 when the file exists, 1 otherwise.

**Acceptance criterion:** `bash -c 'source lib/working-memory/paths.sh && wm_acceptance_criteria_path 2026-01-01-foo'` prints exactly `.yoke/acceptance-criteria/2026-01-01-foo.md` and exits 0, AND `tests/wm-paths.test.sh` exits 0.
