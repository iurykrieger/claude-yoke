## Overall objective

Ship a TypeScript / Node.js service that exposes a single
`POST /reversals` endpoint, idempotent on `tx_id`, that calls the
existing Stripe-like gateway's `/refunds` API and emits structured audit
events to the `payments-events` Kafka topic. Single-currency,
no-partial-refund v0.

## Sprints

### Sprint 1 — endpoint + happy path
**Delivery objective:** working `POST /reversals` against a fully-settled transaction, with a refund posted to the gateway and an audit event emitted.

#### Task 1.1 — POST /reversals endpoint
**Acceptance criterion:** curl with a valid request body returns HTTP 201 with the refund record; the row in `transactions` has `reversal_state = 'completed'`.

#### Task 1.2 — Stripe-like gateway client
**Acceptance criterion:** the service issues exactly one `POST /v1/refunds` per reversal request; the response body is parsed into the `Refund` type.

#### Task 1.3 — Audit event emission
**Acceptance criterion:** for each completed reversal, exactly one `reversal.completed` event is published to `payments-events` containing `tx_id`, `requestor_id`, `timestamp`, and `refund_amount`.

### Sprint 2 — idempotency + race protection
**Delivery objective:** concurrent reversal requests on the same `tx_id` produce at most one refund.

#### Task 2.1 — Row-level lock on the transactions row during reversal
**Acceptance criterion:** stress test with 50 concurrent reversal requests on one `tx_id` produces exactly one `reversal.completed` event and exactly one gateway `POST /refunds` call; the other 49 return HTTP 409 with body `{"reason": "already_reversed"}`.

#### Task 2.2 — Gateway-side rate-limit handling
**Acceptance criterion:** when the gateway returns HTTP 429, the service retries with exponential backoff (max 5 attempts); if all retries fail, the service emits `reversal.failed` and returns HTTP 503.

### Sprint 3 — PII redaction + states beyond `settled`
**Delivery objective:** PII in audit events is redacted; reversal correctly fails for non-`settled` source transactions.

#### Task 3.1 — Audit event PII redaction
**Acceptance criterion:** emitted `reversal.*` events contain neither raw `email` nor raw `phone`; instead they carry `email_hash` and `phone_hash` (SHA-256). Verified by a structural-test fixture against `payments-events` payloads.

#### Task 3.2 — Reject non-settled source transactions
**Acceptance criterion:** reversal request against a transaction in `pending` or `failed` state returns HTTP 422 with body `{"reason": "tx_not_settled"}` and emits `reversal.failed`.

## Contracts and interfaces

- **`POST /reversals`** — request body `{ tx_id: string, requestor_id: string }`; response `Refund` from gateway plus `reversal_state`. Schema: `contracts/reversals.openapi.yaml`. Tests: contract tests against `tests/contract/reversals.test.ts` (Sprint 1) plus stress test for idempotency (Sprint 2).
- **Audit event `reversal.{requested|completed|failed}`** — JSON shape `{ tx_id, requestor_id, timestamp, refund_amount?, reason? }`. Schema: `contracts/payments-events/reversal.schema.json`. Validated by `npm run test:contract` against the schema.

## Dependencies

### External services and libraries
- Existing Stripe-like gateway — gateway team already owns the
  `/refunds` API; no new contract negotiation.
- Existing `payments-events` Kafka topic — already provisioned; new
  service is a new producer.
- Vitest 1.x for unit and contract tests.

### Internal prior work
- `payments-core/transactions` — owns the `transactions` table; the
  reversal service queries it via the existing read library.
- `payments-events/sdk` — already-published Kafka producer SDK.

### Cross-team coordination
- **Customer-support team** — needs the new endpoint integrated into their support tool by 2026-06-15 (1 month before audit deadline).

## Out of scope

- Partial refunds. Single full-amount reversals only in v0.
- Multi-currency. Source-transaction currency must match refund currency.
- Customer-facing UX (in-app reversal request). Support-tool API only in v0.
- Provisional / pre-authorized reversals (gateway holds money but doesn't refund).
- Reversal of fraud-flagged transactions (separate compliance flow; not Yoke's example).
